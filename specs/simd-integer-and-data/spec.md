# simd integer and data

extend [mode context and decoding](../mode-context-and-decoding/spec.md), [scalar data and widths](../scalar-data-and-widths/spec.md), [memory map and code validity](../memory-map-and-code-validity/spec.md) and their inherited execution contracts with raw XMM state, legacy packed integer execution and bit-preserving data movement. include checked wide memory, alignment outcomes, retained-entry behavior and public state import/export in the same scope.

the selected instructions execute in every imported mode under an enabled SSE2-capable execution view: CR0.EM and TS are clear, and CR4.OSFXSR is enabled. no guest control-register writes, feature toggles, disabled-state #NM/#UD handling or CPUID reporting is added. real and virtual8086 execution are not intrinsically excluded. this subset does not claim complete SSE/SSE2 coverage.

FP arithmetic/conversions, MXCSR access, x87/MMX, MMX/XMM conversions, VEX/EVEX, wider vectors, SSE3 and later operations, masked stores, non-temporal stores, fences and state images remain separate work. raw FP-format moves and shuffles below manipulate bits without examining NaNs, rounding, denormals or exception status.

## raw state and public API

add synchronous idle methods:

```ts
readXmmState(): bigint[];
setXmmState(xmm: bigint[]): void;
```

the bank contains exactly sixteen unsigned 128-bit bigints, XMM0 through XMM15. bit0 is the least significant bit of byte0; increasing byte/lane indices move toward more significant bits. memory byte0 at the lowest selected linear address supplies bits7:0. construction initializes every bank to zero. all bit patterns are valid, including arbitrary encodings of floating-point values.

retain the existing three-field `State`, `readState`, `setState` and `RunResult.state` as the GPR/flags/RIP projection. `setState` preserves every XMM bank. `setXmmState` preserves the GPR state, context and guest bytes that exist at its publication point, and does not invalidate code or change context version. an equal import has the same semantics. `setContext` preserves all raw XMM values, including XMM8-15 while they are inaccessible to non-long64 instruction encodings. a complete idle checkpoint combines GPR state, XMM state, context and memory; a run result alone is the existing GPR projection.

require an actual array of length16 and validate every entry as bigint in `0..2^128-1`. capture array length and each selected slot once, validate and copy the entire bank, then publish it atomically. return a fresh array from every read. getters may perform independent CPU operations: check lifecycle before capture and again before publication, and preserve their GPR/context/memory effects. if a getter successfully imports another XMM bank, a successful outer import publishes its complete captured bank last; a rejected outer import leaves the nested bank in place. never publish a partial bank after rejected input. reading/importing XMM state is forbidden while running or awaiting compilation, after failure, and after disposal, following existing state/context lifecycle rules. guest faults remain resumable idle outcomes.

append canonical XMM storage after the existing176-byte private RunState prefix. retain all existing offsets, reason values and the five-argument generated entry ABI. expose vector offset/extent and total transport size through the layout descriptor. scalar imports retain their176-byte payload and update only the existing GPR projection; they must not serialize or reset the appended bank. XMM import has its own complete256-byte payload: banks0-15 in order, each sixteen little-endian bytes with low64 before high64. successful `setState` and `setXmmState` both clear stale guest diagnostics, including the new alignment record, without changing architectural state outside their projection. a rejected import publishes no diagnostic reset; independently committed reentrant operations retain their own effects.

validate required XMM exports and vector layout before publishing a CPU. the bank starts after the176-byte prefix, spans exactly256 bytes and fits wholly within both the declared transport and private linear memory. reject a missing/incompatible layout or export using existing construction-error conventions, cleaning up any owned instance. retain unsigned wasm32 pointer/length decoding; test pointers above2GiB, an extent ending exactly at private memory end, and out-of-range extents before any bank publication.

## host capability

standard fixed128 WebAssembly SIMD is a minimum runtime requirement for this execution profile, including CPUs initially running scalar guests. `createCpu` validates a known-valid minimal SIMD module before allocating/publishing its owned Core instance. absent support rejects construction with `TypeError`; it must not become a late generated-code compile failure, guest unsupported exit or failed CPU instance. validate the feature rather than guessing from a user agent. no relaxed SIMD or second scalar-SIMD backend is required. document this minimum in the public usage requirements and test the rejected-construction path.

## selected instructions

only legacy XMM encodings are admitted. packed operands and destinations are128 bits regardless of CS.D,66 or REX.W unless a specific narrow transfer below says otherwise. all selected operations preserve the complete admitted GPR flags word, including DF. GPR results use their specified view write policy; no other GPR or inaccessible XMM bank changes.

### transfer and mask rules

`66 0F 6E/7E` selects MOVD between XMM and GPR/m32; effective REX.W selects its64-bit MOVQ variant. mandatory66 does not select a word transfer, including under CS.D=0. moving into XMM zeroes all bits above the transferred32/64 bits. moving out to a GPR performs a32/64-bit GPR write, with inherited non-long64 upper-bank preservation. a memory destination receives exactly4/8 bytes.

`F3 0F 7E` loads/copies low64 bits to XMM and zeroes high64. `66 0F D6` stores low64 to memory or copies it to an XMM register, zeroing that register's high64. same-register MOVQ still clears high64. neither form is a full128-bit exchange or a NOP.

MOVSS/MOVSD use F3/F2 with `0F 10/11`. a register source replaces only the destination's low32/64 bits, preserving its upper bits; a memory load replaces the low part and clears the rest of the destination XMM register. register aliases in either encoding direction retain those rules. memory stores access exactly the low4/8 source bytes. MOVAPS/UPS/APD/UPD copy all128 raw bits; no selected move changes numeric status.

PINSRW takes low16 bits of a GPR source or one m16, selects word `imm8 & 7`, and preserves other destination words. legacy PEXTRW (`66 0F C5`) has an XMM register source, not a memory source; it extracts `imm8 & 7` and writes a zero-extended word as a32-bit GPR result. PMOVMSKB, MOVMSKPS and MOVMSKPD similarly produce zero-extended16-,4- or2-bit masks as32-bit GPR results. long64 clears upper GPR bits; other modes preserve raw bits above32. REX.W does not turn these masks/word extraction into16-bit writes or preserve upper RAX in long64.

### integer details

capture both operands before replacing the destination, including identical source/destination registers. PMULUDQ uses dwords0 and2 to produce two64-bit unsigned products. PMULLW retains each16-bit low product; PMULHW and PMULHUW select signed and unsigned high halves respectively. PMADDWD sums adjacent signed16-bit products modulo32 bits: two products of `-32768 * -32768` produce `80000000`, without saturation or exception. averages compute `(unsigned(a)+unsigned(b)+1)>>1` without overflowing the source lane width. PACKUSWB interprets source words as signed before saturation to `0..255`.

XMM/m128 shift counts use the unsigned value of the complete low64 bits; high64 is ignored for computation. do not mask counts to lane width or truncate them to32 bits. logical counts at least the lane width produce zero; arithmetic counts at least the lane width produce the lane sign fill. count zero preserves lane bits. immediate counts use the full imm8 value before the same comparison. byte shifts use the complete imm8 byte count and zero the whole vector at16 or greater. standard Wasm shifts mask their count, so direct lowering requires the x86 overshift check first.

PSHUFD selects each result dword from source using its corresponding2-bit immediate selector. PSHUFLW/HW select the designated four source words and retain the untouched source half, rather than the old destination half. SHUFPS selects result lanes0/1 from old destination with imm8 bits1:0/3:2 and lanes2/3 from source with bits5:4/7:6. SHUFPD selects low64 from old destination using bit0 and high64 from source using bit1. ignore unused immediate bits only after fetching the complete instruction.

## prefixes and legality

choose a mandatory selector for selected SIMD opcodes: use the inherited last F2/F3 group1 selector when present; otherwise66 when present; otherwise no mandatory prefix. F2/F3 suppress66 for this selection regardless of their physical order. an unimplemented selected variant does not fall back to66. thus `66 F3 0F 6F` and `F3 66 0F 6F` select MOVDQU, while `66 F3 0F FC` remains unsupported rather than becoming PADDB. this selection is opcode-specific: ordinary REP strings and unsupported F2/F3 scalar/HLE forms retain their existing behavior.

all legacy prefixes still cancel an earlier REX in physical order. REX.R/B extend real XMM or GPR fields in long64; REX.X extends explicit addressing. group `/digit` fields are not registers. packed register width is not the inherited ordinary operand width. 67 changes addressing only. segment selection, completed-next-PC RIP-relative addressing, logical/linear source accounting, repeated size-prefix presence and exact fifteen-byte rules remain inherited.

known register-only operands, including PMOVMSKB, MOVMSKPS/PD, legacy PEXTRW sources and immediate-shift XMM destinations, reject a memory ModR/M class as invalid-encoding at ModR/M before unrelated address fields. unknown/unimplemented group selectors remain unsupported at their deciding selector. valid known forms consume every required SIB/displacement/immediate before operand access. a single LOCK on an otherwise admitted SIMD form consumes its required encoding, then returns invalid-encoding before data access. repeated LOCK or mixed LOCK/repeat retains the inherited deciding-prefix unsupported outcome. no selected SIMD form is a memory RMW.

## checked access and alignment

selected m128 forms check the whole16-byte span, even when computation uses only a low half or a low64-bit count. this is the embedding's full-span access choice, including instructions whose manuals permit implementations to fetch fewer bytes. register-only masks/extraction access no memory. MOVD/MOVQ, MOVSS/MOVSD and PINSRW use their actual4/8/2-byte spans. loads require R; stores require W and do not require destination R. identical stores still require W and retain executable-alias invalidation.

every selected m128 operand requires16-byte alignment of its translated linear start address except MOVDQU, MOVUPS and MOVUPD. this includes bitwise operations, comparisons, min/max, products, reductions, count operands, packs/unpacks and shuffles as well as ordinary arithmetic and aligned moves. narrow transfers have no added16-byte alignment requirement. host scratch/RunState pointer alignment is unrelated to this guest rule.

use the existing context/segment and full-span address-domain/canonical checks first, then instruction alignment, then mapping permissions. this is an explicit embedding priority, not a claim about every hardware exception combination. add reason `alignment-fault` after existing reason values, with an exclusive exported record:

```ts
interface AlignmentFault {
  instructionPc: bigint;
  segment: SegmentName;
  offset: bigint;
  address: bigint;
  width: number;
  access: 'read' | 'write';
  alignment: number;
}
```

the record appears as `RunResult.alignmentFault` only for `alignment-fault`. offset is the selected effective offset before segment-base addition; address is its translated linear address. width and alignment are16 for the selected faults. no `fault` or `segmentFault` accompanies it. this instruction-alignment diagnostic does not model #AC controls or deliver a guest #GP handler. other access failures retain existing data/segment fault tuples with the complete selected width. clear the new diagnostic wherever existing guest diagnostic clearing occurs; successful retries and unrelated later runs must not inherit it.

perform a complete preflight before any guest store byte is written. two separate eight-byte stores with a possible late fault are insufficient. capture all source bits before overlapping/aliased stores. preserve inherited ascending-linear write order when distinct linear slices alias the same backing. aggregate executable invalidation across all written slices; a later non-code slice cannot erase an earlier owner-invalidating effect. private scratch transport is not guest architectural state. wide helpers must not round addresses, overread/overwrite guards, or pass v128 through JavaScript wrappers; use internal Wasm-to-Wasm access or private scalar/byte transport under the same memory authority.

## retirement, faults and reuse

each successful selected instruction retires once and consumes no repetition allowance. preserve any preceding REP accounting. an instruction fault preserves its incoming GPRs, all sixteen XMM banks, flags, bytes and logical RIP, with no retirement. predecessor effects remain committed. source faults suppress the complete vector destination, including would-be upper-zeroing and partial-lane changes. failed stores publish no bytes or register changes. no lane-level progress or REP restart policy applies.

code-writing stores complete all selected bytes, next RIP and one retirement before invalidation dispatch. budget and stop retain priority at the committed next boundary. never execute a stale successor or middle entry, including after an identity store through a different backing alias. data values and imported XMM values are invocation inputs, not translation constants or executable dependencies. reuse must observe changed values at every admitted entry without recompilation solely for `setXmmState`.

keep canonical XMM values in CPU-owned state. GP-only artifacts have no XMM locals, loads or publication traffic. vector artifacts may use a statically selected set of banks; every bank they may publish must hold its correct incoming value at any entry/fault even when a writer is skipped. publish all completed predecessor effects on every controlled exit. mixed regions, helper calls, dispatches and budget-one resumes must preserve raw bits without an entry-zero assumption or an unexecuted-predecessor dependency.
