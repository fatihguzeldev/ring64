# long-mode paging and permissions

## objective and chosen vertical

Implement an opt-in, imported four-level IA32e paging profile, from guest page-table/root changes through checked fetch/data/system access, precise #PF/CR2 publication, guest handler repair and IRET retry. Include Long64 and compatibility execution, 4 KiB/2 MiB/1 GiB mappings, hierarchical permissions, A/D effects, executable aliases and bounded invalidation. A walker or a CR register bank alone does not complete this vertical.

Implementation through `c1380a4` has loaded execution contexts, segmented/canonical admission, private linear mappings, backing-aware code ownership, selected processor/external delivery, REP restart and hardware debug. It has no physical address domain, paging controls, page walks, CR2 or vector14. Current `ExecutionContext::fetch` and discovery read `Image` directly; descriptor/TSS/frame owners do so separately. They are all consumers of this change.

Paging now closes a substantial execution path across those owners: import a bootstrap mapping; the guest constructs another root, changes mappings, takes a page fault, repairs its own PTE through a mapped alias, invalidates/reloads, and returns to complete the interrupted work exactly once. This requires no OS-boot assumption. Remaining x87 special functions are the strongest independent numeric alternative; selected fast system transfers require their MSR/enable authority. Standalone CPUID/control storage would not close the missing access behavior.

The existing [memory](../memory-map-and-code-validity/spec.md), [execution context](../mode-context-and-decoding/spec.md), [access faults](../architectural-access-and-legality-faults/spec.md), [event delivery](../event-delivery-and-returns/spec.md), [software events/IRET](../software-events-and-iret/spec.md), [external events](../external-interrupts-and-halt/spec.md), [REP](../string-and-repeated-execution/spec.md) and [debug](../hardware-breakpoints-and-debug/spec.md) contracts remain the foundation. Paging is applied after their logical/linear address formation and before physical backing access.

## address spaces and public boundary

Keep the existing private-linear model as the default. Omitted `memoryModel` means `linear`; an explicitly supplied value must be a supported primitive string. Old `code`/`ram`, explicit mappings, host memory methods, imported modes and private diagnostics retain their current meaning. Do not silently reinterpret an old mapping as a physical mapping or give legacy imported Long64 a fictional architectural PG=0 register image.

Add a distinct constructor form, using the existing backing/mapping records and capacities:

```ts
interface PagingState {
  cr0: bigint;
  cr2: bigint;
  cr3: bigint;
  cr4: bigint;
  efer: bigint;
}
// Additive Options variant:
// { memoryModel: 'ia32e-paged', memory: { backings, mappings },
//   memoryLimits, entry, paging: PagingState, context?, limits, compiler }
```

`ia32e-paged` requires explicit `memory`, `entry`, `memoryLimits` and a complete paging bank; `code`/`ram` shortcuts reject. Mapping bases are guest physical addresses in this variant. `entry` and scalar RIP remain logical CS offsets. Default context is Long64; supplied contexts and later replacements must be Long64 or compatibility. Invalid construction/import publishes no partial CPU state. The memory model is immutable for a CPU lifetime. Reject `paging` on a linear CPU, including an explicitly supplied undefined/null value; model-specific getters/setters also reject the wrong model.

Fix MAXPHYADDR=52 and canonical48 linear addresses. Physical mapping spans are checked in unsigned `[0, 2^52)`, without canonical filtering; a span ending exactly at `2^52` is valid. Backing byte lengths and counts remain explicitly bounded wasm32 capacities; a high physical base does not allocate intervening RAM. Preserve nonoverlap, split windows, arbitrary backing slices, aliases and read/write/execute private permissions. Physical page-table reads require private R, A/D updates private W, and final accesses their actual private permission. These permissions are independent of page permissions.

Add idle `readPagingState()`/`setPagingState(bank)` as a complete independent projection. Require primitive unsigned64 bigints and the normalized profile below; CR2 is raw unsigned64 and may be noncanonical. Capture values once, validate the entire candidate against the live lifecycle/run generation after getters, then publish atomically. Readbacks are detached. Do not add five registers to every ordinary scalar/run snapshot. Paging imports do not read tables or fabricate faults merely because a root is currently unbacked. `setState` preserves the bank; a valid `setContext`, including an equal context, preserves it while retaining the predecessor's event/shadow/NMI-block cancellation. An incompatible context rejects before that cancellation. Bank repair preserves already selected event/debug sources and deferred SS history; changes affecting translations invalidate/revalidate existing owners, while a CR2-only edit does not change translation authority.

Add `readPhysicalMemory(address, length)` and `writePhysicalMemory(address, bytes)` for paged CPUs, with the same idle capture/capacity/private-permission behavior as existing administration. They bypass guest walks, A/D, CR2 and debug matching. `readMemory`/`writeMemory` remain linear-model methods and reject on a paged CPU; they do not acquire a new, ambiguous physical or side-effecting guest-walk meaning. `setMappings` operates in the constructor-selected mapping plane. Physical host repairs participate in backing/source invalidation. No linear peek/debugger translation API or address-space switching API is required here.

## coherent control profile and guest consumers

The profile starts already in IA32e. Fix CR0.PE/PG/MP/ET/NE=1 and EM/TS/AM/NW/CD=0: normalized CR0 is `0x80000033` plus variable WP at bit16. Fix CR4 to `0x628` (DE/PAE/OSFXSR/OSXMMEXCPT). EFER has LME/LMA=1, variable NXE, and SCE/FFXSR=0; normalized readback is `0x500` or `0xd00`. CR3 contains a 52-bit physical root and PWT/PCD, with unused low bits normalized to0. These are selected execution controls, not a complete CPUID identity or guest reset state. All existing numeric/debug assumptions remain true.

Host imports require that normalized image: fixed bits must agree, unused/reserved bits must be0, CR3 may contain only bits51:12 and4:3, and all five fields must be present. Guest normalization is distinct from importing a complete canonical checkpoint. A missing backing at a valid root is allowed until actual access. A future identity spec must describe the selected capabilities consistently; CPUID remains outside this increment.

Implement MOV from/to CR0/CR2/CR3/CR4 (`0F20`, `0F22`), RDMSR/WRMSR for IA32_EFER (`0xc0000080`) and INVLPG (`0F01 /7`) in the paged IA32e profile. Other execution-model/control combinations remain explicit private unsupported frontiers. On linear CPUs preserve the old probe/required-byte/unsupported frontier for these unadmitted forms, before instruction begin or artifact/quota admission; recognizing a new opcode must not clear RF or require newly invented tails there. Existing admitted `0F01` group forms keep their own ModR/M requirements. Do not introduce a writable register whose effects are ignored by an existing consumer.

- MOV CR ignores ModR/M.mod and consumes no SIB/displacement. Ignore66/REX.W; long64 uses64 bits and REX.B extends the GPR; compatibility uses32 bits with the inherited GPR upper-bank policy and zero-extended CR writes. Illegal CR1/5/6/7/9–15 and effective REX.R naming anything except CR8 select #UD. CR8 is a valid deferred APIC/priority facility, so use the private unsupported frontier rather than pretending it is an illegal CR. LOCK selects #UD; preserve required-byte and unsupported-prefix priorities. MOV CR's undefined arithmetic flags preserve their incoming concrete values.
- At runtime pin legality before CPL0 admission, then architectural value checks, then selected-profile support. GD applies to MOV DR, not MOV CR. CPL1–3 selects #GP(0); valid transfers otherwise use normal instruction-begin RF behavior. Successful control writers end/revalidate the unit before their successor, including cached middle and native entries.
- CR2 writes accept every unsigned64 bit pattern in Long64. They neither walk nor invalidate translations. CR3 writes do not probe the root. With PCIDE=0, bits2:0 and11:5 are ignored, not reserved #GP; normalize them to0, preserve PWT/PCD, and use only bits51:12 as the root. Bits60:52 and63 are reserved and select #GP(0); nonzero LAM bits61/62 request deferred behavior and are private unsupported after architectural checks. Every admitted CR3 write, including same-value writes, establishes an invalidation/serialization boundary.
- For CR0, nonzero upper32 selects #GP(0); reserved low32 bits are ignored and ET remains1. The architecturally defined low fields are mask `0xe005003f`. PG=1/PE=0 or NW=1/CD=0 is #GP(0); clearing PG in Long64 is #GP(0). Valid writes changing deferred MP/EM/TS/NE/AM/cache or mode behavior are private unsupported before publication. WP changes are real permission changes.
- For CR4, revision093 defines bits0–14,16–25,27,28,32; other set bits are reserved #GP(0). Clearing PAE while IA32e is active, changing LA57 while active, and invalid PCIDE transitions select their architectural #GP(0). Other valid changes outside fixed `0x628`, including numeric/debug enable changes, are private unsupported, not silently masked or reported as arbitrary #GP. Same-value writes may complete and serialize.
- RDMSR/WRMSR use ECX and the EDX:EAX low32 pair. RDMSR clears the high32 of RAX/RDX in both admitted submodes, including compatibility; this explicit instruction behavior overrides the ordinary legacy GPR merge policy. WRMSR reads the pair without changing those GPRs. Preserve arithmetic flags. For EFER, only SCE/LME/LMA/NXE are admitted fields; reserved bits select #GP(0), writes to read-only LMA are ignored, and changing LME while PG=1 selects #GP(0). SCE enable requests are private unsupported; NXE changes affect permissions, reserved NX interpretation and fetch error codes immediately after the writer boundary. Unimplemented MSR indices remain private unsupported after privilege admission; this is not a complete MSR-map #GP claim.
- INVLPG requires a memory-form address and CPL0; register form/LOCK select #UD. It computes a linear address without reading operand memory, walking tables, changing A/D or matching a data breakpoint. Noncanonical Long64 addresses are NOPs after legality/privilege checks. A canonical address may conservatively invalidate all paged compiled owners; it retires once and ends the unit. Same-value root reload and INVLPG remain meaningful even with the cache policy below.

Reset, entering/leaving IA32e, legacy/PAE paging, CR8/APIC, PCID/PGE retention, LA57, LAM/LASS, SMEP/SMAP, keys, CET, HLAT, virtualization, memory-type/PAT/MTRR simulation, devices and shared-vCPU synchronization remain separate coverage. PWT/PCD/PAT/G and software/ignored entry bits retain valid readback without introducing those facilities. No dense large-page allocation or page cache/TLB framework is required.

## walks, permissions and fragmented access

Decode four 9-bit indices at linear bits47:39,38:30,29:21,20:12 and a 12-bit offset. CR3 locates a 4 KiB PML4; each used entry is an aligned little-endian64 physical read. A nonleaf's bits51:12 select the next table. PS=1 in a PDPTE or PDE produces a 1 GiB or2 MiB leaf; a PTE is a 4 KiB leaf and its bit7 is PAT, not PS. Support all three sizes, with physical offset bits29:0,20:0 or11:0 respectively. Large leaves require reserved address bits29:13 or20:13 to be0, while PAT bit12 is allowed. PML4E.PS is reserved. With MAXPHYADDR52, entry bits62:52 are ignored when the deferred facilities are disabled; do not reject software/key fields merely because they lie above the physical address width. CR3 has a different reserved-bit format. NX at any present level is reserved if NXE=0; otherwise OR XD across levels. P=0 is checked before reserved/permission interpretation, so absent entries with garbage do not become RSVD faults.

Accumulate U/S and R/W by AND over every controlling entry. A CPL3 ordinary access needs aggregate U/S=1; a user write also needs R/W=1. Supervisor reads ignore R/W and may access user pages; supervisor writes require aggregate R/W only when WP=1. Fetch ignores R/W but obeys XD with NXE=1. CR4.SMEP/SMAP are0, so neither a user page nor AC introduces another supervisor restriction. Walk to a valid leaf before selecting a permission violation; a lower nonpresent/reserved entry is not replaced with an early upper-level permission fault.

Represent a checked linear span as ordered physical fragments. Split at guest page boundaries and private physical mapping boundaries; adjacent linear pages need not be physically adjacent or share a backing. Preserve full-width linear/segment/canonical/alignment checks before page admission according to each existing instruction's priority. Admit nominal fragments in ascending linear order: walk the current page with its A effects, then check that fragment's final private physical access before touching the next page. An earlier final physical refusal therefore wins over a later P0/permission fault and leaves that later walk untouched. Dirty metadata admission is the separate selected-write phase below, not a speculative part of a nominal permission probe. Report the first failing byte/page in that ordered phase. There is no architectural partial scalar/vector destination store when the owner's whole-span admission fails. Earlier successful instruction suboperations and REP elements retain their existing effects; do not impose a new global transaction over a multi-access instruction.

Use explicit access provenance: ordinary operands/fetches use current privilege, GDT/LDT/IDT/TSS metadata reads and descriptor accessed/busy writes are implicit supervisor accesses regardless of source CPL, and an event's stack-frame accesses use the prepared target CPL/stack context. Same-privilege frames retain that privilege. IRET reads its current frame with the current stack's privilege before installing the destination. Do not apply the metadata supervisor rule indiscriminately to implicit stack operands. Page-table reads/A/D writes themselves are physical accesses and are never recursively paged.

Admission/commit must keep the exact physical fragments and their translation identity. An RMW writeback uses the same admitted operand as its read-for-write, including failed CMPXCHG and identity writes. Far/event frames and selected image writes commit their admitted destinations, without re-walking after descriptor/A/D writes. Those writes can alias a PTE and change its apparent mapping between preflight and publication. Preserve the current all-slot admission before frame publication and its nonfaulting commit, including every required dirty-metadata operation described below; do not keep `expect` over a fresh walk or late D permission check that can select a new fault. Plans are transient bounded instruction/element work, discarded on private exits; no access log, durable unretired-memory continuation or competing mapping authority is justified.

## A/D effects and private failures

Select a deterministic eager-A profile. During an actual walk, read/validate each present entry, then set its A bit if clear before continuing to the next level. An absent/reserved entry is not modified; valid ancestors already visited retain their updates. A valid leaf may acquire A before a permission #PF; this is an explicit choice in hardware's variable fault-side-effect footprint. Do not promise that all RAM is unchanged when an instruction faults.

Dirty is tied to actual participating writes, not a write-permission probe. Capture each actual write's leaf identity and D-needed decision at admission. After nominal fragment admission and selection of actual payload effects, preflight all required D-update physical writes before any payload, descriptor publication or architectural result publication. Then execute all planned D updates as a nonfaulting physical phase before any of those publications; only then publish the owner's payload/results. No fresh walk, D decision or private permission probe may be introduced during commit. Zero-mask MASKMOV and sparse-image padding can require nominal write permission and A admission without dirtying an unwritten page. Suppressed x87 stores do not dirty a leaf; failed CMPXCHG identity writes and zero-count memory-shift writebacks do. RMW permission faults use write intent even before readback. Read-only operands, instruction fetch, CLFLUSH, page-table A/D updates and metadata reads do not themselves generate D for a guest data page.

A/D bit setting preserves other current entry bits; do not overwrite an entry from a stale saved word. Apply updates through physical backing publication so aliases/source watchers see them. A bit already set when its update is admitted causes no redundant write or private W requirement. A later payload may overwrite/clear a captured leaf's D bit like any software PTE write; do not retroactively repair it or add a fallible update inside the same commit. The next independent access admission observes the new entry. OR planned updates into the current word so unrelated intervening bits are preserved. A denied A/D admission is a private backend refusal: eager A effects and D effects of earlier completed suboperations remain, but a failure while admitting this owner's planned D phase publishes none of its D updates or payload/results. CR2/event state is not fabricated. A later fragment or later committed suboperation may leave earlier A/D effects; pin exact effects in independent tests. Host inspection and compile-only peeks never perform A/D writes.

Keep private backing failures distinct from #PF. A present guest mapping selecting missing/private-denied physical RAM is not a nonpresent guest PTE. Missing table RAM, denied A/D writes, physical capacity/domain refusal and final R/W/X denial retain a private frontier. Add `physical-memory-fault` with a typed `physicalMemoryFault` record on paged runs: instruction PC, current affected linear address, original linear access kind, attempted physical span start/width, failing physical address, actual physical access kind, cause (`unmapped`, `permission`, `address-range`) and phase (`walk-read`, `accessed-write`, `dirty-write`, `final-access`). Retain segment and table/reference/phase provenance when supplied by the operand/system owner. A read can therefore explain a physical write refusal during A publication. Do not overload the old linear `fault.address` or attach physical addresses to CR2. Existing direct-linear diagnostics remain unchanged. Paged CPUs also retain the existing pre-walk linear segment/canonical/u64-domain diagnostics; a widened linear overflow with no physical attempt must not invent a physical address/phase.

## fetch admission, discovery and code ownership

Keep discovery, source registration and asynchronous compilation observational. They can peek through a pure walk and record dependencies, but cannot set A/D, update CR2, select an exception/debug source or fail early for an unreached instruction. Future failures remain discovery frontiers. Pending/abandoned compilation and resource accounting do not themselves create guest accesses.

Actual reached-instruction admission is separate. Initial budget0/stop and retained-event/external arbitration remain prior gates. A valid execute breakpoint selects before required code fetch, so it wins over a code-page #PF and performs no page walk for that instruction. Otherwise perform the actual required-byte fetch/decode admission, with its walk/A effects, before instruction begin. Cold probe, cached middle entry and native intra-unit branches must agree. A later private translation/artifact quota refusal may retain A effects from this already reached required fetch; it must not invent effects for speculative future bytes. A code-fetch #PF precedes lower-priority #UD/overlength or instruction execution, and preserves established pre-begin RF/NMI phases.

A retained unit may execute an instruction only while its current fetch permissions, physical code identity and relevant translation dependencies remain valid. Do not walk a first byte then assume all saved instruction bytes are accessible. Conversely, if a fetch A update changes code or translation identity, abandon the stale encoding before beginning it or fetching its old continuation bytes. Re-probe the actual changed instruction; a formerly long encoding may now be a one-byte instruction and must not fault on an obsolete tail. These refetches retire no instruction and retain RF/shadows until a valid instruction begins.

Bound pre-begin fetch invalidation work separately from instruction/REP retirement and actual compilations. Use `maxTranslationsPerRun` as the finite per-run ceiling for abandoned reached-instruction fetch/decode admissions: count each side-effect/dependency-induced abandonment in a paged-only `resources.pagingRestarts`, and on the ceiling-th abandonment return private `resource-limit` before another such pass. This counter is a per-run nonnegative integer `number`, present as0 on paged runs without abandonment and omitted on linear runs. Do not report a fictitious compilation. Preserve completed A effects, current RIP and pre-begin RF/shadows; the next run gets a fresh allowance and re-probes current bytes. Initial budget/stop and execute-debug priority remain; faults actually detected within an admitted pass retain their normal priority. This work ceiling is distinct from the later compilation quota, so the next not-yet-admitted pass is not promised ahead of a private yield. Ordinary completed instructions/elements remain bounded by their existing budgets.

Use the existing artifact owner/cache for physical code slices, root/control identity, page-table entries that determine instruction translation/permissions, and physical backing incarnations. Page-table dependency bytes need private R, not code X. Software writes through any physical/backing alias, mapping/backing replacement, permission-only PTE edits and control changes must invalidate or revalidate all dependent entries, including cached middle and native successors. Dependency handling must account for alias offsets rather than compare only guest physical addresses.

Choose coherent walks without a retained TLB/paging-structure cache: completed page-table edits are visible to subsequent accesses even before INVLPG. Compiled instructions cannot act as a hidden stale instruction-TLB. INVLPG/root reload may conservatively retire all paged owners. Root changes at an unchanged linear RIP must not reuse another root's code. Controls affecting permission interpretation also change owner authority. Do not bake mutable roots, CPL or permission state into an owner without validation. Reject stale asynchronous installs using the existing lifecycle/generation owner, not a second translation cache.

Choose visible A/D self-modification: every changed backing byte participates in source invalidation. A read/fetch can now invalidate code through an A update, and a write to a non-code data page can invalidate code through D. The current store-only code-write boundary is insufficient. Check the relevant completed or pre-begin boundary for these side effects; never execute stale bytes or re-run a completed store/control transfer. Conservative invalidation on metadata-only A/D changes is allowed, but it must terminate once bits are set and its cold cost must be measured. No-op bit updates must not create infinite recompilation.

## page faults, frozen sources and delivery

Add `page-fault`/`pageFault` for proven architectural vector14 detection. The diagnostic identifies instruction PC, failing linear address, original access kind and numeric error code. CR2 is updated at detection/selection in report mode and with automatic entry allowance0. It is the failing byte/page's linear address, not the first span byte, physical frame or PTE address. No private failure, noncanonical #GP/#SS, discovery peek or mere event retry updates it.

Pin low error bits: P=1 for permission/reserved violations and0 for a nonpresent controlling entry; W/R describes write intent; U/S describes the explicit access provenance above; RSVD=1 only with P=1; I/D=1 for fetch only when NXE=1 (SMEP=0). Other bits are0. Thus user RO write=`7`, supervisor WP1 RO write=`3`, user NX fetch=`21`, user absent fetch with NXE1=`20`, and reserved user read=`13`. With NXE0 an ordinary absent fetch has I/D=0; present NX is instead reserved. Do not OR selector EXT bits into a PF error code during external entry.

Extend pending vector14 with mandatory unsigned64 canonical `ExceptionEvent.pageFaultAddress`, in addition to its required error code. Forbid that field on other sources. Validate error bits0..4, RSVD⇒P and the absence of simultaneous write/fetch classification; preserve the existing FLAGS/return-boundary checks. Do not reconstruct a captured address/error from current CR2, page bytes, NXE or CPL: a supervisor metadata access can fault while current CPL=3, and controls/memory may already be repaired. Secondary delivery faults retain the predecessor's accepted diagnostic instruction/return boundary; a historical instruction PC need not equal return PC. A direct-linear CPU rejects vector14 imports because this source belongs to the selected paged profile.

`setState` round-trips a frozen PF atomically and does not update CR2. Omitting the pending event clears that source while preserving the paging bank. `setPagingState`, physical memory repairs and numeric/debug repair preserve frozen sources; a current CR2 edit is not silently overwritten when the accepted PF is retried. The normal pending-option omission path returns `pending-exception` unchanged. A complete checkpoint restores the compatible context, paging/numeric/debug projections, physical memory and scalar/event/interrupt state under their owner lifetimes. Add transport fields through the authoritative descriptor after the existing layout; preserve all existing offsets and old accepted prefixes. Do not hand-copy offsets, infer class in TypeScript or store the bank in every scalar snapshot.

Deliver #PF through IA32e IDT gates targeting a valid 64-bit code segment and qword automatic-entry frames, including when the interrupted code is compatibility mode, using the shared event-attempt budget. Legacy IVT and 16/32-bit gate-entry formats remain predecessor behavior on linear CPUs; they are not alternative paged-entry formats. Keep the existing admitted IRET width/return rules within IA32e. Entry/handler translation uses the current repaired paging bank, not a frozen old root. A successful entry retires no guest instruction; a handler can read CR2, fix a PTE, INVLPG/reload CR3, discard the error slot and IRET. Do not replay a completed control transfer/store/frame if handler fetch or compilation later refuses.

Use Intel's asymmetric secondary-fault classes. Benign→PF and contributory→PF select the secondary PF; PF→contributory or PF→PF selects #DF(0); #DF→contributory/PF selects shutdown. Existing contributory→contributory behavior remains. Every detected secondary PF updates CR2 even if the resulting selected source is DF or shutdown. Drop obsolete PF/debug metadata on replacement; preserve the original accepted boundary and existing explicit abort/shutdown profile. A private failure during any entry retains the selected source for repair and consumes only the already attempted automatic allowance; it is not another PF or DF. IRQ/NMI source kind, accepted NMI blocking and HLT wakeup remain independent of vector14.

## existing instruction and debug consumers

Route all actual guest accesses through the selected paging authority: fetch; scalar/LOCK/RMW and adjusted bit-string operands; near/far stack and pointer operands; IRET and POP SS; strings per element; SIMD/MMX/x87; MXCSR; sparse legacy/FX images; MASKMOV and non-temporal writes; explicit descriptor operands; GDT/LDT/IDT/TSS metadata and accessed/busy updates; software/automatic entry frames and returns. Inventory each current helper/semantic consumer during implementation. Host physical administration and page-table physical accesses do not recurse through this route.

Preserve nominal geometry versus selected payload: sparse images/MASKMOV preflight the existing full nominal span and permissions, yet write/dirty/match only actual fields/bytes. PREFETCH/LEA remain nonaccessing; CLFLUSH retains its byte-read admission and A effects without data matching/D; INVLPG has address-only semantics. Waiting #MF and numeric/alignment priorities remain those of their instruction owners.

Debug compares linear addresses, never physical aliases. Page walks/A/D, implicit system metadata and entry-frame writes stay excluded by the approved debug profile, while ordinary control-stack and explicit descriptor operands still match on successful completion. Execute #DB precedes code PF; a primary PF beats tentative data/TF completion and cancels unselected SS-deferred data just like the other recognized architectural faults. A private physical refusal preserves durable SS history and discards only uncommitted current candidates. Preserve completed REP work, counts/indices/comparison flags and the old report-versus-delivery partial-TF policy. IRET code-page PF is pre-begin and preserves NMI block; frame-page PF is post-begin and retains IRET's early unblock. Control writers, paging fault boundaries and native fast paths must not swallow selected debug/external causes behind post-work quotas.

## implementation and verification boundaries

Follow [architecture](../../agents/architecture.md): x86 owns page formats, access privilege/permissions, controls and fault semantics; physical backing owns mapping/private permissions/incarnation; instruction/access owners own fragmented admission and publication; the existing artifact owner owns executable/translation validity; embedding adapts transport; TypeScript coordinates idle capture, bounded runs and compilation. Cross owners through explicit access/prepared-effect capabilities. Do not prescribe a new source tree, copy paging rules into host glue, or introduce a universal observer, competing cache or unbounded plan list. Keep default linear access specialized without a runtime PG poll in each inherited helper.

Implementation checkpoints are physical-domain/API capture; coherent controls and walk/permission owner; A/D and prepared fragments across every consumer; actual versus observational fetch/code validity; producer-typed PF/CR2/escalation; guest handler repair and alias/root/debug/REP integration. Each behavior begins with a failing literal packet. No new dependency, CI redesign or unrelated ISA expansion is required. Preserve existing style: owner types and enums, captured records, lowercase imperative commits when separately authorized, and the repository's Rust/TypeScript formatter/linter conventions.

Spec checks: `npx prettier --check specs/index.md specs/long-mode-paging-and-permissions/spec.md`, local-link validation and `git diff --check`. Implementation checks: `cargo test --locked`, `npm run typecheck`, `npm run lint`, `npm run build`, `npm test`, `npm run test:browser`; `npm run check` is the complete format/lint/native+Wasm Clippy/Rust/build/Node/Chrome gate. Spec validation is not implementation evidence.

Use exact source `c1380a4` as performance baseline: all170 inherited report and169 matched-delivery workloads, including18 debug kernels, on Node and Chrome. Paging absent has no intended guest semantic change: prove exact generated bytes/import signatures/helper call counts for both ordinary and debug-observed artifacts, preserved existing state offsets, five-argument invocation, output/work/accounting and cache/entry/dispatch counts. Record core/host/code/cache/transport sizes and creation/translation/compile/instantiation/first/early/later timings. Include short resumes and known descriptor/exception controls; compare balanced/reversed old/current and same-build A/A, retain zero/sub-tick samples, and investigate replicated absolute costs without repeatedly expanding a sample union.

Characterize paged identity/nonidentity loops separately; there is no old paged baseline. Measure cold A/D versus warmed tables, hierarchy/page size, cross-page fragments, system/entry accesses, root reload/INVLPG, PTE/code aliases, PF report/delivery/handler repair, private physical refusal and debug/native loops. Guard complete results; separate run timing from host repair/rearming, and define instruction/element/walk/entry/run denominators. Mutation proof must kill wrong physical canonicality, early permission stop, wrong PF bits, stale CR2 reconstruction, ignored upper permissions, PS/PAT confusion, missing system paging, source-CPL frame access, D-on-probe, speculative A publication, RMW/frame retranslation, stale PTE/root owners, read-induced code invalidation loss and old native/per-element replay. Count actual semantic assertion failures, not crashes/timeouts. No p99, hardware-cycle or application-throughput claim follows from these synthetic cohorts.
