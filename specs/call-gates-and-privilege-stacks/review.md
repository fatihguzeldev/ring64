# call-gate selection and falsification

Prepared against clean implementation `43dad55`, after the five-spec cohort and its [performance recovery](../five-spec-integration/performance-recovery.md). This record concerns specification/source/manual review. No new implementation, runtime conformance, measured gate performance or executed mutation kills is claimed.

## why this is next

Three independent agents compared the current code with the earlier thirteen-area research, then challenged the leading candidates. Historical research supplies ownership/dependency questions, not a fixed spec count or evidence that old gaps remain.

| candidate                                 | current evidence and decision                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| call gates and privilege stacks           | [Far code selection](../../src/x86/protection/far.rs) recognizes system gate kinds but returns Unsupported. Ordinary far transfers/outer RETF, GDT/LDT, cached TR/TSS stack consumers, paged prepared frames and context/debug owners already exist. This completes a substantial selected execution path without a new host platform or global feature model. Selected.                                                                     |
| processor identity / deterministic time   | CPUID/TSC operations/providers are absent; this remains valuable system work. A positive CPUID family promise cannot be inferred from partial opcode coverage: x87 transcendentals are definitely absent, and the SIMD contract explicitly avoids a complete CPUID claim. TSD, MSR/control/lifecycle and truthful feature/model policy need their own contract. An initially preferred identity recommendation changed after this challenge. |
| remaining x87 special functions           | Coherent numeric gap on existing raw80 state, but transcendental approximation/rounding/status and an independent accuracy oracle need explicit policy. Hardware/libm/MPFR equality cannot silently become the selected x87 model.                                                                                                                                                                                                           |
| hardware task switching                   | Real missing gate/NT-return paths, but adds outgoing/incoming task images, CR3/context publication and partial-failure behavior. It must not be hidden inside call gates.                                                                                                                                                                                                                                                                    |
| XSAVE/AVX, retained TLB, parallel atomics | Require their own feature/component, invalidation or shared-memory authority. Existing FX images, INVLPG and private LOCK execution do not establish those remaining facilities.                                                                                                                                                                                                                                                             |

The existing thirteen areas have selected implementations, not thirteen completed verticals. Scalar/context/decode, memory, control/stack, repetition, protection, paging, events, numeric, SIMD, private atomic and system work already have owners. This choice advances control/stack and descriptor protection, and consumes existing paging/event/debug contracts. CPU identity/clocks, task execution, transcendental accuracy, extended state/AVX, retained translation facilities, shared-vCPU ordering and selected other controls such as CR8 remain separate remaining scope; this is not a fixed count of future specs.

## resolved falsification findings

| attempted simplification / counterexample                                     | contract resolution                                                                                                                                                                                                                                                                                                                                                               |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| source operand width or destination CS.D determines frame                     | Gate type determines W2/4/8 independently; source width still determines the required pointer and next-PC. Matching RETF selects its own width.                                                                                                                                                                                                                                   |
| ordinary code-descriptor admission can handle a gate target unchanged         | Gate permission, embedded-selector RPL and inner nonconforming rules differ. The gate is indirection, never the loaded CS cache.                                                                                                                                                                                                                                                  |
| same-CPL64 always pushes four slots because narrative says stack switch       | Detailed CALL SAME-PRIVILEGE pushes only CS/RIP; four slots belong to CPL change. Compatibility→64 adopts full raw RSP/long64 stack geometry with SS unchanged.                                                                                                                                                                                                                   |
| reuse interrupt entry's RSP alignment, IST, FLAGS and initial-canonical check | CALL has none of those effects. Validate actual pushed spans; a first-hole initial RSP can have valid lower pushes. TSS field-address validity is separate.                                                                                                                                                                                                                       |
| treat the IA32e count byte as IST/reserved #GP                                | Count is ignored; only the documented upper type-consistency field is selected for that tail check. Target must L1/D0.                                                                                                                                                                                                                                                            |
| interpret JMP's `DEST(Offset)` shorthand as the caller's far offset           | Vol3A gate indirection supplies the target. Caller offset bytes are required but their value is ignored.                                                                                                                                                                                                                                                                          |
| require16 bytes for every IA32e far selector before low classification        | Ordinary code descriptors need8. Selected gate extent is checked after low classification; gate low privilege/P0 precedes the selected tail read. This exact access-order profile is pinned in the spec.                                                                                                                                                                          |
| wrap a tail selector in u16 or copy IDT vector diagnostics                    | Retain original widened GDT/LDT lookup and selector provenance. Expanded LDT tail aboveffff is an acceptance case.                                                                                                                                                                                                                                                                |
| use RETF's new-SS validator for CALL                                          | CALL needs #TS for bad new SS and #SS for absent new SS; RETF retains its #GP rules. TSS reads SS first, then pointer, with full cached-field extent admission.                                                                                                                                                                                                                   |
| old/new stack CPL is the same for all implicit memory                         | Old parameters use old CPL, frame writes use destination CPL, metadata uses supervisor provenance. Existing GuestMemory is initially bound to old CPL.                                                                                                                                                                                                                            |
| copy count31 in one124-byte read or the ten-slot event frame                  | Existing paged scalar/vector reads cap at16; parameter reads are per slot, and maximum legacy frame capacity is35.                                                                                                                                                                                                                                                                |
| snapshot parameters and claim native ordered-alias parity                     | Keep the inherited captured-publication profile explicitly; SDM's ordered description may differ for overlapping source/frame aliases. Ascending captures, reverse pushes, no overlay/native microcode claim. Earlier page-table effects still influence later captures.                                                                                                          |
| all RAM/frame bytes must be unchanged on a failed call                        | No frame/descriptor payload publication is allowed, but earlier permitted page-table A/D writes may alias those bytes. Compare the exact retained effects.                                                                                                                                                                                                                        |
| set accessed on every selected descriptor                                     | Gate typeC must remainC. Only target code/new legacy SS descriptor A is published; no gate A, TSS busy or pointer writes.                                                                                                                                                                                                                                                         |
| observe the existing two old-stack writes after semantics                     | Capture actual operand footprints from preparation. No gate/TSS reread after aliases, fictitious two-slot mask or system-metadata watchpoint.                                                                                                                                                                                                                                     |
| gate fields can be cached at compile time                                     | Fresh runtime data, ordinary↔gate reclassification and A→B→A edits at one retained source site are required. No new gate cache or persistent continuation.                                                                                                                                                                                                                        |
| every code-alias A update should restart/redecode the gate                    | Required-fetch A checks can abandon before begin. After begin, far semantics complete the captured transfer if other admissions pass, then retire/redispatch; metadata A changing captured selector13 to33 must not reselect a new gate. Written-contract review removed an incorrect generic source-abort requirement and an impossible even-opcode9A/present-PTE alias example. |
| a new gate can be compared to its old Unsupported time                        | New behavior is characterization only. Unchanged controls retain paired snapshots, reverse/A-A and timer-limit discipline, including both recovered x87 targets and five IA32e kernels.                                                                                                                                                                                           |

The private capture/publication choice extends existing far/event and [paging prepared-destination](../long-mode-paging-and-permissions/spec.md) contracts. Preserving exact native progressive alias semantics would require reopening those contracts, including payload writes that redirect later page walks. A local byte-forwarding overlay would not solve that issue. This limitation is exposed in scope and literal aliases, rather than hidden behind a new Unsupported result for legal overlapping operands.

## review and verification boundary

Three independent lanes read and challenged the written contract for ISA/priority, memory/alias/debug and scope/implementation readiness. Two concrete blockers were corrected: post-begin source invalidation and selector-coded canonical descriptor faults. The latter explicitly refines the forward CALL/JMP consumer, including the unclassified initial lookup, while report mode keeps its complete system-memory diagnostic; unrelated producers and the generic mapper retain their behavior. Transient provenance cannot leak to a later private refusal. No implementation or executable-gate proof is inferred from that review.

Static literal verification passed30 named assertions covering raw descriptor bytes, instruction lengths, frame/cleanup/raw-bank/alias arithmetic and touched-span canonicality, plus256 legacy formula combinations (W2/4 x32 counts xold/new SS.B16/32). Receipt: `/tmp/ring64-call-gates-spec-literals.json`; checker SHA256 `6691c3d145a65fd2c4a6cf60c9d96f614912a2288693814ef36b9d8affdafcfd`. This is specification arithmetic/field consistency, not the implementation's required independent runtime oracle. Local source links, formatting and final diff are checked separately.

During implementation, independently expressed native/public expectations and semantic mutants must fail on the corresponding mistakes; the [spec's completion criteria](spec.md#commands-performance-and-completion) require actual emitted/public Node/Chrome execution and final artifact/performance evidence.

Primary inputs are Intel SDM093 Vol2A CALL/JMP, Vol2B RET and Vol3A §§6.8.3–6.8.6/Table6-2, refreshed through the official Intel portal; exact links and inspected PDF hashes are [in the specification](spec.md#primary-references). No manual pseudocode is copied into an implementation. The same-CPL64 frame and JMP-offset ambiguities are resolved by cross-reading those primary sections, not by silently preferring a secondary emulator.
