# numeric execution controls

Status: implemented; see [verification](verification.md) and the [integrated audit](../five-spec-integration/verification.md). Source audit baseline: `4df41a0814beaceb0681dc013f5eac094cdc6660`. Second of five; incorporates the preceding [x87 cohort](../x87-remainder-exponent-and-bcd/spec.md).

## complete execution path and scope

A guest changes numeric-enable/task-switch controls, the next reached numeric form selects the correct #UD/#NM/#MF or executes, a guest handler repairs controls with CLTS/MOV CR, and IRET retries the original instruction once. Include pure generated vector operations, streaming forms, images, cold fault discovery, retained middle entries, pending asynchronous compilation and complete captured fault sources. Storing mutable CR bits alone is insufficient.

Operate on the current `ia32e-paged` profile in Long64 and compatibility execution. Later `physical` profiles inherit these rules. Keep private-linear CPUs' current unsupported CR/CLTS frontier and always-enabled numeric behavior. NE remains1 here; reset/NE0 external error routing, CPUID, task switching, XSAVE and additional arithmetic are outside scope. The previous #MF/#XM delivery implementation is reused rather than claimed as new coverage.

## authority, normalized controls and host lifecycle

Use the existing complete `PagingState` bank, with one authoritative CR0/CR4 image. Normalized CR0 is `0x80000031 | MP<<1 | EM<<2 | TS<<3 | WP<<16`; CR4 is `0x28 | OSFXSR<<9 | OSXMMEXCPT<<10`. Thus PE/PG/ET/NE and DE/PAE remain1. All 32 combinations of the five new booleans are legal, including OSFXSR0 with OSXMMEXCPT1. EFER, CR2, CR3, WP and other fixed/reserved/private-frontier rules retain their predecessor meanings. Existing CR0=80000033/CR4=628 remains the enabled default.

Constructor and idle `setPagingState` capture complete primitive unsigned64 candidates once, require normalization, validate relationships and recheck lifecycle/run generation after user getters before atomic publication. Readbacks are detached. Invalid or stale outer imports publish nothing and cannot undo a successful nested operation. Scalar/context/numeric/debug imports preserve the control bank. Numeric-control repair preserves numeric payloads, MXCSR, CR2, frozen selected events, NMI blocking and durable history under their existing owner rules; `setContext` retains its own explicit event/shadow cancellation contract.

`MP/EM/TS/OSFXSR/OSXMMEXCPT` are execution eligibility, not a second feature-state bank and not numeric data. Numeric-only changes do not change page permissions or require a new page-table walk. Retain existing destructive CR3/INVLPG and actual paging-permission fences; do not classify all new CR0/CR4 bit changes as identical page-table mutations. CW, raw x87/XMM state and MXCSR remain live data consumed by the existing numeric owners. Idle host read/set APIs for x87, XMM and MXCSR are administration: they remain usable under disabled guest controls, post no guest #NM/#UD and preserve other banks/captured sources.

## CLTS and control-writer completion

Add CLTS `0f06`, with no operand or ModR/M: clear only CR0.TS, preserving all other control/scalar/numeric facts. CPL0 is required; CPL denial, including virtual8086 in later physical profiles, selects #GP(0). A recognized LOCK form selects #UD before privilege. Ignore66/67/segment/REX on this operand-free form; F2/F3 and conflicting prefix groups retain the control decoder's private frontier. Do not fetch an imaginary next byte. EM, pending x87 status and TS itself do not block CLTS.

MOV CR0/CR4 preserves existing instruction legality → privilege → reserved/invalid value → admitted/deferred facility processing. A failed writer publishes no controls, assumption generation, event repair or cache change. A successful MOV CR/CLTS retires once under its source context and reaches ordinary completion before successor eligibility. It preserves arithmetic FLAGS except inherited instruction-begin RF handling. CLTS does not clear x87 pending status, change page roots, reset numeric state or synthesize a task switch.

At completion publish controls and revoke affected generated assumptions/pending publications together. Preserve writer TF/RF/SS-deferred arbitration and newly eligible IRQ/NMI before post-work stop/budget/target gates. A next-entry mismatch must not consume that completed boundary. Equal host images or CLTS with TS already0 may cancel pending captures under normal publication rules, but cannot invent a guest page-table change or numeric result.

## reached order, RF and numeric #UD

Use the same reached boundary on cold and native paths: entry budget/stop and existing external arbitration; execute #DB before source-byte fetch; required fetch/CS-limit/decode/legality; selected numeric admission; waiting #MF if applicable; instruction-begin RF clearing; operands/alignment/paging/private admission; numeric effects and completion. Numeric admission must not be hidden inside the current observed-only debug begin path: it applies when TF/DR observation is inactive too. A skipped future numeric instruction causes no fault or state update.

A pre-execution #NM or EM/OSFXSR #UD performs no operand read/write, page walk for data, numeric status update, destination change, data-watchpoint match or instruction retirement. It precedes bad operand address/alignment and old pending #MF. Retain live RF at this pre-begin fault phase, and separately assert the architectural saved fault FLAGS image. Existing fault staging owns cancellation of SS-deferred history; control repair and private memory refusals do not impersonate an architectural fault. No uncommitted current operand-debug candidate survives.

OSXMMEXCPT0 is not unconditional SSE disable. Exact and masked operations execute. When a selected SIMD operation detects a newly unmasked numeric condition, update MXCSR per its existing pre/post computation rules, suppress the destination, and select #UD instead of #XM. The instruction has passed numeric admission and begin, so live RF is already cleared; this includes a SIMD owner's pre-computation numeric exception stage, which is still later than instruction admission; saved fault FLAGS still follows the fault-source owner. Old sticky flags becoming unmasked alone do not select a new exception. Do not report vector19 merely because the old helper returned a SIMD-exception candidate.

This post-numeric #UD is distinct from pre-execution EM/OSFXSR #UD. Preserve the existing `invalid-encoding` reason spelling as the #UD transport reason, but give the new producer typed numeric provenance; the spelling does not claim that these valid encodings are malformed. Do not route it through the generic decoder-fault arm that has a different RF phase.

## typed results and historical event sources

Add reason `device-not-available` after existing reason IDs (current tail26 is paging-restart), with one authoritative descriptor and no shifted old offsets/reasons. `RunResult.deviceNotAvailable` is present only for that reason; it includes `instructionPc`, literal vector7, `family` (`x87`, `wait`, `mmx`, `simd`, `bridge`, or `fx-image`) and captured `controls: { mp, em, ts, osfxsr, osxmmexcpt }` primitive booleans. Legacy x87 images use familyx87. This small diagnostic is derived from the bank, not another mutable authority.

For new numeric #UD add optional `RunResult.numericControlFault`, exclusive with other fault diagnostics: vector6 and `instructionPc`, `family`, captured controls and a discriminant:

- `phase: 'admission'`, `cause: 'em' | 'osfxsr'`. EM wins when both deny; no numeric raised/status fields exist.
- `phase: 'numeric'`, `cause: 'osxmmexcpt'`, plus the existing SIMD `stage`, `raised`, `unmasked`, `mxcsrBefore`, `mxcsrAfter` facts. The record's vector is6, and `simdException` is absent.

Newly produced records are complete; incomplete or incoherent records reject atomically. Validate captured facts: x87/FX #NM needs EM||TS; WAIT needs MP&&TS; MMX #NM needs !EM&&TS; SIMD/bridge #NM also needs OSFXSR1. Admission EM #UD permits only mmx/simd/bridge, and OSFXSR #UD only simd/bridge. Numeric #UD permits only simd/bridge with a numeric-producing form, requires EM0/TS0/OSFXSR1/OSXMMEXCPT0 and nonzero primitive six-bit raised/unmasked values. Before/after MXCSR are primitive unsigned16, `unmasked=raised & ~(mxcsrBefore>>7) & 0x3f`, control bits are unchanged and status publishes the existing before|raised rule; do not infer raised conditions merely from the difference in old/new sticky flags.

Extend pending vector7 (no error code) with optional `deviceNotAvailable`, and pending vector6 with optional `numericControlFault`. Reuse the same source records; vector and instruction boundary must agree: a full fault record has `record.instructionPc == event.instructionPc == event.returnPc`; a fresh producer also has live RIP equal to that PC. Intrinsic record validation uses captured source facts, without reading the current opcode or comparing captured controls/status with a repaired live bank. The enclosing pending event retains its inherited `returnPc == state.rip`, saved-FLAGS and VM invariants, so retaining this fault still requires the imported live RIP to match its return boundary; changing RIP requires replacing the event with ready. Old metadata-free vector6 inputs remain accepted. Deliberately also accept a metadata-free host-imported vector7 fault, analogous to other externally supplied processor sources; newly generated vector7 always carries the full record. This is an import policy, not compatibility with a formerly supported vector7. Reject wrong-vector metadata, both records together, invalid family/cause/phase/booleans and partial records. Capture once, then recheck lifecycle; do not read source code or compare historical controls with the repaired current bank. `setState` omission clears the pending source under the existing contract without clearing control or sticky numeric state.

Opt-in delivery uses the existing shared attempt allowance, frame widths, pending repair and IRET path. Both are fault-class sources at the source PC, with no error code. Report-only execution returns its typed reason without automatically inventing an IDT entry. Already selected pending sources survive omitted delivery options and compatible control/numeric/memory repair; successful entry is not replayed after handler fetch/compile refusal. Secondary GP/PF/DF replacement must clear obsolete numeric metadata instead of inheriting it through `ExceptionEvent::secondary` struct updates; old sticky numeric state remains independent. Clear transient numeric-control and #NM diagnostics on every existing probe/prepare/import/delivery diagnostic-reset path while retaining the separate pending source. A following decoder #UD cannot inherit stale numeric cause. A historical #NM may be delivered after CLTS; it must not be reclassified using TS0.

## generated assumptions, fault probing and limits

The baseline [assumption owner](../../src/dbt/ownership.rs) validates only full `ExecutionContext`, observed profile and source activation; numeric controls are outside that snapshot. Choose retention with numeric-eligibility-aware admission: extend the one owner capture/publish/admit proof with the numeric facts actually specialized by that unit, or a consumer-owned live eligibility fact. Splitting numeric eligibility from paging invalidation is required; merely relaxing validation and keeping the current full-CR0/CR4 destructive comparison does not fulfill this chosen retention contract. A cached positive context proof cannot authorize execution under old enable bits; merely clearing its boolean without changing the captured/matched facts is insufficient. Revoke affected proofs on every actual control publication, including guest MOV/CLTS, host imports, A→B→A and saturated publication epochs; source death/release/eviction remains independent. Do not add a second cache or permit async publication to succeed after controls changed and changed back.

Admission refusal is not a guest #NM and must not increment cache-hit/native-entry/retirement, touch LRU as a hit or consume guest budget. It selects another eligible candidate or returns to the existing bounded host admission loop. A disabled form must fault only when reached, not at unit entry because a later untaken branch contains it. Enabled code may specialize behind guarded assumptions; a disabled variant or live consumer may select the reached fault. Control writers end stale paths before successor execution.

`core_probe` currently returns dispatch for every successfully decoded operation, and the host probes before testing compilation quota. Add the shared pure form/control admission there. At the actual current PC a fully decoded disabled form must produce the same typed #NM/#UD and RF/source phase even if cache capacity or remaining compilation quota cannot admit another artifact. The probe evaluates only enable admission, not live SIMD arithmetic, pending numeric results or OSXMMEXCPT numeric selection; it cannot publish speculative MXCSR status to evade quota. Do not require browser compilation to discover a known fault, and do not bypass fetch/#DB/legality checks. Speculative unit discovery stays observational and cannot publish status/faults for future instructions.

Default enabled admission should reuse the existing activation/publication boundary. No new host/Core call or unconditional per-instruction observer is justified solely by numeric controls. Guards may not be elided merely because a data operation lowers directly to Wasm rather than an existing helper. Preserve old scalar/vector residency and consumer-specific helper handovers.
