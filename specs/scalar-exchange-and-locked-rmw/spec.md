# scalar exchange and locked rmw

extend [scalar data and widths](../scalar-data-and-widths/spec.md), [integer memory](../integer-memory/spec.md), [integer arithmetic and bits](../integer-arithmetic-and-bits/spec.md), [memory map and code validity](../memory-map-and-code-validity/spec.md) and [mode context and decoding](../mode-context-and-decoding/spec.md) with scalar exchange, compare-exchange and the legal LOCK forms of admitted modifying integer instructions. execute the complete selected families in every currently imported mode.

this scope uses existing register views, arithmetic flags, checked scalar memory and source invalidation. keep the three-field State API, execution contexts, run options and generated entry ABI. each successful selected instruction retires once and consumes no repetition units. preserve preceding REP accounting. no paging, descriptors, numeric state or general rollback framework is required.

## forms and decoding

| family    | admitted forms                                              | widths and effects                                                                                                                                                                                                                    |
| --------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| XCHG      | `86 /r`, `87 /r`; `90+rd`                                   | register/register or register/memory exchange at 8/16/32/64 bits; opcode-register forms use AX/EAX/RAX and a non-byte register. preserve all flags.                                                                                   |
| NOP alias | opcode `90` when its effective opcode-register bank is zero | preserve all raw register banks and flags regardless of operand-size prefixes, including REX.W.                                                                                                                                       |
| XADD      | `0F C0 /r`, `0F C1 /r`                                      | register or memory destination, register source, 8/16/32/64 bits; source receives the old destination, destination receives their sum, six arithmetic flags follow ADD.                                                               |
| CMPXCHG   | `0F B0 /r`, `0F B1 /r`                                      | compare AL/AX/EAX/RAX with a register or memory destination at 8/16/32/64 bits. equality selects source-to-destination; inequality selects destination-to-accumulator. six arithmetic flags follow accumulator minus old destination. |
| CMPXCHG8B | `0F C7 /1`, memory, without effective REX.W                 | compare EDX:EAX with one eight-byte memory operand; equality stores ECX:EBX, inequality loads EDX:EAX. change only ZF.                                                                                                                |

retain inherited operand-size selection for scalar forms: CS.D and 66 outside long64; default32, 66 selects16 and effective REX.W selects64 in long64. byte forms retain AH/CH/DH/BH without REX and SPL/BPL/SIL/DIL or extended registers with effective REX. explicit addresses retain the complete ModR/M/SIB, displacement, RIP-relative, address-size and segment rules. calculate every effective address from incoming registers.

opcode `90` requires the actual extended register identity: `41 90` exchanges EAX and R8D, while `44 90` remains NOP. `41 66 90` is NOP because the later legacy prefix cancels REX. distinguish the NOP alias from ModR/M `87 C0`: the latter really writes EAX and clears upper RAX in long64. a same-register 16-bit or 64-bit exchange still uses its ordinary write semantics.

CMPXCHG8B always accesses eight bytes and uses the low32 views of architectural banks EDX/EAX/ECX/EBX. 66 does not select a four-byte or word-pair operation. REX.R does not extend `/1` or implicit pairs; REX.B/X affect only the explicit address. fetch the required ModR/M byte first. `/1` with register mode is invalid-encoding with or without effective REX.W. a memory `/1` form with effective REX.W selects valid but unimplemented CMPXCHG16B: return unsupported at ModR/M before its address fields or operand data. `48 66 0F C7 /1` can therefore select 8B while `66 48 0F C7 /1` selects unimplemented16B. other `0F C7` selectors return unsupported after ModR/M, before unrelated address fields are consumed.

the imported mode does not emulate an old processor's feature inventory: XADD, CMPXCHG and CMPXCHG8B are admitted in real and virtual8086 as well as protected, compatibility and long64 execution. CPUID and feature-enable controls remain separate work. F2/F3 forms, including PAUSE and HLE hints, remain unsupported under the inherited repeat-prefix policy. do not turn `F3 90` into NOP. multi-byte NOP, fences, CMPXCHG16B, RTM/HLE, shared backing and parallel vCPU execution are outside this scope.

## LOCK admission and diagnostics

memory XCHG has implicit locked semantics with or without an explicit LOCK. a single LOCK is also admitted on memory-destination XADD, CMPXCHG and CMPXCHG8B and on these existing modifying memory forms:

| existing family    | admitted locked memory destinations                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------- |
| arithmetic/logical | ADD, ADC, AND, OR, SBB, SUB and XOR; their currently admitted register-source and immediate forms |
| unary              | INC, DEC, NEG and NOT                                                                             |
| bit modification   | BTS, BTR and BTC, with register or immediate bit index                                            |

do not admit LOCK on register destinations, CMP, TEST, BT, shifts/rotates, multiplication/division, MOV, LEA, or other non-lockable instructions. preserve each admitted operation's existing flags and addressing semantics; LOCK does not turn a register-destination instruction with a memory source into a memory-destination RMW.

extend the single-LOCK deciding policy for the selected opcode families. once the opcode and any group selector identify an otherwise implemented operation, consume its required ModR/M/SIB/displacement/immediate bytes, then classify an illegal LOCK as invalid-encoding before operand-data access. this includes read-only CMP/TEST/BT and implemented non-lockable members of a newly inspected group. unknown selectors and valid unimplemented operations remain unsupported at their existing deciding point. unrelated opcode families keep their inherited prefix diagnostics. the selected diagnostic order is an embedding policy, not a complete hardware exception-priority model.

selected opcode groups are `00–3D` admitted ALU forms, `80/81/83`, `84/85`, `86/87`, `90–97`, `F6/F7`, `FE/FF`, `0F A3/AB/B3/BB`, `0F BA`, `0F B0/B1`, `0F C0/C1` and `0F C7 /1`. valid unimplemented selectors in these groups are not made invalid by this list. a truncated selected form still fetches its required suffix before LOCK classification. repeated LOCK and mixed LOCK/F2/F3 remain unsupported at the inherited deciding prefix. preserve exact fifteen-byte admission and overflow behavior.

## capture and publication

snapshot the selected incoming operand views before publishing any architectural write. for memory forms, also capture the explicit effective address and all implicit accumulator/pair inputs before a register that participates in the address can change. address evaluation never observes the result of this instruction's register writes.

every selected memory form is a write-intent RMW, including an identity exchange, XADD with zero, a failed CMPXCHG/CMPXCHG8B, and a bit modification that leaves its target bit unchanged. use the inherited full-span R+W preflight and diagnostic policy before exposing a load value. a failed compare still performs the ordinary memory writeback of the captured old value; it requires W and participates in conservative code invalidation. a read-only page or mapping cannot succeed merely because the comparison fails.

stage the result, register updates and flags until the complete store succeeds. failure preserves this instruction's incoming sixteen banks, flags including DF, bytes, logical RIP and retirement. predecessor instructions remain committed. retain exact selected-segment, linear/segment fault metadata and full access width. split mappings and unaligned spans follow the existing checked scalar policy; no alignment exception or partial store is added.

### register exchange and XADD

XCHG exchanges captured values even when both views share a bank, such as AL and AH. merge subregister writes without losing the other updated view. memory XCHG stores the captured register value, then publishes the captured old memory value to that register. `[RAX],RAX` must store and read at the incoming RAX address.

XADD computes the width-truncated sum and ADD flags from the two incoming values. source receives old destination, then destination receives the sum. when both name the same view, the sum wins. distinct byte views within one raw bank receive both results. a memory-destination XADD stores the sum before publishing its source register or flags; a source register used in the effective address cannot redirect the store.

### conditional register writes in CMPXCHG

compare the captured accumulator against the captured destination. on equality, write the captured source to the destination and leave the accumulator unwritten unless it aliases that destination. on inequality, write the captured destination to the accumulator and leave a register destination unwritten. memory destinations still receive the required old-value writeback on inequality.

apply view merging and long64 zero-extension only to actual register writes. in long64 CMPXCHG32, a successful compare preserves upper RAX unless the destination write itself names EAX; a failed compare preserves a distinct register destination's upper bits while the EAX write clears upper RAX. implement neither an unconditional identity write to a register destination nor an unconditional accumulator rewrite. byte aliases of AL/AH must use incoming snapshots and the selected branch's actual write. source has no separate writeback.

### CMPXCHG8B pairs

form the compare value from low EDX as bits63:32 and low EAX as bits31:0; form the replacement from low ECX and low EBX in the same order. compare the whole qword. success stores the replacement and sets ZF, preserving the complete raw RAX/RDX pair. failure writes the old qword back, clears ZF, and publishes low/high halves to EAX/EDX. these writes clear their respective upper32 bits in long64 and preserve the embedding's unrelated upper raw bits outside long64. all other flags, including DF, remain unchanged on either branch. capture pair inputs before an explicit address based on a pair register could be affected by its output.

## observer model and code validity

execution uses CPU-owned copied RAM backings. public mutation and state/context access require an idle CPU; generated execution calls internal checked-memory exports synchronously and exposes no guest-memory callback. aliases within that CPU name the same owned bytes. a caller's shared input buffer is copied at capture and does not become live shared guest memory.

within this observer model, an admitted locked instruction exposes one successful complete RMW result at an instruction boundary. unlocked instructions retain their ordinary semantics; no competing guest observer can interleave with the access. do not add Wasm shared memory, mutexes, retry loops, host callbacks, alignment fallbacks or a second memory authority merely to implement the LOCK prefix. this contract does not specify inter-vCPU visibility, allowed concurrent outcomes or device/DMA ordering. concurrent execution requires a later synchronization contract covering every conflicting ordinary and atomic access.

memory stores, including failed-compare identity writebacks, retain executable-backing dependency invalidation through every linear alias. after a successful code-writing instruction, publish all register/flag/memory effects, next logical RIP and one retirement before dispatch. budget and stop at the committed boundary keep their existing priority. never continue into a stale successor or cached middle entry. these fixed instructions have no REP-style unfinished-instruction restart.

new scalar instructions have ordinary fallthrough discovery. data operands and comparison outcomes are invocation inputs, not translation dependencies or constants. changed RAM values, source registers, accumulator pairs and flags must be reread at retained entries. preserve logical/linear source accounting, context ownership, eviction, resource refusal and pending-publication rules.

## performance and increments

compare inherited scalar, memory/RMW, stack/control, mul/div, REP, retained-entry, short-resume and forced-churn workloads using matched core/host cohorts and checked outputs. compare generated artifact bytes and metadata where admitted decode frontiers are unchanged; report source/region growth separately where newly executable encodings change discovery. ordinary unlocked forms and register operations must retain specialized lowering; adding LOCK admission must not add per-access runtime locking, retry or shared-memory checks to them.
