# legacy paging implementation evidence

The isolated legacy implementation is based on `e00a41875c54798a554f7c30864e784e569df10d`. Runtime changes end at `eb82d60`; additional ownership/frame assertions and the complete gate were checked at `c8e11257a9f3ba765f6373683b4b5eface96149e`. This branch uses the baseline numeric defaults; integration with the preceding numeric-control implementation must preserve its variable numeric masks and proof rules. No README change belongs to this implementation.

## completed execution checks

`npm run check` passed after restoring every mutation: Prettier/Rust formatting, oxlint, native and wasm32 clippy with warnings denied, **811 native tests**, release Wasm build, **226 Node tests**, and **864 shared Chrome scenarios**. Environment: Node25.9.0, rustc1.97.1, TypeScript7.0.2, Playwright1.64.1, headless Chrome157.0.8103.79. The checked Core is1,132,644 bytes with SHA256 `ea98648c12d3fc3fea2f9586c4e4d60e9abdcf8c10978b5b1c81cf8b8914f97f`.

The new shared cases exercise actual generated Wasm in Node and Chrome:

- Atomic physical construction and detached conditional quartet imports; raw CR2/CR3 preservation and PAE execution without any PDPT backing.
- Non-PAE4KiB/PSE-36 and PAE4KiB/2MiB accesses, including a PAE physical address outside canonical48 and sparse large-page payload windows.
- Exact4-byte table reads, D publication and source dependencies beside unmapped adjacent bytes; W-only payload access; prepared payloads that clear their own PTE.
- Same-value MOV CR3 and changed/unchanged PSE, all-four capture before reserved validation, a later private slot hole, typed control-load provenance and failed-writer atomicity.
- Actual #PF→five-instruction handler→IRETD→one retried store in both formats, including private frame refusal/repair. The six-dword user frame, restored state, one delivery and six retirements are independently asserted.
- Protected16 and VM86 defaults, four-word protected16 fault frames, ten-dword VM86 frames and the inherited VM86 word-gate private frontier.
- A historical high-canonical IA32e #PF snapshot imported into a physical legacy CPU, repaired CR2, and legacy event entry preserving the captured source.
- Writable code aliases, different-code quartet A/B/A middle entries, pending/primed native proofs at epochMAX, cold quota before unretired control loading, and completed writers surviving successor fetch faults without replay.

The initial new control test failed because same-value MOV CR3 did not refresh the architectural quartet. It passed after adding the prepared load/publication boundary. Malformed tuple capture also failed before its capture implementation was added. These are separate from the deliberate mutations below.

The Core grows from1,116,930 to1,132,644 bytes. Generated body size is not a heap-retention or speed measurement. New warm semantic walks have two live entries,4-byte non-PAE or8-byte PAE; large leaves have one. A triggered quartet load reads4×8 bytes. Actual fetch-coherence peeks and A/D current-word rereads are additional work and must be reported separately.

Paired timing is intentionally deferred to the coordinated integration run while other agents are compiling. It must use equal checked work and balanced/reversed/A-A controls, include inherited linear/IA32e/numeric/debug/context workloads, and distinguish first/warm walks, A/D, capture, faults and short resumes. Fault-only work needs an attempt/access denominator rather than zero retirement. This record makes no no-regression, application/boot or hardware-cycle claim.
