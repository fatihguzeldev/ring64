# system flags and instruction boundaries

## purpose

Implement guest FLAGS stack transfers, interrupt-flag controls and TF single stepping. Preserve system flags through the existing instruction families and publish precise state at completed instructions, repeated elements and faults. A guest can enable TF with POPF, execute a branch or partially repeated string, inspect a vector-1 trap exit, and resume without replaying completed work.

The execution profiles remain real, virtual-8086, protected 16/32-bit, compatibility 16/32-bit and long64, with the imported CPL and loaded segment caches. CR0.AM and CR4.VME/PVI are fixed zero for this contract. AC is writable state but does not enable alignment checking while AM is zero. Existing instruction-specific alignment requirements still apply. This does not expose a CR0/CR4 register image or implement paging, reset or guest transitions between execution families.

## scope

| instructions or behavior | forms                                                                                                                |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| PUSHF, PUSHFD, PUSHFQ    | opcode `9C`; operand16/32 outside long64, operand16/64 in long64                                                     |
| POPF, POPFD, POPFQ       | opcode `9D`; the same width rules                                                                                    |
| CLI, STI                 | `FA`, `FB`, with mode/CPL/IOPL checks                                                                                |
| TF single step           | every existing executable instruction family, including successful far/context transfers and individual REP elements |
| MOV SS, POP SS           | selector loads and their stack/debug boundaries; LSS remains an atomic SS/GPR load without that suppression          |
| state preservation       | arithmetic, DF and system flags, interruptibility, host import/export and retained generated entries                 |

In long64, the default FLAGS stack width is 64 bits; `66` selects 16 bits unless an effective REX.W selects 64. Thus `66 48 9C` pushes 8 bytes, while `48 66 9C` pushes 2 because the later legacy prefix cancels that REX. POPF uses the same rule. Address overrides do not change the operand width or the SS-selected stack-address size. F2/F3 are accepted and ignored for FLAGS transfers, CLI/STI and MOV/POP SS; they consume no repeat allowance. A later legacy prefix still cancels an earlier REX. Inherited repeated/mixed group1 rejection remains an engine-unsupported prefix frontier. A sole LOCK prefix is architecturally invalid for these forms, after required selected operands/tails are fetched and subject to the fifteen-byte limit. Recognized unimplemented instructions remain engine coverage exits.

IDT/IVT entry, INT/INT3/INTO/INT1, IRET, IRQ/NMI injection, HLT, DR registers, hardware/data breakpoints, task switching, virtual interrupts and CPUID remain separate coverage. A single-step exit detects a trap; it performs no handler lookup, frame writes or handler-entry flag changes. Installing IDTR, setting IF, changing NT or toggling ID does not make those operations implemented.

## flags and state authority

ExecutionContext owns mode and CPL. Its virtual8086 mode supplies architectural VM=1; other modes supply VM=0. `State.flags` remains a mutable-flags projection with VM excluded. It is not a complete raw EFLAGS image. Existing virtual8086 callers may continue importing flags=`2`; POPF cannot change VM or the execution family.

Admit CF, PF, AF, ZF, SF, TF, IF, DF, OF, IOPL, NT, RF, AC, VIF, VIP and ID, with reserved bit 1 required and all other bits zero. The exact admitted mask, including bit 1, is `3d7fd7`. Reject VM in the scalar projection to preserve a single mode authority. Default flags remain `2`. VIF/VIP are retained imported state; fixed VME/PVI=0 means these instructions do not redirect IF writes to VIF. NT and ID have their stack-transfer effects without implying task return or CPUID coverage.

Every old instruction preserves system bits that it does not explicitly change. This includes flag-reconstructing arithmetic/logical and bit operations, shifts/rotates, partial-count forms, multiply/divide policies, LAHF/SAHF, x87 FCOMI/FUCOMI, SSE comparisons, descriptor queries and RMW helpers. DF retains its independent semantics. Undefined arithmetic outputs retain their existing selected policies. A helper result must not replace live flags with a stale canonical bank. Compose the public projection consistently on all exits, including faults and partial REP suspension.

Extend the existing State projection with optional input `interruptibility: { sti: boolean; ss: boolean }`; observations always return a detached object with both booleans. At most one can be true. A true STI shadow requires IF=1. Omitted input clears both shadows, preserving the existing scalar-import API as fresh execution input; an explicit object restores them together with registers/flags/RIP. Validate and copy the entire candidate before publication. Rejected malformed input publishes no state or ownership change. If an accessor itself starts a run or disposes the CPU, preserve that action and reject the outer import without further publication or resurrection.

These shadows belong to CPU execution state, not a translated unit, dispatch call, fault record or run allowance. Ordinary observation, zero-budget runs, stop-at-current, private faults, cache eviction and recompilation do not consume them. Successful host context replacement clears both; a rejected replacement preserves them. Scalar import and context replacement do not change XMM, MXCSR or raw/pending x87 state. No new general checkpoint framework or independently mutable VM field is required.

Scalar State import and run-option capture reject an intervening admitted run even when it completes synchronously from cached code during a getter. Context, SIMD and x87 imports follow their projection-local ordering contracts in the [context](../mode-context-and-decoding/spec.md), [SIMD](../simd-integer-and-data/spec.md) and [x87](../x87-state-and-execution/spec.md) specifications.

## FLAGS stack transfers and privileges

PUSHF captures the live architectural flags view and pushes its low selected width through the existing SS stack path. In 32/64-bit images RF and VM are zero. Reserved bits are zero except bit 1, including the upper 32 bits in a qword image. The 16-bit form stores the low 16 bits. PUSHF does not change other flags; RF follows the instruction-begin rule below.

POPF captures the complete selected-width stack value before changing SP or flags. Ignore reserved bits and preserve fields excluded by the following table. A successful POPF clears RF; it never loads RF, VM, VIF or VIP from the stack. The 16-bit form preserves AC and ID. The 32/64-bit forms can update AC and ID at every CPL. NT and the arithmetic/TF/DF/OF fields are writable at every admitted privilege level.

| profile                                  | PUSHF admission                 | POPF IF and IOPL writes                       |
| ---------------------------------------- | ------------------------------- | --------------------------------------------- |
| real                                     | admitted at every imported IOPL | both writable                                 |
| protected, compatibility, long64; CPL0   | admitted                        | both writable                                 |
| protected, compatibility, long64; CPL1–3 | admitted                        | IF writable iff CPL<=old IOPL; IOPL preserved |
| virtual8086, IOPL3                       | admitted                        | IF writable; IOPL preserved                   |
| virtual8086, IOPL0–2                     | #GP(0) before stack access      | #GP(0) before stack access                    |

Use the pre-instruction IOPL for permission decisions. Insufficient POPF privilege silently preserves IF/IOPL where the table requires preservation; it does not become a #GP outside the virtual8086 admission failure. Consult SDM Table4-20 and its operation algorithm for the CPL<=IOPL case; the introductory prose contains a conflicting IF listing.

CLI clears IF and STI sets IF in real mode, or when CPL<=IOPL in protected/compatibility/long64, or IOPL=3 in virtual8086. Otherwise report #GP(0) without modifying IF. VIF/VIP remain unchanged. These instructions do not access operand memory. IF does not mask TF traps or numeric faults.

Use existing stack-address wrapping and raw upper-bank policies. A pushed slot and popped slot have the full selected width, even across aliases or mappings. Check the full range before the private-RAM write. Failed PUSHF/POPF preserves SP, destination bytes and all flags other than an already-cleared RF. The original diagnostic remains authoritative for segment, noncanonical, mapping and permission failures; do not invent #PF/CR2 or IDT delivery. For example, a real-mode stack fault at SP=1 remains a detected stack failure; #DF/shutdown from attempted exception delivery is outside this contract.

## SS loads

Select MOV SS `8E /2`, register or memory, in every supported mode. It reads only the low16 selector of a GPR or exactly2 memory bytes, regardless of operand-size/REX.W. REX.R does not extend the segment selector field; REX.B can extend a GPR source and ordinary address extensions apply. Memory EA uses old GPRs and loaded segments, including an explicit SS override. MOV CS and reserved segment encodings remain invalid.

Select POP SS `17` outside long64, with operand16/32 and the old SS-selected stack-address size. In long64 it is invalid. Other segment PUSH/POP forms remain separate coverage. For copied private RAM, select a full operand-width stack read and use its low16 selector; this is the checked footprint chosen from the POP operation algorithm, not a universal hardware bus-footprint claim. Prepare the incremented raw SP using the old SS.B and inherited upper-bank rule before installing the new SS. A new SS.B never reinterprets that same instruction's pop step.

Both operations use the existing SS descriptor-load rules: writable data, RPL=CPL=DPL, #GP for selector/type/privilege failure, #SS for a qualifying non-present descriptor, and the existing long64 null-SS exception. Real/virtual8086 selector loads use their established base/cache rules. Capture the old source/stack value before descriptor lookup and an accessed-bit write; do not reread an aliased source after that write. Descriptor-A admission precedes its effect, then publish selector/cache, prepared POP SP and boundary state together. Failed loads preserve SS/SP and other registers, with only the RF begin effect allowed. Same-selector loads still validate current descriptor memory; a context-equal successful load still has its SS suppression/history effect. Accessed writes and SS-context changes participate in ordinary backing/context invalidation before a successor can execute.

## instruction begin and RF

RF suppresses instruction breakpoints, which are outside this slice; it does not suppress TF single stepping. Its clearing is still observable and must follow a defined begin point.

Preserve RF on entry budget0, stop-at-current, required instruction-fetch/CS-limit failure, translation/resource refusal, unimplemented instruction and private invalid-encoding diagnostics. These engine diagnostics do not assert an architectural #UD-delivery phase. A waiting x87/MMX/state-image operation that detects an existing pending #MF before execution also preserves RF. Retain each family's established waiting/no-wait classification.

After complete selected decode and those early checks, clear RF before ordinary execution checks/effects. A later data/stack/descriptor/target failure, denied CLI/POPF privilege, reserved MXCSR fault or newly raised numeric exception may therefore leave RF=0 with zero retirement. Preserve the original fault and all other instruction-specific fault-state rules. Do not clear RF only at successful retirement, or clear it before an early pending #MF check.

For a nonzero-count REP, no available repeat work before its first element preserves RF. With work available, execution begins before its first attempted element; RF stays cleared after success or an operand fault. A zero-count REP completes and clears RF without an operand access. Restoring the comparison entry flags on private suspension/fault must not resurrect RF. No-wait x87 operations begin normally despite pending exceptions. A bare string follows ordinary instruction accounting.

## completion, single step and interruptibility

Sample TF before executing an instruction. Setting TF with POPF when its incoming value was zero produces no trap after that POPF. Clearing TF with POPF when it was one still produces the sampled single-step trap after the successful POPF. Faulted/unexecuted instructions produce no single-step trap, and cannot retire to escape the fault.

After a successful instruction with sampled TF=1, report reason `debug-exception`, vector1, class `trap`, cause `single-step`. Append the new reason without renumbering existing reason IDs. Metadata includes source `instructionPc`, `resumePc`, boolean `instructionCompleted`, and `resumeFlags`: the architectural flags image for a possible later event frame, including VM derived from mode. For an unfinished repeated instruction, force RF=1 only in that saved image. Live `State.flags` retains its actual RF value; reporting a trap does not simulate handler entry or clear TF/IF/NT. No error code or DR6 register implementation is implied.

Completed instructions retire once and publish the next logical PC, including branch targets, near returns and the prepared far-transfer destination. Target-value checks belonging to the instruction still precede completion; destination instruction fetch follows the trap boundary. Thus a completed JMP to an unmapped but valid target can produce #DB before that target is fetched. A successful far change publishes the new CS/SS/CPL/submode and full prepared SP before reporting the trap; old generated locals cannot overwrite them.

For TF=1, REP stops after each completed element. An unfinished repetition has resumePc=current instruction, zero retirement, one repeat iteration, advanced count/indices and the completed element's effects. CMPS/SCAS expose that comparison's flags at this architectural trap boundary. A final or condition-terminating element retires once and uses next-PC. A zero-count REP retires once with no repeat iteration and can trap. A fault before completing an element reports the original fault without a trap for that element. The established repeat-budget/private-invalidation comparison-entry restoration policy remains in force for those private suspensions; do not apply it to an architectural trap.

Report an eligible trap before post-completion budget, stop, repeat-budget or code-invalidation dispatch. Entry budget0/stop-current still prevents execution. For partial REP, apply this order after the element and its count/index/flag/code-write effects. Never execute a stale successor before reporting. The report is returned exactly once for that completed boundary; resuming executes the published continuation normally, with TF unchanged unless the caller changes it. Clearing diagnostic storage between runs cannot discard a trap hidden behind a budget/stop reason, since no such lower-priority reason may replace it.

STI creates its one-instruction maskable-interrupt shadow only when incoming IF=0. STI with incoming IF=1 does not create a fresh shadow. A successful MOV SS or POP SS suppresses its own sampled TF trap and establishes an SS shadow through the following instruction. LSS suppresses neither its own TF trap nor events on the following instruction. An SS shadow does not suppress the following ordinary instruction's TF trap.

At the next successful instruction or final REP completion, consume the incoming shadow; private suspension after partial REP elements preserves it until the instruction completes. A newly eligible STI or MOV/POP SS can establish its own shadow at that boundary. For consecutive SS loads, select no extension of an already active SS shadow and no suppression of the second load's TF trap. The architecture guarantees suppression only for the first consecutive load; this is Ring64's explicit choice for the remaining case. The second load still applies its normal segment/SP effects.

Private suspension/failure detects no delivered exception, so it preserves the incoming shadow. Select reporting an architectural trap to clear both shadows, including a newly created STI shadow or a shadow held across an unfinished REP. Thus TF1/IF0 STI returns #DB with IF1 and both shadows false. This is the controlled-exit observation policy; no handler flags are otherwise applied. A later delivery contract must clear blocking state at actual event delivery, including delivery before successor completion. STI's shadow is retained for inspection and later IRQ delivery when no trap is reported; this slice does not claim maskable interrupts can be injected or serviced.

## generated execution and ownership

Rust owns writable masks, privilege decisions, RF phases and boundary semantics. Generated Wasm may inline those rules without calling a generic interpreter. Host code validates/copies transport and preserves lifecycle guards; it does not compute x86 FLAGS semantics.

Retained middle entries, dynamic transfers, helper failures, context redispatch, code-writing aliases, cache eviction and pending asynchronous compilation must use current flags and interruptibility. A specialization on TF/RF/shadows needs guarded assumptions at every reusable entry and publication boundary. POPF, host imports and context replacement must not permit stale assumptions to execute one extra instruction. PUSHF observes predecessor flags without forcing unrelated numeric-bank copies.

Keep the default TF0/RF0/clear-shadow path free of new unconditional per-instruction helper calls, event polling, whole-bank spills and allocations. Do not require byte-identical generated code when a representation change is justified; verify its cost. Append or adapt transport fields from one authoritative Rust layout, update host validation, and retain existing generated entry arguments unless a measured necessity requires otherwise. This spec defines behavior rather than a new effects IR or source tree.

## verification and performance

`npm run check` is the implementation acceptance command. Keep tests with their semantic, decoder, lowering, transport and public lifecycle owners. Review correctness, boundaries and performance independently; use manual tables/literal bytes rather than implementation-generated expected values.

Compare the inherited checked scalar/flags, memory, strings, stack/control, SIMD, MMX/x87, retained-entry, short-resume and forced-churn workloads on matched Node/Chrome cohorts with identical inputs and checked observations. Include default-clear controls and characterize system-flags-preserving operations with TF0. The old build rejects the new control bits, so those inputs are current-only coverage or within-current clear/nonzero controls; mark their old-build baseline unavailable rather than bypassing validation.

Characterize PUSHF/POPF/CLI/STI and TF stepping separately, including an instruction per public resume, partial REP, SS suppression and context changes. Record translation, browser compile/instantiation, first completion, early/later reuse, native entries, dispatches, generated/cache bytes and diagnostic latency. Time only equivalent work. Keep raw balanced samples; investigate material outliers with fresh, reversed and same-build controls. Separate synthetic throughput from application performance, and shared-process first completion from independent cold starts.

Implementation checkpoints are flags/state authority with inherited preservation; decode and checked FLAGS/SS stack/control semantics; RF begin phases; TF and shadow boundaries; REP/context/cache/host integration; independent review and matched performance. Each checkpoint includes its concrete consumers and tests. They do not require separate user-facing specs.
