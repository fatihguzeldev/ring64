# external interrupts and halt

## purpose and chosen boundary

Complete external request → instruction-boundary acceptance → guest handler → IRET → continuation, including a guest that waits with HLT. Reuse the implemented gate/TSS/IST/frame and exception-delivery owners rather than introducing a device controller or another execution loop. This follows [event delivery and returns](../event-delivery-and-returns/spec.md), [software events and iret](../software-events-and-iret/spec.md) and [system flags and instruction boundaries](../system-flags-and-instruction-boundaries/spec.md).

The implementation through `547609c` already supplies IF/STI/SS history, precise TF outcomes, processor entry, bounded escalation and checked IRET across imported execution contexts. External intake and HLT close a coherent remaining delivery vertical. DR breakpoints require their own access/debug producers; paging requires control-register authority, a physical domain and walks across every access owner.

Select a single-CPU, idle-only embedding profile: one controller-selected maskable interrupt slot and one coalescing NMI latch. Requests cannot arrive during an admitted run, including an asynchronous compilation wait. There is no concurrent Wasm preemption, timer callback delivery, PIC/APIC, EOI, interrupt priority controller, pin-level protocol or active-run injection. A device that needs a larger queue owns it outside the CPU. This limit is part of the public contract, not a claim about hardware interrupt timing.

## intake, source identity and observation

Add synchronous idle-only methods:

```ts
cpu.requestInterrupt(0x20); // true: occupied the empty IRQ slot; false: already occupied
cpu.requestNmi(); // void; set the NMI latch, coalescing repeated requests

await cpu.run({ budget: 100n, eventDelivery: { budget: 16n } });
```

`requestInterrupt` accepts an integer number in `0..255` without coercion; invalid input rejects even if the slot is full. An occupied slot is never overwritten, including by the same vector. Requests do not inspect tables, capture PC/FLAGS, clear shadows, wake execution or debit an allowance. Apply the existing disposed/failed/busy lifecycle guards; reject during active execution or compilation without changing the queue. Both methods may queue while halted, pending or shutdown. An IRQ queued in shutdown remains inert there.

The architectural owner distinguishes `irq`, `nmi` and processor exceptions independently of vector. A true NMI uses vector2, ignores IF and establishes NMI blocking. An IRQ tovector2 is still maskable and does not establish that blocking; an IRQ tovector13 has no error-code slot and is a benign first delivery for escalation, not #GP. IRQs to all admitted u8 vectors use this same external-source rule. This API consumes a vector already selected by an outside controller, so it does not invent APIC priority or reserved-vector behavior.

At a fresh observable boundary, NMI is eligible when latched, not NMI-blocked and not SS-inhibited. IRQ is eligible when its slot is occupied, IF1 and neither STI nor SS inhibition applies. Select the explicit profile in which STI does not inhibit NMI; Intel permits processor-dependent NMI inhibition after STI. Preserve the predecessor's MOV/POP SS, LSS, consecutive-load and incomplete-REP shadow rules.

An eligible request is accepted atomically into one frozen pending interrupt before any entry access: remove its slot/latch and capture the logical continuation PC and architectural saved FLAGS. Acceptance of NMI sets `nmiBlocked` immediately, before even the first IDT/IVT read. Eligibility tests apply to queued selection, never to retry of an already accepted source; its own NMI blocking cannot prevent that retry. Acceptance also leaves halted/shutdown activity; a later private refusal does not restore that activity or requeue the source. A newly queued request can occupy the vacated slot/latch while an earlier accepted event remains pending, but only after the run has yielded.

## arbitration and bounded service

Use `eventDelivery: { budget: bigint }` as the canonical opt-in for both the existing selected exceptions and external service. Retain `exceptionDelivery` as an equivalent backward-compatible alias. Supplying both with non-undefined values rejects; explicit undefined means omitted. Preserve the predecessor's unsigned64 validation, single property capture, reentrant run-generation/lifecycle validation and atomic admission. Do not read an alias budget twice or establish another delivery allowance.

With either option, every automatic entry attempt debits the same allowance immediately before it begins, including private refusal, unsupported machinery and architectural escalation. Queueing, source selection, HLT and NMI unblocking are not attempts. Retain `deliveryAttempts`, `remainingDeliveryBudget`, `event-budget` and the existing no-progress contract. Instruction retirement, repeated elements and entry attempts remain independent. Software INT entry and IRET keep ordinary instruction accounting.

Omission preserves processor-exception report behavior. A retained processor exception still returns `pending-exception`. A retained accepted external event, or an eligible queued external source at an ordinary/halted boundary, returns the new `pending-interrupt` reason without acceptance, entry access or queue consumption. An ineligible queue does not prevent ordinary execution. No option plus shutdown still returns `shutdown`, preserving any queue. Append new reason IDs without renumbering predecessors.

Preserve these frontiers:

1. A shutdown without the selected NMI wake condition below returns shutdown before instruction budget/stop. Otherwise initial instruction-budget0 and stop-at-current-RIP prevent all acceptance, delivery and HLT work. A retained pending source is then serviced before new arbitration or guest-byte probing.
2. Complete an already executing instruction's selected synchronous outcome first. A completed TF trap has priority over NMI, then IRQ; next-instruction fetch/decode follows external arbitration. This is Intel's distinction between a trap on the previous instruction and a lower-priority instruction-breakpoint fault. Do not replace a retained selected event across a private yield with a later higher-priority request.
3. After a newly selected exception or an instruction completion that makes a queued source eligible, stage/service before post-execution budget/stop, as for the predecessor's last-allowance TF trap. IRET is such a completion boundary; successful software INT entry uses the handler gate in4. With delivery allowance0, acceptance can leave a frozen pending event and `event-budget` without an attempt. In report mode the corresponding selected diagnostic or pending-interrupt return precedes post-work budget/stop.
4. After successful automatic or software INT entry, apply instruction-budget/stop-at-handler before probing handler bytes or accepting another queued source. With work available, fresh arbitration may accept NMI before the handler's first instruction; an interrupt gate's IF0 masks IRQ but does not mask NMI. Each additional automatic attempt consumes allowance. No completed frame is replayed after a handler translation refusal.

An unfinished REP cannot receive a new request while running under this intake profile. A private repeat-budget/memory suspension followed by idle intake is a fresh before-instruction boundary using the published state: completed elements remain committed, the continuation is the source REP PC, and comparison FLAGS retain the predecessor's private suspension policy. Do not reconstruct last-comparison FLAGS, force saved RF1 or claim a hardware mid-REP interruption by decoding the continuation bytes. Existing genuine partial-REP TF traps retain their precise saved FLAGS/RF and priority. Queued masked/blocked requests stay queued through an unfinished instruction; shadows retain their existing private-yield lifetime. Active-run intake and true new between-element external interruption would need a separate producer/history contract.

## HLT and NMI lifetime

Implement `F4` HLT in every imported mode. Real mode succeeds; protected, compatibility and long modes require CPL0, and virtual8086 faults with typed #GP(0). HLT has no explicit operands; operand/address-size, segment, F2/F3 and admitted REX prefixes do not change its effect. LOCK HLT is selected #UD after required-byte decoding, before privilege checking. Report mode uses the existing typed protection/invalid-encoding diagnostics; delivery mode admits these explicit new #GP/#UD producers. Other invalid/unsupported encodings and the inherited maximum-length frontier keep their old classification. Resource/required-byte/pre-begin failures do not halt or retire.

Successful HLT retires one instruction, advances the logical PC by the decoded length under inherited mode rules, publishes live state and consumes an incoming shadow as normal instruction completion. It selects persistent halted activity if no higher-priority completion outcome occurs. HLT does not fetch its successor, spin or hold a promise open. Return new reason `halted` once completion arbitration and the applicable post-work gates permit it; subsequent runs with no eligible wake return halted without probing bytes. A post-HLT budget/stop return may also expose halted state. IF0 plus only IRQ stays halted without consuming it. An eligible accepted interrupt wakes at the post-HLT PC, even if its entry then fails privately.

A sampled TF trap on HLT is a completion outcome and wakes the processor: report #DB with ready activity, or stage pending #DB in delivery mode, even when its entry allowance is0. Do not leave a single-stepped HLT permanently halted. `STI; HLT` with initially IF0 and a queued IRQ executes both instructions, consumes the STI delay and saves the PC after HLT. IF1 STI does not create a new delay and therefore cannot defer an already eligible IRQ.

NMI blocking survives successful/failed entry, intervening IRQ/exception handlers, private suspension, cache changes and ordinary context changes performed by guest instructions. It is not an IF bit and does not end at successful entry, RETF or software INT. One additional NMI may latch while blocked; repeated requests coalesce.

IRET unblocks NMI when the selected instruction commences execution, before its privilege/IOPL/NT/frame checks and before an unsupported task-return frontier. The unblock persists if IRET subsequently faults or meets a private stack refusal. Keep existing decode, invalid LOCK, required-byte and pre-begin resource frontiers before this side effect. This is an explicit early instruction effect outside the checked frame's atomic publication; it applies in report and delivery modes. A selected synchronous IRET fault is handled before fresh external arbitration. After a private failure with no selected event, a resumed run may accept the newly unblocked queued NMI before retrying IRET.

Extend the predecessor's terminal-shutdown profile only for selected NMI wake. Its exact wake predicate is an NMI latch, `nmiBlocked:false`, SS inhibition clear and event delivery enabled. If false, return shutdown before instruction budget/stop; if true, preserve initial budget/stop gates and all normal acceptance/allowance rules. A blocked or SS-inhibited NMI cannot wake shutdown, and IRQ cannot wake it. This is a deterministic Ring64 subset of hardware wake behavior: use the retained scalar PC/FLAGS as the saved boundary, do not claim architectural recovery from #DF, and do not infer a complete hardware “inside NMI handler” state machine from one bit. Reset/INIT/SMI and the remaining shutdown exit cases remain excluded.

## checkpoint and replacement contract

Keep a single execution-admission state; extend the existing event union and add a separate bounded interrupt projection:

```ts
type InterruptEvent = {
  source: { kind: 'irq'; vector: number } | { kind: 'nmi' };
  returnPc: bigint;
  savedFlags: bigint;
};

type EventState =
  | { kind: 'ready' }
  | { kind: 'pending'; exception: ExceptionEvent } // unchanged predecessor shape
  | { kind: 'pending-interrupt'; interrupt: InterruptEvent }
  | { kind: 'halted' }
  | { kind: 'shutdown' };

type InterruptState = {
  irq: number | null;
  nmiPending: boolean;
  nmiBlocked: boolean;
};
```

Construction starts ready with empty queues and no NMI blocking. `readState()` and run snapshots always include detached `event` and `interrupts`. `setState()` is complete scalar/event/interrupt replacement: omitted event means ready and omitted interrupts means empty/unblocked. Explicit undefined/null or malformed projections reject. Capture all fields once and publish atomically with the existing reentrant-import rules; nested successful host effects survive an outer rejection. Pending interrupt source is discriminated, accepts no exception/error-code fields and gives NMI no caller-selected vector.

Validate u8 IRQ numbers and exact booleans; unsigned64 `returnPc == state.rip`; the predecessor's saved FLAGS mask/bit1/VM agreement; and saved FLAGS equal to live scalar FLAGS plus mode-derived VM, including RF for this before-instruction external profile. Pending external sources require SS inhibition clear; pending IRQ additionally requires IF1 and STI inhibition clear, matching its captured acceptance boundary. Pending NMI requires `nmiBlocked:true` and permits either STI value; IRQ does not imply either NMI-blocking value. Halted requires both inherited shadows clear, since a successful HLT consumed them. Ready/processor-pending/shutdown may retain NMI blocking and queued work. Reject cross-field inconsistencies without changing scalar state, context, queues or artifact ownership. Existing processor-exception validation stays unchanged.

Successful host `setContext()`, even equal, clears accepted event/halt/shutdown to ready, both inherited shadows and NMI blocking. Preserve unaccepted IRQ/NMI queues: they have no captured old-context boundary and remain requests to this CPU. A rejected context import preserves them all. Guest CS/CPL/submode changes are architectural transitions and do not perform this host-replacement reset. Restore a complete checkpoint context first, scalar/event/interrupt snapshot last. A caller wanting to abandon all queued work uses scalar replacement with empty interrupts; context replacement alone is not cancellation.

Memory/mapping/backing operations, numeric imports/readbacks, clear-fault, probes and compilation/cache operations preserve queues, accepted events, halt/shutdown and NMI blocking. Repairing IDT/TSS/stack backing can retry a frozen event using current table bytes and live stack/GPR inputs. Accepted return PC/FLAGS stay frozen; no accepted source is acknowledged or captured twice. This is checkpoint transport and explicit intake, not a controller model or an unbounded event log.

## entry, failure and ownership

External entry reuses processor-source gate/target/TSS/IST and frame admission, bypassing software gate-DPL/virtual8086 IOPL checks. It carries EXT1 where the inherited architectural error algorithm uses EXT, preserves hard-zero cases and never pushes an error slot for the original IRQ/NMI. Preserve real fixed16 IVT frames, protected gate widths, selected virtual8086 32-bit gate profile and IA32e qword frames. Entry clears inherited shadows and transforms live FLAGS only when it commits; NMI blocking was already set at acceptance and survives refusal. Saved/live RF remain distinct where the predecessor's exception rules require it.

Keep captured reads and pre-admitted A-bit/frame writes before publication. Private map/permission/geometry/resource/Unsupported refusal retains pending-interrupt without partial frame/context effects; NMI acceptance/wakeup are already committed independent effects. A selected architectural entry fault replaces the external source with a pending secondary processor fault, with exact EXT-aware error code, RF1 and the accepted return boundary. Set that exception's diagnostic `instructionPc` to the same boundary; no guest instruction is claimed to have produced the interrupt. Treat the original external source as benign regardless of vector, so the first contributory entry fault does not immediately become #DF. Subsequent contributory escalation/#DF/shutdown follows the predecessor. Source consumption and NMI blocking survive the replacement.

Architectural eligibility/priority, source capture, HLT and NMI lifetime belong to the Rust x86/event/boundary owners. Embedding owns authoritative transport; TypeScript captures options, coordinates bounded service and artifact lifetimes. No x86 interpretation moves into host queue code. Extend the authoritative layout descriptor without independent offset lists or a prescribed source tree. Keep the existing generated invocation unless a concrete implementation requirement warrants review.

Inactive execution with no external queue must retain the plain fast path, without per-instruction external polling, new host calls or table reads. A queued source must become observable before the next instruction whenever eligibility changes, including STI completion/delay consumption, POPF and IRET. Service must also precede generated post-work budget/stop gates; adding arbitration only after host redispatch is insufficient. Idle-only intake does not require a new per-element external REP observer. Existing observed TF/RF/shadow code is not automatically sufficient for other newly emitted boundary work: retained middle entries, profile identity and stale asynchronous publication guards must agree. Do not bake dynamic queues/FLAGS/stop/budgets into discovery facts or add another cache. Generated HLT/pending-state writers must explicitly update the host's run-local event-kind knowledge; preserve its no-per-dispatch-poll optimization only where its mutation assumption remains true.

Publish live scalar/numeric state before entry and avoid stale generated locals overwriting helper output. A-bit/frame aliases invalidate executable backing through the existing owner; redispatch at the handler. Pending compilation, eviction and resumed middle-entry paths cannot lose queued work, replay a committed frame or install an artifact for the wrong boundary profile.

## acceptance packets

Use independent literal bytes/descriptors/frames through public Cpu and actual generated Wasm in Node and Chrome, with Rust decode/semantic/transport tests beside their owners. Addresses, instruction bytes and register/flag values below are hexadecimal; vector numbers, retirement/attempt counts and allowances are decimal unless prefixed `0x`. Unlisted state and guarded memory remain unchanged. Expected source classes, priority and frames must not be computed by the implementation under test.

1. Protected32 IRQ vector0x20, IF1/flags202, PC1000, ESP8000, CS8, interrupt gate to2000: accept before fetching unmapped source bytes; frame dwords at7FF4/7FF8/7FFC are1000/8/202, no error slot, live flags2, zero retirement/one attempt. Stop at handler before touching unmapped handler bytes, then IRETD returns to1000 and execution resumes. Contrast IF0, pending omission, zero entry allowance, initial instruction-budget0 and stop-at-source.
2. IRQ2 versus true NMI with IF0; IRQ13 versus processor #GP and `CD 0D`; controller-selected IRQ0/8/255. Check no error slot, source-aware benign escalation, no synthetic NMI block for IRQ2 and EXT1 failures. A bad IRQ13/NMI gate selects a secondary protection fault before any #DF; a further contributory failure can escalate.
3. Literal `FB F4` at1000 with flags2 and queued IRQ vector0x20 executes STI then HLT, retires two, saves1002/8/202, and executes no successor before handler entry. Use budget2/entry allowance1 and absent handler bytes. IF1 at initial entry instead services IRQ before STI. Warm plain artifacts/middle entries, then queue IRQ under IF0 and use POPF/IRET to enable IF with the last instruction allowance and stop at the new PC: entry must precede both post-work gates, without polling ordinary instructions. Also test CLI;HLT, inherited SS shadow, MOV/POP SS versus LSS and consecutive SS loads.
4. HLT alone with successor unmapped: next-PC halted snapshot, repeated halted runs with no fetch, IF0 IRQ retained, NMI wake at post-HLT PC, private failed entry leaving pending rather than halted. Test real/protected16/32/virtual8086/compatibility/long64, CPL3 #GP(0), LOCK #UD priority, ignored prefixes, truncated/overlength decode and pre-begin resource refusal without retirement/halt.
5. TF1 HLT with an incoming SS shadow and queued NMI: HLT consumes the shadow, completed #DB wins before NMI and the halted state ends. Report-mode #DB, allowance0 pending #DB and delivered #DB preserve their distinct effects. With enough budget, NMI then nests before the #DB handler's first instruction; a final instruction-budget/handler-stop gate still wins before that next acceptance.
6. NMI acceptance sets blocking even at entry allowance0; private IVT/IDT/TSS/frame denial preserves it with no half-frame. Queue another NMI while blocked, coalesce repeats, repair/resume the first, and prove the latch cannot nest until IRET starts. Include an intervening IRQ/exception and RETF/software INT, none of which unblocks it.
7. IRET private stack refusal, malformed frame, virtual8086 IOPL failure and unsupported NT return all expose early unblock after instruction begin. Contrast invalid LOCK, required-byte failure and pre-begin resource refusal, which preserve blocking. A selected IRET protection fault precedes queued NMI; a private failure permits NMI before retry on the next run. Cover real16, protected16/32, virtual8086, compatibility/long64 and successful outer returns.
8. Queue both NMI and IRQ; NMI wins and IRQ stays queued. A trap gate preserving IF permits later IRQ; an interrupt gate masks it. Software INT with an incoming SS shadow and latched NMI commits its frame but honors final instruction-budget/handler-stop before accepting NMI; IRET uses the completion-first rule instead. A frozen pending IRQ/exception survives a later queued NMI without reselection. Exhaust one shared allowance across external entry and secondary faults; successful entry followed by handler-first-instruction faults has bounded progress and no free attempts.
9. Partial REPE/REPNE suspension followed by idle intake uses source PC, remaining count/indices, committed bytes and published comparison-entry FLAGS without manufactured RF1. Resuming executes only remaining elements. Contrast the existing genuine partial-REP TF saved last-comparison FLAGS/RF and no phantom instruction retirement. Queued inhibited requests do not consume shadows during zero-work/private repeated yields.
10. Detached snapshots and complete restore of ready, halted, accepted IRQ/NMI, blocking/latches and shutdown. Old omitted projections retain their specified defaults. Reject malformed/coercible vectors, inconsistent saved flags/RIP/VM, pending NMI without block, accepted sources with incompatible captured IF/shadows and halted with shadows atomically. Getters perform nested queueing/context/state/run operations: capture once, preserve successful nested effects on rejection, reject busy intake and invalidate stale outer run admission.
11. Equal host context import clears accepted/halt/blocking but preserves queued sources; failed import and memory/numeric repairs preserve everything. Guest mode/privilege transitions do not cancel queues or blocking. Run/compilation waits reject intake, including cached and asynchronous paths, without source mutation.
12. Shutdown without an eligible NMI stays terminal; IRQ and blocked/SS-inhibited NMI cannot wake. Cover shutdown with retained SS inhibition after a failed entry chain, including instruction-budget0/stop priority. Unblocked queued NMI plus opt-in and clear SS inhibition may leave shutdown at the retained deterministic boundary, including allowance0/private refusal. Omitted delivery, initial instruction-budget0/stop and failed host imports preserve the queue/activity as specified. Do not use a returning #DF handler as a recovery oracle.
13. A-bit/frame aliases overwrite source, handler or retained middle-entry code; no stale bytes execute. Successful entry followed by resource refusal/eviction/stale compilation resumes without frame replay. Wrong boundary profiles cannot publish; the host observes every generated event-kind writer. Inherited rejected compilation remains a failed-CPU lifecycle, not a repairable event refusal.

## verification and performance

Keep the repository's Rust/TypeScript style, behavioral owners, shared literal scenario registration and dependency direction from `agents/architecture.md`. This spec does not prescribe new modules, dependencies, fixed file counts or a controller framework. Implementation checkpoints are complete intake/state capture, source-aware bounded service, HLT/NMI/IRET transitions, generated profile/cache integration and independent conformance/performance evidence; update this contract before broadening intake timing or architectural fault classification.

Run `cargo test --locked`, `npm run typecheck`, `npm run lint`, `npm run build`, `npm test` and `npm run test:browser`; `npm run check` is the complete formatting/lint/Clippy/Rust/build/Node/Chrome gate. For this spec-only change, run `npx prettier --check specs/index.md specs/external-interrupts-and-halt/spec.md`, check local links and `git diff --check`. No runtime or delivery-readiness claim follows from document checks.

Compare checked inherited kernels against source `547609c` on identical Node/Chrome bytes, inputs and observations: default report, event-enabled with empty queues and existing TF/RF/shadow paths. Use guests without newly admitted HLT for these matched baselines; old F4-as-Unsupported fixtures and discovery frontiers need intentional updates. Compare masked-IRQ/blocked-NMI overhead with equivalent current-build empty-queue controls. Characterize eligible IRQ/NMI, STI;HLT/wakeup, IRET unblock/refusal, allowance-one resumes, secondary escalation, queue checkpoints, private REP reentry and executable aliases separately. External delivery is current-only where the baseline has no equivalent; host emulation is not a matched baseline. Record queue/acceptance/attempt counts, translation/compile/instantiation, first completion/later reuse/short resumes, native entries/dispatches, artifact bytes/memory and latency. Use balanced/reversed samples and same-build controls for material regressions; synthetic wake latency does not establish application throughput. Falsify source-kind confusion, trap priority, acceptance-before-attempt blocking, IRET early effects, queue retention, inactive polling and stale profile publication with targeted mutations through the real public execution path.
