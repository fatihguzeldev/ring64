# near control and stack

extend [mode context and decoding](../mode-context-and-decoding/spec.md), [stack and near control flow](../stack-and-near-control-flow/spec.md), [string and repeated execution](../string-and-repeated-execution/spec.md) and their inherited memory/source contracts with memory-indirect near transfers, explicit stack-memory operands, frame teardown and counter branches. execute these forms in every currently imported mode, with independent operand, effective-address and implicit stack widths.

this scope uses existing GPRs, flags, loaded segments, checked scalar accesses and generated target routing. it changes neither the three-field State API nor the public run/transport contract. these fixed bounded instructions consume one instruction-budget unit on completion and no repetition units. preserve any repetition accounting already accumulated by preceding REP instructions.

far/privilege transfers, segment-register stack forms, PUSHF/POPF, ENTER, PUSHA/POPA, reset, descriptors, paging and guest event delivery remain separate work. ENTER and PUSHA/POPA require their own ordered multi-access and restart rules; REP's completed-element policy is not a general transaction mechanism.

## forms and widths

| family            | admitted encodings          | behavior                                                                                                                                                             |
| ----------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| memory near CALL  | `FF /2`, memory             | read an absolute near target, save the decoded next logical PC, then transfer. retain existing register/direct CALL forms.                                           |
| memory near JMP   | `FF /4`, memory             | read an absolute near target and transfer. retain existing register/direct forms.                                                                                    |
| alternate PUSH    | `FF /6`, register or memory | capture the selected source, then push one slot. retain opcode-register and immediate PUSH forms.                                                                    |
| alternate POP     | `8F /0`, register or memory | pop one slot to the selected register or explicit memory destination. retain `58+rd` forms.                                                                          |
| frame teardown    | `C9` LEAVE                  | select the frame address from BP/EBP/RBP at stack-address width, read one slot there, then publish the new stack and frame pointers. no preceding ENTER is required. |
| count branches    | `E0 cb`, `E1 cb`, `E2 cb`   | LOOPNE/LOOPNZ, LOOPE/LOOPZ and LOOP: decrement the address-size count, then branch on the decremented count and, where applicable, incoming ZF.                      |
| count-zero branch | `E3 cb`                     | JCXZ/JECXZ/JRCXZ tests the address-size count without modifying it.                                                                                                  |

memory CALL/JMP use a 16/32-bit offset outside long64 according to effective operand size. in long64 their target and CALL return slot are always 64 bits; 66 does not create a 16-bit near transfer. load the complete 2/4/8-byte target pointer at this width before validating its value. the loaded value is a logical CS offset, not a linear fetch address.

PUSH/POP and LEAVE use inherited stack-slot selection: outside long64, effective operand size is 16/32; long64 defaults to 64, 66 selects 16, and effective REX.W selects 64. long64 cannot encode a 32-bit slot. for LEAVE, `66 C9` uses a word; `66 48 C9` uses a qword; `48 66 C9` uses a word because the later legacy prefix cancels the earlier REX.

explicit memory addressing follows the complete inherited ModR/M/SIB, displacement, RIP-relative grammar, address-size override, register views and segment-selection rules. 67 changes explicit addressing and counter selection, not implicit stack width. stack address size remains SS.B outside long64 and 64 in long64; it is independent of slot width and CS.D. LEAVE has no explicit memory operand, so address/segment prefixes do not change its SS frame access, while inherited prefix ordering still determines effective REX and instruction length.

apply REX extensions only to real encoded registers. REX.R does not extend `/digit` selectors. `FF /6` and `8F /0` register encodings obey REX.B exactly like their opcode-register equivalents; no byte-register views are involved. default segments depend on actual base identity: inherited RSP/RBP selects SS while R12/R13 and an index-only BP retain their inherited DS behavior. explicit overrides affect only the explicit source/destination, never the implicit SS stack access.

retain all admitted prefix/length rules. REP/F2/F3 forms remain unsupported, including unimplemented BND behavior. repeated LOCK or mixed LOCK/repeat prefixes remain unsupported under the inherited deciding-prefix policy. for a single LOCK prefix on the admitted near/stack/count families, first consume the otherwise required encoding bytes, then return invalid-encoding before operand-data access; this is Ring64's selected diagnostic order, not a hardware exception-priority claim. unfamiliar FF/8F selectors remain unsupported before unrelated address fields are consumed. in particular, nonzero 8F selectors must not be blanket-classified as invalid POP: some byte sequences belong to unimplemented AMD XOP encodings.

## capture, access order and publication

all selected forms preserve the entire admitted flags word, including DF. retain the checked context/memory authority for full spans, split mappings, source/destination permissions, segment attribution, canonical/linear-domain checks and backing aliases. do not add alignment checks or a second access policy.

| form           | ordered checks and effects                                                                                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| memory CALL    | evaluate/read the explicit source using incoming registers; capture its target; validate that actual target; calculate/check/write the outgoing SS slot; then commit SP, actual target RIP and one retirement. |
| memory JMP     | evaluate/read the explicit source; capture and validate its actual target; then commit target RIP and one retirement.                                                                                          |
| memory PUSH    | evaluate/read the explicit source using incoming registers; capture its value; calculate/check/write the decremented SS slot; then commit SP, next RIP and one retirement.                                     |
| memory POP     | check/read the incoming SS slot; construct a temporary incremented stack-pointer bank; evaluate/check/write the explicit destination under that temporary bank; then commit SP, next RIP and one retirement.   |
| LEAVE          | construct the temporary frame-based stack-pointer bank; check/read one SS slot there; compute the resulting SP and BP views; then commit both pointers, next RIP and one retirement.                           |
| counter branch | compute the candidate count and condition without publishing them; validate only a taken target; then publish any count write, selected next RIP and one retirement.                                           |

CALL source-before-target-before-stack and POP stack-read-before-destination-write extend the current embedding's fault ordering. they are explicit checked-execution policies, not complete architectural exception delivery. a failed selected instruction leaves its incoming GPRs, flags, memory, logical RIP and retirement unchanged; successful predecessor instructions remain committed. report the existing full linear or segment fault tuple for the access that actually failed. the source target word is ordinary data: a source read failure wins even if its unavailable value would have been an invalid target.

target validation checks the actual loaded/computed logical offset and inherited CS/canonical rules, not target mapping/X permission. a canonical unmapped target can be committed; budget and stop at that next boundary still precede its fetch. failed long64 target checks retain the loaded target in the width-zero CS execute diagnostic. non-long64 CS-limit failures retain the inherited width-one segment tuple. do not reconstruct a target by re-decoding code after a write.

capture CALL/PUSH inputs before outgoing stack stores, including `[RSP]`, `[RSP-disp]`, another segment base, or a different linear alias of the same backing. CALL must retain its captured target while the stack store writes the return address. PUSH of RSP/ESP/SP and alternate `FF /6` register aliases retain the existing incoming-source rule.

### POP memory and pending SP

let `oldBank` be the entire incoming raw RSP bank. compute the incremented selected SP/ESP/RSP modulo implicit stack width, then merge that value into `oldBank` using the inherited write policy. this produces `pendingBank` without publishing a register write. every use of architectural bank 4 in the explicit destination address uses `pendingBank`; all other bases/indices retain their incoming values. then apply explicit address-size narrowing, segment-base addition and full-span checks normally.

the temporary value is not merely a zero-extended low SP. for a 16-bit stack, upper raw bits of bank 4 survive the merge and can matter to an address32 destination. this deterministic wrap rule is Ring64 policy; Intel documents processor-family-specific POP memory destination behavior at the 16-bit stack-wrap boundary.

the destination's addressing state does not change other banks whose low encoding bits happen to be four, such as R12. register `8F /0` remains the existing POP-register operation: increment the selected stack pointer first, then merge the popped value into the destination view, including aliased SP/ESP/RSP.

a failed destination store must preserve incoming SP even though its fault address was calculated from pending SP. a successful store commits pending SP exactly once. identity writes still require destination W permission and retain code invalidation. the source value is captured before any overlapping destination store; no failed element-like partial store is introduced.

### LEAVE

copy the selected BP/EBP/RBP view into the selected SP/ESP/RSP view at implicit stack width, preserving unrelated raw bits of the incoming stack bank. use the temporary bank's selected low stack-width offset for the SS read at operand slot width. the incoming SP is not the read address. after a successful read, advance the temporary SP by slot bytes at stack width and write the popped value to BP/EBP/RBP at operand width. preserve the independent upper bits of each bank according to mode.

stage these effects until the read completes. an invalid incoming SP does not prevent a valid frame-based access, and a failed frame read does not leak the temporary SP. neither 67 nor an explicit segment prefix changes the implicit frame access. do not add ENTER nesting, chain reads, speculative final-frame probes or hidden state to implement LEAVE.

## counter branches

address size chooses CX, ECX or RCX; it does not choose the target width. E0–E2 compute `(selected count - 1) mod 2^countWidth` on every successful execution, including an untaken branch. initial zero therefore wraps to the maximum count and ordinarily branches. LOOP requires only candidate count nonzero; LOOPE additionally requires incoming ZF=1; LOOPNE additionally requires incoming ZF=0. subtraction must not generate arithmetic flags.

E3 branches exactly when the selected incoming count is zero and never writes that bank. in long64, an actual address32 LOOP-family write clears upper RCX; outside long64 it preserves raw bits above the selected write width. E3 preserves the entire raw bank even when its selected ECX/CX is zero. R8–R15 remain untouched by implicit count operations.

add the signed rel8 to the completed next logical PC. in long64, target arithmetic remains RIP64 despite 66 or REX.W. outside long64, a taken target uses inherited effective operand16/32 narrowing, independently of the address-size count. untaken execution uses sequential EIP32 without operand16 truncation. only a taken target receives CS/canonical validation. a target fault must not publish the candidate count; an untaken success still publishes the decrement for E0–E2.

each counter branch retires once, regardless of branch direction. a self-loop or wrapped initial count remains bounded by instruction budget. it consumes no repetition allowance and must not use REP iteration counts as progress. apply the inherited budget-before-stop-before-fetch order at the committed next/target PC.

## discovery, reuse and code writes

discovery treats memory/register-indirect JMP as dynamic frontier; it may admit a CALL's static return fallthrough but never reads target RAM or imported registers to discover the dynamic destination. LOOP-family and E3 have two static edges. count, ZF, SP, frame values and pointer memory are invocation inputs, not translation constants. preserve exact-entry routing, overlapping instruction entries and logical/linear source-byte accounting in nonzero-CS contexts.

reuse a memory-indirect artifact while its target word changes; validate and route the newly loaded value on every invocation. target data is not an executable dependency solely because it contains an address. current instruction bytes and source identity still participate in inherited ownership, context, mapping, eviction and asynchronous publication rules.

successful code-writing CALL/PUSH/POP completes the whole instruction, including bytes, SP, actual next/target RIP, flags and one retirement, before invalidation dispatch. these fixed forms do not adopt REP's unfinished-instruction refetch rule. never execute a stale successor or retained middle entry. preserve committed state when the next boundary returns budget, stop, unsupported/fetch diagnostics or resource refusal. unchanged data writes must not flush unrelated artifacts.

## performance and implementation boundaries

compare the inherited scalar, memory/RMW, stack, multiply/divide, string/REP, retained-entry, short-resume and forced-churn workloads on matched core/host cohorts. retain specialization by decoded operand kind: ordinary register/direct forms must not pay a generic runtime memory-source branch, and flags/DF must not gain arithmetic work from count decrements. use the existing target lookup and source-validity owners.

characterize the new forms separately: pointer-table CALL/JMP with changing RAM targets, source/stack overlap, ordinary and code-alias PUSH/POP, postincrement-address POP, mixed-width LEAVE, taken/untaken/self-loop counter branches, translated segments and entry/reuse patterns. record checked instruction/element accounting, first completion, translation/browser compile/instantiation, early/later reuse, generated bytes/dependencies, native entries and dispatches. use balanced repeated raw samples and complete output checks outside timing. new forms have no executable old baseline; equivalent-looking instruction sequences may have different fault semantics. distinguish synthetic results and transport-size proxies from game performance and memory retention.

land reviewable increments: typed memory source/target models and decode; memory near transfers/PUSH with captured inputs; staged POP memory and LEAVE; counter branch discovery/routing; then full mode/alias/fault/reuse verification. each increment includes its callers and tests. do not broaden the admission table accidentally while refactoring an operand model.
