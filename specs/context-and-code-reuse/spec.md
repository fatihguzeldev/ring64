# context and code reuse

Implementation and bounded correctness/performance evidence: [verification](verification.md).

## objective and chosen vertical

Retain valid generated code across execution-context changes and reuse it when its assumptions become current again. A guest can enter a kernel, switch GS, deliver/return from an event and return to previously translated user code without recompiling every visited context. The same contract covers imported contexts, segment/table operations and far transfers. Correct source invalidation, asynchronous compilation, checked activation and bounded ownership are part of this vertical; a SYSCALL-specific cache shortcut is insufficient.

The baseline is `c956811ea40e94d6bf683f6e105839d1a383ffef`, including the complete [fast system transfers](../fast-system-transfers/spec.md) implementation and its [verification](../fast-system-transfers/verification.md). Current context publishers retire all translation sources when context changes. The host cache distinguishes PC and the existing boundary-observed profile, but not multiple live context variants. In the delivered simple 101-round-trip packet this produces 203 compilations, 203 native entries and 202 dispatches. The GS and CR3 variants each produce 405 compilations. These are structural observations from synthetic workloads, not application-throughput estimates.

This is an **engine vertical**, not additional instruction coverage or completion of another of the thirteen architectural areas in [the index](../index.md). Independent review considered the remaining CPU scope before choosing it:

| candidate                  | dependency closure and decision                                                                                                                                                                                                                       |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| context and code reuse     | measurable repeated compilation across existing context writers; closes assumption identity, memory ownership, activation and global capacity together. Selected.                                                                                     |
| x87 special functions      | strongest new-ISA alternative: fourteen remainder/exponent, transcendental and BCD operations remain. Needs an explicit raw80 accuracy/oracle contract, compound stack-result publication and expansion of the current five-bit operation descriptor. |
| imported legacy/PAE paging | strong system alternative; existing memory consumers are useful, but walk/control formats and PAE loaded-PDPTE lifecycle form another coherent execution family. Not just another leaf walker.                                                        |
| reset and mode transitions | requires an honest physical-unpaged lifecycle, control transitions, reset hidden caches and numeric-enable consumers. Current immutable memory profiles do not supply that contract.                                                                  |
| extended state / identity  | enable masks, real component consumers and reported capabilities must agree; a storage bank or CPUID table alone does not close an execution story.                                                                                                   |

Keep all existing supported modes, immutable memory models, instruction/fault semantics and public constructor options. Do not add legacy paging, reset, a TLB/root cache, a new instruction family, cross-CPU sharing or a generic context-interning/cache framework. Internal checkpoints below do not narrow the complete vertical.

## assumptions and ownership

Separate three facts: an owner is **alive** while its registered memory sources remain valid; it is **eligible** when its compiled assumptions also match the current CPU; it is **active** only after checked admission for a native invocation. A live artifact from context A remains dormant while B runs. Incompatibility alone must neither execute it nor prune it as dead. A dead/released owner can never become live again by restoring context, bytes, mapping names or a page root.

Use the existing Rust translation/source owner and TypeScript artifact owner. Bind an immutable assumption record to the source owner at compilation, captured from the facts actually used by discovery/lowering. A safe initial record is the full normalized `ExecutionContext` plus the existing boundary-observed profile. This includes mode, CPL, all visible selectors and loaded segment bases/limits/default-size/usability/kinds/attributes, GDTR/IDTR and loaded LDTR/TR state. Full conservative equality is acceptable; a smaller projection requires an explicit inventory and proof for every omitted field and consumer. Imported but currently unused facts must not silently alias merely because today's fixture does not exercise them.

Distinguish semantic equality from the existing context-change epoch. A previously installed A artifact must be eligible after A→B→A with unchanged sources and no destructive fence, even though the epoch changed. Preserve the conservative rejection of pending compilation that crossed an actual context change, including A→B→A. The epoch is not a permanent installed-artifact key. Equality/fingerprints must retain full-width values and resolve collisions safely; JavaScript Number truncation, hash-only equality, epoch saturation or identifier reuse must not admit stale assumptions or defeat pending-change rejection. Handle capacity edges explicitly before unsafe publication/admission rather than relying on practical unreachability.

Keep mutable runtime inputs at their existing authority. GPRs, FLAGS, x87/MMX/XMM/MXCSR state, DR values, fast-entry MSRs, EFER.SCE, interruptibility, pending/selected events, NMI blocking and run allowances are not compiled context snapshots to restore on a hit. Loaded FS/GS bases are context facts; the other GS slot remains in the fast-system bank. The existing observed/plain specialization is an assumption in its own right. Any further generated assumption discovered during implementation must have a named owner and validation mechanism before retention is enabled.

Inventory instance-scoped assumptions too: the immutable memory model, compile limits and core/layout/import realization belong to this CPU's existing lifetime; code/read/PTE facts belong to registered memory sources. They must not be lost by a context-only key or used to share artifacts across CPUs. They do not require duplicating an immutable configuration bank in every context record.

The Rust core authoritatively checks assumptions and source validity; the host indexes candidates and owns browser modules, aliases, LRU and release. Architectural state must not depend on browser cache policy. Opaque per-owner metadata or equivalent owner-local state is sufficient; a globally interned history is unnecessary. Metadata, indexes and source watchers must have a bounded lifetime tied to current state, bounded in-flight work or retained owners, with cleanup on release, failed installation, destructive retirement and disposal.

## context publication and memory fences

Cover every existing nondestructive context publisher, not only fast transfers:

- idle host `setContext`;
- segment, descriptor-table, LDTR and TR operations;
- ordinary far CALL/JMP/RETF;
- software event entry and IRET;
- automatic exception, IRQ and NMI entry;
- SYSCALL/SYSRET, SYSENTER/SYSEXIT and SWAPGS;
- selected FS_BASE/GS_BASE WRMSR.

Publish exactly the existing architectural results and retain still-valid owners rather than blanket-retiring them for a changed context. A context-changing instruction/helper must still end or revalidate its current generated path before a successor can use old embedded assumptions. Retaining an owner does not authorize the old native invocation to continue under new bases, sizes or privilege. Preserve current dispatch boundaries; reducing dispatches is not required.

Admission eligibility and instruction-completion observation are different checks. A successfully completed writer still publishes its retirement, #DB/deferred causes and newly eligible external sources before the existing post-work budget/stop gates. Do not broaden an existing observed-profile/boundary check into an early full-context-mismatch exit that bypasses this arbitration. In particular, last-budget SYSENTER after SS suppression and SYSRET restoring TF/IF retain their destination-boundary debug/NMI/IRQ behavior. The old owner becoming ineligible for the next native entry must not suppress completion of the writer that changed the context.

Do not skip the operation because its destination context is cached. Descriptor reads/accessed-bit writes, stack/frame accesses, page A/D effects, transfer completion, debug arbitration and selected-source handling still occur. A GDT edit alone does not reload hidden segment caches; invalidate actual registered code/table sources when affected, not an invented dependency on every descriptor byte.

Preserve predecessor side effects on success and failure. Equal host `setContext` still performs its current interruptibility/event/deferred-debug/NMI cancellation and diagnostic cleanup, while compatible code may remain retained. Failed IRET keeps the old execution context but can clear NMI blocking before frame admission fails. A successfully committed transfer or event entry followed by target #PF, private-X refusal, stop or compilation quota retains the destination context and completed frame/transfer effects. Resume must not replay entry, reread an already-consumed LSTAR or swap GS again. Event entry retires zero guest instructions; changing context does not itself imply retirement.

Preserve the exact existing paging invalidation policy. Successful guest MOV CR3, including a same-value reload, retires owners. Translation-affecting CR0/CR3/CR4/EFER.NXE changes and effective INVLPG retain their current destructive behavior. Noncanonical Long64 INVLPG does not retire owners; the guest instruction still retires once. CR2 writes, SCE-only changes, unchanged CR0/CR4/EFER and equal host `setPagingState` do not acquire new fences. Rejected writes publish no replacement context/root. A→B→A across a real paging fence must not recover an old owner. This spec deliberately does not promise reuse across roots or alter current TLB-free dependency rules.

Code and executable-translation sources stay registered while their owners are dormant. Host/guest writes through every backing alias, mapping/permission changes and code/PTE self-modification must invalidate affected inactive owners as well as the active owner. Preserve source identity by backing incarnation, exact geometry/offset and required access: executable bytes require X; page-table/read sources require R according to the existing owner. Removal/re-addition with the same public backing ID or restored bytes must not resurrect an owner. Keep existing `setMappings` source revalidation, active-code-change exits, required-fetch effects and paging fault priorities.

## lookup, activation and bounded lifecycle

Extend the existing artifact index to retain multiple context/profile variants at a logical PC, including direct middle entries. All entry aliases remain attached to their owning artifact. Overlapping entries and replacement must have a coherent selection/removal rule: removing one owner cannot erase another owner's entries, and encountering an incompatible candidate cannot hide an eligible one. Do not create an independent per-context browser cache.

Keep one global artifact cap, byte cap and LRU across all contexts/profiles. Count each retained artifact once, irrespective of aliases. Actual eligible uses update recency; rejected candidate scans do not masquerade as hits or make incompatible owners permanently hot. Finite candidate lookup must be bounded by retained owners; optional indexes must not retain an unbounded context history. Existing artifact/byte caps need not become total-process-memory limits, but report assumption/index/source-watcher overhead separately and prove bounded metadata per retained owner/source.

Treat activation as a checked admission, not an advisory call. Immediately before generated execution, the core validates the owner, complete assumptions and profile together. The host must consume a refusal; it must not call the stale module. A rejected candidate is no native entry, retired instruction, cache hit or compilation attempt. Distinguish a live incompatible candidate from a dead owner so pruning releases only the latter. Resolve remaining candidates or follow the ordinary miss path without retrying the same refused owner indefinitely. One lookup may examine each retained candidate at most once; if adversarial changes require restarting that lookup without guest progress, allow at most `maxTranslationsPerRun` such restarts per run in a separate private counter. Exhaustion is a controlled `resource-limit`, not an engine failure. Do not falsify `compilations` or `pagingRestarts` to pay for unrelated retries; ordinary mismatch scans do not themselves exhaust the restart allowance.

The initial lookup does not consume a restart allowance; each restarted lookup does. Once all permitted restarts have been used, yield before starting another lookup/probe. This new private restart frontier does not overwrite a fault/refusal already detected or a staged event. It is separate from the ordinary miss/translation-quota ordering below and must have its own cap-exhausted assertion.

Maintain the current miss frontier: required probe/access/decode faults or private refusals precede translation-quota refusal where they do today. A dormant candidate must not conceal a required #PF/#UD, execute-breakpoint boundary or private permission failure. Successful admission must also preserve current reached-instruction fetch/A effects and boundary observation; a cache hit is not a new permission bypass. No guest work or current context is rolled back merely because lookup, activation or browser compilation later refuses.

Compilation remains asynchronous and captures a specific owner/assumption record. Before installation, check captured source validity, pending-context epoch/profile and CPU lifecycle under the current strict policy. Discard pending work after A→B→A even when an already installed A artifact would be reusable. Do not stamp an old unit with the live context at install time. Disposal, source invalidation, changed context/profile, browser compile/instantiate failure, capacity refusal and exceptions must release unpublished owners exactly once without leaking assumption records or aliases. Public setters/readers keep their existing busy/reentry rules; test-only captured-core hooks do not authorize active-run public mutation.

Preserve public inspection detachment and existing resource meanings. If metadata needs an additional assumption token, keep it opaque and detached; do not expose a second mutable architectural state or serialize the full context on every instruction. A retained cache affects compilation/cache observations, not register/event/work semantics. Reuse the existing once-per-native-entry activation call for checked admission, including budget-one entries. No context poll inside the generated body, separate default host/Wasm poll or per-instruction JSON/hash transport belongs on that path; candidate-scan admission calls are measured separately.

## independent acceptance packets

Use actual generated Wasm through public `Cpu` on Node and Chrome, plus focused Rust/TypeScript tests at assumption, source, cache and coordination owners. Freeze literal bytes, contexts, frames and expected results independently of the key/normalizer under test. Compare full scalar/context/paging/fast-system/numeric/debug/interrupt/event/continuation state, guarded memory, retirement/repeat/event work and resource observations. Test-only admission/async hooks must be explicitly separated from public API coverage.

1. **Same PC, different facts.** A/B/A at the same RIP with distinct FS/GS bases, CPL, segment limits/usability/types/attributes, selectors and table/TR/LDT snapshots. Include identical bytes decoding differently under CS.D/mode and width-dependent direct middle entries across supported imported real/protected16/32/VM86/compatibility/Long64 profiles where supported. Warm A and B, return to A with unchanged sources and adequate capacity, and prove correct literal results with no new compilation. Conservative full-context inequality may compile extra variants; it must not admit wrong semantics. Independently perturb each recorded fact to falsify an omitted-field key.
2. **Dynamic inputs and equal imports.** Reuse code after changing ordinary registers/FLAGS, numeric/MMX/XMM/MXCSR, DR values and fast-entry-bank values. Confirm every dynamic consumer sees the new input, including SCE legality and runtime entry targets. Same-context host imports still cancel history as specified; bank/scalar/paging/mapping setters preserve their distinct authorities and busy/getter-reentry rules. A run-option getter may legally import B before returning its budget: outer admission uses the resulting B, not a capsule captured before getters. A context/mapping getter may complete a cached nested run before outer setter publication where the predecessor permits it; do not apply another setter's stricter run-generation contract. Conversely an option getter starting a nested run still rejects the outer run. Observed/plain variants must not alias, and enabling/disabling observation must select correct generated behavior without restoring stale runtime history; paging retains its always-observed specialization.
3. **Complete fast loops.** Warm separate finite fixtures for SYSCALL/SYSRET64, SYSRET32, SYSENTER/SYSEXIT32/64 and GS-based kernel-stack handover with real guest WRMSR/SWAPGS. Use different user/kernel code and data, literal return state, guarded stack bytes and debug-disabled/enabled variants. After all reached contexts/entries are warm, scalar/data-only rearming followed by another 101 cycles and repeated short resumes produces zero additional compilations/generated bytes or actual compiler/instantiator calls, provided capacity fits and no destructive fence occurs. Do not assume exactly two artifacts: middle-entry discovery can require more. Include `maxTranslationsPerRun=1`: prime with bounded budget-one resumptions until sources and entries settle, then complete a long warm run with zero compilation instead of exhausting the quota on a returning context. The baseline's partial quota-limited run is a functional control, not a latency denominator. Guest work, native boundaries and results remain correct; the CR3-changing control remains subject to fences.
4. **Every context writer.** Exercise segment/table/TR/LDT updates, far transfers, software INT/IRET and automatic fault/IRQ/NMI entry/return, with literal descriptor/frame effects and A→B→A reuse where facts return exactly. Include real/protected/compatibility paths already supported, descriptor accessed-bit behavior and direct entry into warmed successors. A false context-change continuation must not execute one instruction with old bases/sizes/CPL. Failed writers retain their specified partial effects; specifically faulting IRET retains old context while honoring early NMI unblock.
5. **Dormant memory sources.** While B runs, modify A's code or executable page-table dependency through host and guest aliases. Return to A: old code is rejected and repaired/recompiled behavior observes the change. Cover X versus R source permissions, mapping split/rebase/removal, backing remove/re-add with identical ID/bytes, writes restoring original bytes, active self-modification and overlapping middle entries. Poison descriptor memory without reloading a hidden cache as a negative control; only real source overlap or a later architectural reload changes admission/semantics.
6. **Exact destructive controls.** Root A→B→A, same-value guest CR3 reload, effective INVLPG, WP/NXE/control changes and PTE alias writes cannot revive retired owners. Contrast same-value CR0/CR4/EFER, equal host paging import, CR2, SCE-only changes and noncanonical Long64 INVLPG. Assert literal paging/control state, CR2/#PF metadata, A/D and private diagnostics; preservation of a non-fence alone does not waive another actual invalidation.
7. **Refused activation and miss priority.** Present live wrong-context/profile candidates, dead owners and overlapping eligible variants through a narrow test hook. Prove refused modules are never invoked and rejected candidates do not count as hits/native entries or touch LRU. Scan to an eligible variant or take the ordinary bounded miss path. With translation quota exhausted, contrast architectural #UD/#PF, execute debug and private-X refusal against a valid genuinely cold target. Repeat adversarial refusals to prove termination without fabricated work/counters. Exhaust the separate admission-restart allowance and assert its pre-next-probe `resource-limit` frontier, exact attempt bound and preservation of already-detected faults/staged sources.
8. **Pending browser compilation.** During controlled asynchronous compilation change an assumed base/context/profile, do A→B→A, invalidate a source and cross a paging fence. Public busy reads/setters and disposal still reject; separately use the captured-core hook for lower-layer currentness tests. Late installation must not adopt new facts. Exercise failed browser compile/instantiate, rejected busy disposal, eventual idle disposal, nonfitting artifact and failed publication, then assert exactly-once cleanup of unpublished owners and no dangling records/watchers/indexes. Installed live owners refused only for current incompatibility remain dormant; refusal alone does not release them. Include identifier/epoch capacity edges without requiring impractical real-world wraparound.
9. **Global capacity and aliases.** Alternate many contexts, observed/plain variants and overlapping middle entries under small artifact/byte caps. Check deterministic actual-use recency, global accounting, removal of only the evicted owner's aliases and no orphan assumptions/source registrations. Repeated A/B creation/eviction must stay bounded, including contexts with identical PCs and different widths. Small-cap churn may recompile; it must retain correct bounded resource exits and disposal cleanup. A unit too large to fit preserves the existing private refusal and releases its temporary owner.
10. **Committed boundaries and repair.** After a successful fast/far transfer or event entry, suspend before target fetch/compilation via stop, budget or quota. Separately select target #PF/private-X failure and repair through the existing host or guest-handler path. Check exact frame, saved boundary, source/destination CPL and retirement, including zero-retirement automatic entry. Resume executes each committed effect once. Changed LSTAR, stack data or GS after suspension must not cause replay of consumed entry work; fault repair may invalidate genuine sources normally.
11. **Debug and event histories.** Combine retained context changes with TF/RF, DR execute/data causes, SS-deferred history, STI/MOV SS suppression, pending selected IRQ/NMI and report/deliver modes. Cache hits must still honor the next fetch/boundary and ordinary completion arbitration before post-work limits. Assert frozen pending sources, NMI-block lifetime, handler frames and exact retired/repeat/delivery work across short resumes. Retaining code must not retain, clear or reconstruct history beyond the existing operation's rules.
12. **Inherited consumers and resource frontiers.** Run existing scalar/REP/LOCK, numeric/state-image, descriptor/far, software/automatic/external-event, debug and paging-repair packets on both memory models. Preserve accessed/dirty ordering, instruction-required-byte priority, partial REP/state-image progress and active-code invalidation. Compare independent semantic snapshots against the frozen baseline; declare intentional compilation/cache changes separately from invariant guest work. A source-only cache test or a successful syscall loop does not replace generated execution at these boundaries.

Falsification must kill independently asserted mutations for: PC-only/profile-only keys; an installed-artifact epoch key that prevents A→B→A reuse; omitted base/size/CPL/attribute assumptions; assumptions captured from late live state; inactive owners pruned as incompatible; unchecked activation; rejected-candidate false hits/LRU updates; stale inactive code/PTE aliases or backing incarnations; wrong R/X dependency domain; paging-fence resurrection; one unconverted context publisher; continuation under old generated assumptions; skipped descriptor/frame/fetch/A-D effects; dynamic bank/history restored from a capsule; leaked pending/released records; and per-context rather than global capacity. Count admitted semantic or structural assertion failures, not crashes, timeouts or infrastructure refusals. Keep rejected mutations and their reasons visible.

## implementation and performance boundaries

Follow [architecture](../../agents/architecture.md). Context owns architectural normalization/equality; discovery/lowering identifies assumptions; Rust translation ownership captures and validates them alongside memory validity; the host artifact owner controls index/LRU/release and the run coordinator consumes admission. Embedding adapts these contracts. Do not put x86 comparison semantics in TypeScript or memory-source policy in the browser cache, duplicate context authority, prescribe speculative directory trees or refactor unrelated instruction lowering.

Suggested small logical checkpoints: owner assumptions and alive/eligible tests; bounded variant indexing/global LRU and checked activation; conversion of all context publishers with exact fence controls; asynchronous/lifecycle integration; complete generated packets and adversarial review/performance evidence. These are future implementation/commit units, not permission to stop after a narrow slice. This turn prepares the spec only; implementation and commit/push need the separate authorization used by this workflow.

Spec-only checks: `npx prettier --check specs/index.md specs/context-and-code-reuse/spec.md`, local-link validation and `git diff --check`. Future implementation requires the complete `npm run check` gate (format/lint, native+Wasm Clippy, Rust, build, Node and Chrome), independent mutation evidence and recorded artifact restoration. Spec review is not runtime proof.

Freeze baseline source `c956811ea40e94d6bf683f6e105839d1a383ffef` and shipping core SHA256 `af835f3d514ee7abc6fa63db6545c6c1af6a87bd3e158151e996d70bb808d017` (1,122,118 bytes), with exact production-host/input hashes, tool/runtime versions and any dirty diff. Do not reuse an older paging/fast-system before-snapshot as this spec's baseline. Preserve raw evidence and source/artifact correspondence for both sides.

All 170 inherited report groups, 169 matched-delivery groups, 20 paging kernels, two EFER kernels and eleven fast-transfer kernels are now baseline-supported. Run explicitly paired Node/Chrome comparisons with the same bytes, inputs, observations, rearming and denominators; a current-only characterization file is not a baseline comparison. Preserve guest outputs, work, faults, frames and dynamic helper behavior. Keep the existing RunState transport size/offsets and five-argument generated entry ABI unchanged; assumption records belong to ownership, not architectural transport. Preserve generated module bytes/imports for unchanged lowering and declare any necessary changed-context body/import differences before interpreting measurements. Compilation/cache-hit/cache-byte observations intentionally change for retained-context cases, so blanket resource-count equality is not an acceptance criterion. Dispatch/native-entry changes require explicit boundary justification rather than an assumed optimization benefit.

Keep the inherited fast driver, including its whole-physical-RAM/code/table reset, for comparable cold/rearmed costs. Those writes invalidate code by design. Add small separate warm-reuse fixtures that visit every needed context/profile/middle entry during a finite untimed warm-up, then rearm only scalar/non-source data. Verify zero Rust translation, browser compilation and instantiation calls, zero additional generated bytes and bounded stable retained owners/bytes over the next 101 cycles and short resumes. Larger/smaller capacities must demonstrate the expected fit/churn distinction. Neither target count nor timing may be achieved by skipping guest work or suppressing invalidation. No zero-compilation target applies across the retained CR3 fences or bulk source rewrites.

Measure cold translation/compile/instantiate/first completion, early/later reuse, context switches, long loops and short quanta separately. Report per-run, per-round-trip, retired-instruction, native-entry/dispatch and event-delivery denominators, plus core/host/module/cache sizes and assumption/index/source-watcher overhead. Isolate host rearming, context comparison/transport and actual guest work. Include increasing same-PC context populations up to the configured global cap, eligible-first/eligible-last/miss controls, candidates examined, admission/validity calls, pruning/source revalidation and per-lookup transport; a bounded linear scan still needs an honest worst-case cost. Measure inactive-source write invalidation and eviction/release fanout too. No new full-context serialization/comparison per guest instruction or extra default observer belongs in the inactive path. Retain unchanged-context linear/paged and dynamic-MSR controls to expose lookup overhead; faster context loops do not excuse a material regression there.

Use balanced before/after order, reversed controls and same-build A/A with fixed meaningful rows and replicated absolute costs. Keep raw zero/sub-tick samples and undefined ratios. Preserve unresolved inherited measurements, including the predecessor's bounded Chrome matched-debug private-IDT residual, as historical limits rather than silently treating them as solved. Do not expand unions to average away a regression. The structural warm-reuse target is mandatory; elapsed improvements must be measured and reported without inventing a latency promise. This spec does not claim fewer architectural areas remaining, guest TLB reuse, boot capability, hardware cycles, p99, whole-application throughput or an exact remaining spec count.
