# string and repeated execution

extend [mode context and decoding](../mode-context-and-decoding/spec.md) with memory strings, direction control and bounded repetition. execute MOVS, STOS, LODS, CMPS and SCAS through the generated-wasm path in every imported mode. completed elements, instruction retirement and a public run's repetition allowance are separate quantities.

this uses the existing loaded segments, checked mappings and backing aliases. it includes the partial-progress rules these instructions need, without introducing a general effect IR or a second interpreter. port/string I/O, guest interrupt delivery, paging, descriptors, reset/transitions, ENTER, numeric state and parallel memory ordering have separate contracts. imported memory faults remain embedding outcomes, not delivered architectural exceptions.

## instruction forms and direction

| family    | encodings  | admitted behavior                                                 |
| --------- | ---------- | ----------------------------------------------------------------- |
| direction | `FC`, `FD` | CLD clears DF; STD sets DF; other admitted flags are preserved.   |
| move      | `A4`, `A5` | MOVS reads the source element and writes the destination element. |
| store     | `AA`, `AB` | STOS writes the selected AL/AX/EAX/RAX value to the destination.  |
| load      | `AC`, `AD` | LODS reads the source into the selected accumulator view.         |
| compare   | `A6`, `A7` | CMPS computes source memory minus destination memory.             |
| scan      | `AE`, `AF` | SCAS computes the selected accumulator minus destination memory.  |

the first encoding of each memory family is byte-sized regardless of operand prefixes. the second uses the inherited operand width: 16/32 outside long64 according to CS.D and 66; long64 defaults to 32, with 66 selecting 16 and effective REX.W selecting 64. unused REX register-extension fields do not select other implicit registers.

admit bare forms for all five families; F3 REP for MOVS/STOS/LODS; F3 REPE/REPZ and F2 REPNE/REPNZ for CMPS/SCAS. do not admit F2 MOVS/STOS/LODS or repeat prefixes on other instruction families as a side effect. they remain unsupported. a single LOCK prefix on these strings is a verified invalid encoding. INS/OUTS remain unsupported.

parse F2/F3 with the inherited prefix order and fifteen-byte rules. multiple F2/F3 use the last repeat condition as an explicit Ring64 decoding policy; repeated 66/67 remain presence overrides. a later legacy prefix cancels earlier effective REX, including when that legacy prefix is F2/F3. segment overrides retain the current long64 FS/GS rules. require every byte needed by an admitted form, including the opcode after a repeat prefix. reject an unsupported repeat/opcode combination before decoding unrelated operands. CLD/STD accept inherited ignored size/segment/REX prefixes; repeat-prefixed CLD/STD remain unsupported and a single LOCK-prefixed form is invalid. repeated LOCK prefixes or mixtures of LOCK and repeat prefixes remain unsupported.

expand the admitted `State.flags` mask from `0x8d7` to `0xcd7`, retaining required bit one. DF is bit `0x400`. preserve DF through every inherited instruction, including arithmetic/logical rebuilding, bit scans/tests, shifts, zero/masked counts, undefined-output policies, multiply/divide, faults and retained middle entries. only CLD/STD change it in this scope. `State` remains registers, flags and RIP; IF, TF and other control bits remain outside this imported projection.

## offsets, registers and segments

address size selects SI/ESI/RSI, DI/EDI/RDI and, for repeated forms, CX/ECX/RCX. it is independent of operand width and SS.B. use inherited 67 rules in all imported modes. a successful element adds its width when DF=0 or subtracts it when DF=1, wrapping each used index at address size. a repeated element also decrements the selected count by one. bare forms ignore and preserve the entire count bank, even when its selected value is zero.

update only the indices a family uses: both for MOVS/CMPS, source for LODS, destination for STOS/SCAS. apply inherited register-write rules: actual address32 writes in long64 clear upper bank bits; address16 writes preserve upper bits; non-long64 writes preserve all raw bits above their write width. LODS follows the accumulator's operand-width write rule. no implicit operation accesses R8–R15.

a repeated instruction whose selected initial count is zero completes once without element access, index/count/accumulator writes or flag changes. preserve all raw index/count bank bits in this case, including long64 address32 high halves. this is Ring64's explicit zero-count projection; vendor/model-specific zero-count upper-bank effects are not claimed.

MOVS/CMPS/LODS use DS:source unless a source segment override selects another segment. MOVS/CMPS/STOS/SCAS use ES:destination; a prefix cannot override that destination. a source-only override on STOS/SCAS has no memory effect. long64 FS/GS affect only applicable sources; the destination remains ES with ignored base/bounds. keep selected segment attribution even with base zero. do not select SS from implicit source/destination register numbers.

use the authoritative context/memory path for every full element span, including usability/type/limit, offset narrowing, base addition, canonical/linear domain checks, permissions and split mappings. address16 wraps the starting offset and the subsequent index update, not individual bytes of an element. a valid element can cross offset `ffff` under a sufficiently large loaded limit. retain the explicit non-long64 linear32 full-span policy and enabled-A20 behavior.

## element effects and failures

each element reads current memory; prior completed stores are visible to later source reads, including through another linear alias of the same backing. forward overlap therefore need not behave like memmove or a snapshot copy. any optimized path must prove equivalence to ordered element execution, including fault position, aliases, flags, work limits and code invalidation.

MOVS checks/reads its source before checking/writing its destination; CMPS checks/reads source before destination. this fixes the embedding's two-operand failure priority. LODS checks its source; STOS/SCAS check their destination. STOS captures the selected accumulator before its store. no callbacks, devices or shared-memory read effects are added.

complete all required access checks before committing an element's store, accumulator, flags, indices or count. a failed multi-byte store changes no bytes of that element. a destination fault after a successful MOVS source read still changes no architectural register or destination byte for that element. earlier completed elements and predecessor instructions remain committed. return the existing exact linear or segment fault tuple at the string instruction's logical RIP, with the failing element's start, full width, access intent, selected segment and first failing byte/offset.

MOVS/STOS/LODS preserve flags. bare CMPS/SCAS publish the inherited width-specific subtraction flags after their one successful element. repeated comparisons use each successful comparison's flags to decide whether another element follows: F3 continues on ZF=1, F2 on ZF=0, provided count remains nonzero. incoming ZF never suppresses the first comparison when count is nonzero.

capture a repeated comparison's entry flags immediately before that instruction begins, after all successful predecessors. on a fault, restore those entry flags while retaining completed index/count progress. on normal completion, publish the final successful comparison's flags. do not restore public-run or wasm-function entry flags when a predecessor changed them.

## bounded repetition and public results

extend the existing public run input and result:

```ts
run(options: { budget: bigint; stop?: bigint; repeatBudget?: bigint }): Promise<RunResult>;

// Additional fields on every RunResult:
repeatIterations: bigint;
remainingRepeatBudget: bigint;
```

check idle before reading option getters and again after capturing each option once. `repeatBudget` accepts unsigned u64 bigint, including zero, and defaults to the captured instruction `budget` only when omitted/undefined. reject malformed explicit values even on budget-zero, stopped or ordinary-only runs. recheck lifecycle after input getters; successful nested operations retain their effects. keep the existing pending-run/compilation restrictions.

only completed elements of prefixed string instructions consume repeatBudget, one per element. bare strings and inherited instructions consume none. preserve the separate instruction budget: the whole string instruction retires once on normal completion, including selected count zero, and never retires merely because some elements completed. on every exit, `repeatIterations = suppliedRepeatBudget - remainingRepeatBudget`, independently of `retired = supplied budget - remaining`.

add `reason: 'repeat-budget'` for an unfinished repetition that cannot start another element. it has neither fault record, retains current instruction RIP, completed effects and unconsumed instruction budget. a new run supplies a new allowance and resumes from published registers/flags. the allowance is shared across every repeated instruction and internal dispatch in that public run; recompilation cannot replenish it.

at a reached instruction boundary retain instruction-budget, stop, required fetch/decode and translation/cache admission ordering. repeatBudget=0 is not a gate on ordinary instructions, unsupported/invalid encodings, required-byte fetch failures or zero-count completion. for a valid admitted repetition, check selected count/completion before the work gate; then require allowance before starting the next element or checking its operands. operand faults are not probed when no element can start. an uncached instruction can still encounter translation/resource refusal before this element gate.

after each successful element, commit its effects and consume one repetition unit, then resolve count exhaustion or comparison termination first. if it completes the instruction, advance to decoded next RIP and retire once before applying the inherited budget/stop/code-write gates. exact final-element allowance exhaustion must not return repeat-budget or erase terminating comparison flags. if unfinished, return repeat-budget when the allowance is exhausted; otherwise dispatch on active-owner invalidation or continue with the next element. later ordinary instructions and zero-count repetitions may run with zero repeat allowance while instruction budget remains.

native progress validation checks both remaining quantities against their values at that invocation's entry. neither may increase; an internal dispatch must strictly decrease at least one. budget exits require instruction remaining zero; repeat-budget exits require repetition remaining zero, an unfinished repetition and positive instruction remaining. keep the two u64 quantities separate; their sum is not a u64 progress counter. a decrease only in repetition allowance is legitimate progress with zero retirement. a cumulative nonzero count from an earlier invocation does not excuse a later stalled dispatch. the host consumes transport progress values; it does not decode strings, inspect RCX to infer progress, or compute instruction semantics.

finite caller-selected allowances bound completed repeated work; they are not a wall-clock, compilation-latency or preemption guarantee. no unbounded native loop may ignore the allowance, and the host must return repeat-budget rather than silently refill it until a large count finishes. this does not add timers, guest interrupts or a generic scheduler.

## suspension, repair and code changes

when a repeated CMPS/SCAS remains unfinished at any controlled suspension, publish its entry flags, not intermediate comparison flags. this includes repeat-budget, internal code-invalidation dispatch and subsequent resource refusal. completed indices/count and earlier memory effects remain visible. normal completion publishes the terminating comparison instead. this is Ring64's host-suspension observation policy; future architectural interrupt delivery has its own flag/return-state rules.

restored entry flags make the existing State projection sufficient for a fresh restart. with no intervening host changes to code, context, registers/flags or operand memory, and successful required translation/cache admissions, partitioning only by work limits or recompilation produces the same eventual completion or operand-fault state, apart from per-run accounting/resources. mapping-repair comparisons must apply the same repair and data at the same completed-element checkpoint. no hidden cross-run instruction capsule is needed. observations and equal context imports preserve the published state; setState or changed contexts establish the next execution inputs normally. changed data, mappings, flags, accumulator or direction supplied while idle affect subsequent elements under those inputs. resuming the published state without changing its indices/count does not replay completed elements.

retain source ownership and alias invalidation. an unfinished REP store that invalidates the active owner commits that element, count/index updates and repetition accounting, then leaves at the same logical RIP with zero retirement for that instruction. re-fetch/re-decode there before continuing. writes that alter the current encoding may therefore replace the unfinished repetition with a different instruction; do not execute a latched stale form. this is the checked embedding's immediate code-visibility policy. unchanged current bytes may resume through a different artifact owner.

this completed-element boundary supersedes the inherited whole-writing-instruction rule only for unfinished repetitions. bare strings, completed repetitions and inherited scalar writes still complete the entire instruction and retire once before invalidation dispatch. never enter stale successors or middle entries. public-run repetition accounting and comparison entry-flag restoration survive owner retirement, limited-cache recompilation and resource refusal. completed final elements still honor budget before stop before a following fetch.

## performance and implementation boundaries

compare the inherited scalar, memory/RMW, stack, multiply/divide, retained-entry, short-resume and forced-churn workloads on matched core/host cohorts. admitting DF necessarily changes flag preservation; measure that cost rather than specializing on an unguarded imported flag value. avoid a generic per-instruction repeat branch, interpreter or host callback in the ordinary path. progress transport has one authoritative Rust layout, and flags retain one architectural meaning across scalar and string lowering.

characterize bare/repeated strings separately: widths/directions, source/destination modes and bases, independent mappings, disjoint and overlapping aliases, early comparison termination, faults/repair, code-writing aliases, large allowances and repeated allowance-one resumes. record checked work and retirement counts, first completion, translation/browser compile/instantiation, early/later reuse, native entries/dispatches, generated bytes and dependency/cache metadata. use balanced raw samples with all state/byte/accounting checks outside timing. distinguish transport-size proxies from memory retention, shared-process first completion from cold evidence, and synthetic throughput from game performance.

land reviewable increments: DF and inherited flag preservation; decode/string models; bare checked elements; repeated accounting and host-suspension semantics; alias/SMC/repair integration and public tests. each increment includes its consumers and regression coverage. these are implementation checkpoints, not separate instruction-family completion claims.
