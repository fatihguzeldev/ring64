# architectural access and legality faults

## purpose and selection

Complete guest access/encoding fault → architectural handler → guest repair → IRET → successful retry across the instruction families already implemented. A guest can repair an unusable data segment, a noncanonical operand, a mandatory-alignment failure or an illegal supported encoding without handing the repair back to the embedding. Preserve the distinction between architectural faults and private backing/resource refusals.

The implementation through `fee1edc` already supplies processor and external delivery, error-code frames, IRQ/NMI arbitration, HLT and checked returns. Its [event delivery contract](../event-delivery-and-returns/spec.md) deliberately excludes generic Invalid, segment geometry, alignment and linear-access diagnostics because they lack selected architectural provenance. Closing those producers is the next vertical; this is not a reason-string conversion or just an enum refactor. It reaches decode, translated accesses, multi-access instructions and failures during handler entry.

Hardware debug is the next strong alternative, but needs execute/data/GD producers, DR6/DR7 and fault-class #DB as well as the existing trap-class TF path. Paging needs physical backing, control-state authority, walks, A/D effects and #PF/CR2 together. A generic control-register/CPUID stub closes neither behavior. This increment strengthens the fault foundation used by both; it does not establish an OS boot path.

The [mode/context](../mode-context-and-decoding/spec.md), [private memory](../memory-map-and-code-validity/spec.md), [software entry/return](../software-events-and-iret/spec.md) and [external interrupt](../external-interrupts-and-halt/spec.md) contracts remain the foundation. No new run option, queue, delivery allowance or host injection API is required.

## selected producers and exclusions

Add producer-owned classification in the existing imported real, protected16/32, virtual8086, compatibility16/32 and long64 profiles. Classification depends on the instruction, effective segment, access phase and mode. The table describes selected architectural conditions, not every diagnostic bearing a similar name.

| selected condition                                                                                                      | outcome   | error code |
| ----------------------------------------------------------------------------------------------------------------------- | --------- | ---------- |
| Required instruction length would exceed15 bytes                                                                        | fault #GP | 0          |
| Proven architectural illegal encoding in a currently recognized instruction family                                      | fault #UD | none       |
| Runtime limit violation through SS in modes where segment limits apply                                                  | fault #SS | 0          |
| Runtime limit violation through CS/DS/ES/FS/GS; proven architectural null data-segment access or prohibited access type | fault #GP | 0          |
| Long64 noncanonical memory reference using effective/default SS                                                         | fault #SS | 0          |
| Long64 noncanonical non-SS operand, next instruction fetch or near control target                                       | fault #GP | 0          |
| Existing instruction-mandated alignment violation, including an SS-based aligned SIMD operand and FXSAVE/FXRSTOR        | fault #GP | 0          |

Retain existing typed #TS/#NP/#SS/#GP producers and their instruction-specific codes, except the audited hard-zero/EXT corrections below. Descriptor/TSS/gate operations have instruction-specific rules; a new generic mapper must not replace them. Select noncanonical in-domain IDT/GDT/LDT system reads as #GP(0) where their instruction/phase algorithm establishes that condition, while preserving the existing TSS-field #TS(selector|EXT) path. Widened system-address overflow and missing backing stay private. A selected hard-zero error remains zero during external/processor entry; EXT is not blindly ORed into it. In particular, noncanonical event-frame #SS and invalid handler-target #GP must not become error1 for INT1 or an external/processor source. Correct these existing producers in both report and delivery modes.

Inventory every existing `Invalid` production site and every access-failure consumer during implementation. For each, record the architectural condition or explicit retained private frontier beside the owner/test. Required-byte acquisition and unsupported prefix/form frontiers stay instruction-specific. Admit #UD only where the current decoder recognizes enough of a supported family to prove illegality: selected LOCK restrictions, memory/register-only violations and invalid mode-specific forms need literal tests and instruction-reference support. Keep legal unimplemented forms, unknown opcodes, duplicate-prefix frontiers currently reported Unsupported and excluded feature/task machinery Unsupported. Do not implement a new instruction family to fill this inventory.

Keep unmapped backing, private read/write/execute permissions, backing limits, widened address-domain overflow, allocation/translation limits and browser compilation failure outside the automatic source set. There is no #PF, CR2 or page-fault error code. `Cause::AddressRange` is not sufficient evidence for #GP: the private memory owner checks u64 span overflow before canonicality, and legacy translation has a private32-bit domain frontier. Preserve these widened private refusals and their priority. Canonical selection covers a valid in-domain start/span overlapping noncanonical space; do not reinterpret wrap/refusal policy as a new hardware memory model.

General alignment checking remains disabled under the inherited fixed AM profile; this adds no #AC. Long64 retains its ignored legacy segment limit/type/null checks and FS/GS base rules. Do not synthesize new faults from metadata the active mode ignores. Classify existing failed accesses rather than introducing new checks from a visible selector alone: legacy imported usable caches can carry deterministic default selectors. Protected/compatibility null-data selection requires the existing unusable-access failure and a null selector index/TI; non-null artificial unusable caches remain private absent a proven runtime rule. Imported artificial SS unusable/type combinations likewise remain private without provenance-specific proof; `segment == SS` cannot map every cause to #SS. Host input validation errors are never guest faults.

## provenance and access ownership

The x86 decode/access/protection owners supply the vector, exact error code and phase; embedding transports them and TypeScript coordinates bounded delivery. No TypeScript switch over diagnostic text, instruction bytes or numeric causes selects x86 meaning. Private memory continues to own mappings/backing/permissions independently of guest architectural classification.

Preserve logical source PC, effective segment, translated linear address where available, access kind/width, selected subaccess and before/after-instruction-begin phase through the failure boundary. Use owned typed contracts, not another mutable classification authority or an unbounded access log. Classification may reuse existing diagnostics as evidence inside the architectural owner, but must be independent of whether a report object was serialized or a transient diagnostic was cleared.

Current long64 scalar lowering passes linear address/width without a segment argument, and its helper initially records DS; lowering records the effective segment only on failure. Selecting #GP before that SS provenance arrives is wrong. Preserve default SS selection for RSP/RBP forms and actual stack accesses. Segment overrides obey the active mode: long64 CS/DS/ES/SS prefixes remain ignored, including for fault classification; an ignored SS override cannot turn RBX into an SS access and an ignored DS override cannot remove RSP's SS classification. Admitted FS/GS overrides and legacy-mode overrides retain their effective-segment rules. A memory operand of CALL/JMP/RET and its control target are distinct operations: an SS pointer-read failure can be #SS, while a successfully read noncanonical target is #GP. LEA performs no access.

Carry classification through all existing consumers:

- instruction probing, required-byte fetch and reached decode frontiers;
- scalar load/store, conditional reads, RMW/LOCK and pair operations;
- stack slots, near/far operands and target checks, LEAVE and returns;
- MOVS/STOS/LODS/CMPS/SCAS and repeated-element checkpoints;
- SIMD/MMX/x87 operands, masked/streaming operations and hints;
- sparse/full numeric-state images and their mandatory alignment;
- explicit descriptor-table operands, descriptor/system-table reads, TSS/IST, event frames, software entry and IRET;
- automatic entry refusal, secondary selection, #DF and shutdown.

Use the same architectural decision at helper and generated failure paths. The current guest accesses already use checked Rust memory helpers; V128 loads from returned scratch are not a second guest access. No new observer profile, per-instruction polling, all-access host callback or competing translation cache is justified by this increment. Preserve the five-argument generated invocation and existing numeric offsets unless a concrete requirement warrants a layout change through the authoritative descriptor.

## ordering, reporting and delivery

Default report mode retains existing reasons, typed diagnostic fields, instruction effects, required-byte frontiers and private resource priority, with narrow audited corrections: noncanonical event-stack #SS and invalid handler-target #GP report error0 instead of the old erroneous EXT-derived1. Each producer has the same correct code in both modes. Existing `eventDelivery` and its `exceptionDelivery` alias opt into the expanded architectural source set. With no option, a new classified fault is reported and does not create pending state. A retained event still follows the predecessor's pending/omission rules.

```ts
await cpu.run({ budget: 100n, eventDelivery: { budget: 8n } });
```

The decoder's15-byte limit is checked before requesting byte16. Missing an earlier required byte retains its existing fetch diagnostic; valid15-byte instructions remain executable. Discovery may stop at a future fault but cannot stage it, execute it early or bake a source decision into stale artifact metadata. When execution actually reaches a selected decode fault, classify it before translation/artifact admission, as for UD2. An exhausted remaining translation quota cannot replace a reached architectural invalid/length fault with resource-limit. Private required-byte failure still preserves its previous frontier.

Preserve instruction-begin distinctions. CS-limit instruction-fetch failure precedes begin and does not clear live RF. Newly selected decode #UD/length #GP use the predecessor's opted-in UD2 begin policy; report mode keeps its pre-begin behavior. A data/target/alignment fault after begin keeps the already applied RF clear. All selected fault frames save RF1 independently of live RF. Pending images remain compatible with the existing ExceptionEvent validation. Do not move waiting-x87 checks or an instruction's other established higher-priority checks merely to share a staging helper.

At fresh boundaries, retain completed TF trap → NMI → IRQ → next-fetch/decode ordering. A selected synchronous execution fault wins over fresh arbitration after its failed instruction. Initial instruction-budget0/stop prevents work; newly selected faults are staged and serviced before post-work gates under the existing shared attempt allowance. Successful automatic/software INT entry honors handler budget/stop before new acceptance; IRET remains an instruction-completion boundary. HLT activity writers must still be observed before host budget/stop gates. A new classifier cannot resurrect the stale event-kind failure fixed in the predecessor.

Do not reorder accesses to obtain a preferred exception. Preserve segment/canonical translation before mandatory alignment before private backing admission where those owners currently require it; retain instruction-specific numeric/control/descriptor priorities. False CMOV still reads its selected memory source. MASKMOV validates its full nominal8/16-byte geometry, segment and write permissions even with an all-zero mask; it reads no destination and writes/invalidates only selected bytes. Zero-mask invalid geometry can therefore select a fault, while successful zero-mask execution has no write footprint. PREFETCH/LEA retain their separate no-access rules, and CLFLUSH retains its special type checks. Sparse state images validate their inherited logical geometry and selected fields without turning preserved bytes into reads/writes. In a pointer-read plus target-validation path, a prior private pointer refusal cannot be replaced by a guessed target fault.

## publication, repair and entry escalation

Faulting instructions retire zero. Preserve each family's actual commit rules: no failed scalar/RMW destination or flags publication; completed REP elements remain committed with remaining indices/count and the established comparison-entry flag restoration; existing multi-access POP/far/event/state-image operations retain their documented subaccess/partial-progress rules. ENTER remains unimplemented with its inherited Unsupported frontier. This increment does not impose a new transaction over every instruction. Status/early effects such as deferred numeric state and IRET NMI unblocking retain their existing priority and lifetime.

Successful guest repair must not replay completed work. An illegal instruction may be patched through an executable alias, an alignment handler may repair the saved operand register, and a segment handler may load a valid descriptor/cache before IRET retries. Editing a descriptor alone does not update a loaded cache. Tests that need a valid handler stack must install a privilege/TSS or IST path; a broken source stack cannot be assumed to support same-stack recovery.

Classify selected architectural access failures inside event entry before the entry owner decides escalation. A #GP/#SS producer is contributory: a contributory fault during its attempted entry selects #DF, and a selected contributory fault during #DF entry selects shutdown. An original IRQ/NMI remains benign regardless of vector. Preserve original selected return boundary and exact source identity through replacement; no fabricated guest instruction is assigned to an external event.

Private missing/denied IDT/TSS/stack backing remains a repairable refusal, including during #DF entry. It must neither escalate nor lose the accepted source/NMI blocking. Keep captured reads and pre-admitted descriptor/frame writes before publication, preserve explicit early acceptance/unblock effects and invalidate executable aliases through the existing owner. Failed admission writes no half-frame or A bit. A successful frame is cleared exactly once from pending state even if handler compilation then refuses. A rejected browser compilation retains the failed-CPU lifecycle.

No new checkpoint shape is needed: the existing pending vector/PC/FLAGS/error slot can represent these faults. Memory/numeric repair preserves it; host context replacement retains its established cancellation/queue/blocking behavior. Run-local event-kind/source knowledge must be refreshed at every new state writer without adding a poll to ordinary dispatch.

## independent acceptance packets

Use literal bytes, descriptors and expected frames through public Cpu and actual generated Wasm in Node and Chrome, plus Rust owner/transport tests. Hexadecimal instruction/address/flag examples below use explicit formatting; vectors are decimal. Compare complete scalar/event/interrupt/context/numeric state, guarded memory, retirement/repeat/attempt allowances, failure diagnostics and artifact ownership. Expected classifications must not call the classifier under test.

1. Decode `F0 90` as report-mode invalid encoding versus opted-in #UD. Handler patches the LOCK byte through an executable alias, removes no error slot and IRET retries the repaired code. Distinguish retained unknown/Unsupported opcode `82`, documented but unimplemented CPUID `0F A2`, duplicate LOCK's retained private frontier and selected invalid long-mode forms. Every classified Invalid inventory row needs its own literal oracle.
2. Fourteen `66` prefixes plus `90` execute a valid15-byte NOP. Fifteen `66` prefixes select #GP(0) without fetching byte16. Deny byte15 to prove required-fetch priority. Include overlength ModRM/immediate demand, too-small positive source caps, exhausted remaining translation quota, future unreached diagnostics and retained middle entries. Public configured limits retain their existing positive-value validation. Report mode keeps its exact old exit/RF behavior.
3. Long64 `48 8B 03` with RBX=`0x0000800000000000` selects #GP(0); `48 8B 04 24` with the same address in RSP selects #SS(0). Use valid IST stacks, verify source PC and saved RF1, and repair the saved source register before IRET. `36 48 8B 03` remains #GP and `3E 48 8B 04 24` remains #SS because those overrides are ignored; admitted FS/GS overrides use their actual segment/base. Check default RBP/SS and a canonical start crossing the canonical boundary. Contrast u64-domain overflow retaining a private refusal.
4. Long64 register-indirect CALL/JMP and RET to a noncanonical target select #GP(0), distinct from a noncanonical SS pointer/stack read. A denied pointer read stays private; CALL does not push a return slot after target rejection and RET does not commit SP. Handler repair/retry reaches the intended target once.
5. Protected16/32 and compatibility limits: SS limit/expand-down violation selects #SS(0), other runtime segment limits select #GP(0). DS made unusable by loading a null selector can be repaired by a guest segment load. Use a valid handler stack and prove that a GDT edit without reload is insufficient. Contrast long64 ignored limits/type/null metadata and imported artificial SS cases explicitly retained private.
6. `0F 28 03` MOVAPS versus `0F 10 03` MOVUPS with a misaligned source, including SS override: the mandated alignment fault is #GP(0), while the unaligned form executes. Add FXSAVE/FXRSTOR. Canonical/segment failure wins before alignment; aligned-but-unmapped backing stays private. Preserve destination/numeric banks and all guarded bytes on failure.
7. Cross scalar, conditional memory, LOCK/RMW and pair operations with read/write/for-write refusal. Verify actual segment provenance, false-CMOV reads, unchanged arithmetic flags/destination, no speculative writes and code-alias invalidation only after successful publication. New classifier state cannot survive into an unrelated next exit.
8. REP MOVS and REPE/REPNE CMPS/SCAS fault after completed elements at a selected segment boundary. Save source REP PC/RF1, preserve count/indices/committed effects and the inherited comparison flag policy. Guest repair resumes only remaining work. Contrast zero count, zero repeat allowance, partial TF trap and idle IRQ intake without invented mid-REP history.
9. Numeric priority and images: waiting-x87 pending #MF precedes a later selected operand fault; unmasked SIMD/memory and reserved MXCSR cases retain their established checks. FXSAVE/FXRSTOR and legacy images preserve sparse geometry and all undefined/preserved bytes. Zero-mask MASKMOV still faults on selected invalid nominal geometry, retains private permission refusal and writes no bytes; pending MMX #MF still wins. Contrast valid zero-mask no-write/invalidation with PREFETCH/LEA no-access behavior.
10. Current CS-limit fetch #GP preserves live RF at its pre-begin frontier; a post-begin data #GP clears it; both save RF1. A selected decode fault follows the chosen opted-in begin policy. Alternate report/delivery modes, including resource refusal and cached entries, and distinguish private required-byte fetch refusal.
11. A selected #GP/#SS entry encounters an architectural SS limit/canonical fault on a handler stack: select #DF with no partial frame. A further contributory #DF-entry fault selects shutdown. Contrast identical missing/denied backing retaining pending state and exact refusal. Long64 report-mode `F1` with a noncanonical RSP reports #SS(0), and with a noncanonical handler RIP reports #GP(0), correcting the old error1; opt-in INT1, automatic exceptions and external entry preserve those hard zeros. Descriptor/TSS selector-coded errors keep their own EXT algorithm, including stack-switch cases whose architectural rule selects a selector rather than ordinary-runtime error0. With a newly loaded legacy SS0=`0x10`, a limit failure selects code`0x10` for software INT and`0x11` for INT1, IRQ or the inherited processor-entry EXT1 profile; the same-stack runtime limit case remains0. Default software-entry reporting retains its segment diagnostic while delivery uses the entry owner's captured selector code.
12. Combine selected new faults with queued IRQ/NMI, TF, STI/SS shadows and a faulting IRET. Prove initial and post-work gate priority, retained-selection precedence, NMI acceptance blocking, early IRET unblock and software-entry handler gates. Source kind and fault class cannot be reconstructed from vector alone.
13. Round-trip pending new #GP/#SS/#UD snapshots, repair memory/tables/numeric state, and resume with allowance0/1. Host context/scalar replacement follows the old contract. Failed imports and busy intake preserve successful nested host operations. Private repair, handler-first-instruction fault loops and shutdown remain independently bounded.
14. Frame/A-bit/handler/source executable aliases, stale asynchronous compilation, eviction and maxTranslations1 handler refusal. The frame commits once, revised bytes execute, all owners/resources remain bounded, and a failed browser compilation is terminal. Cover the same fault from a cold entry, a retained middle entry and a changed execution context.
15. In-domain IDT/GDT/LDT gate/descriptor reads crossing canonical space select the phase-established #GP(0), while an otherwise comparable live TSS-field read retains #TS(selector|EXT). Canonical table bases near the hole and sufficient limits isolate address geometry from limit/type checks. Contrast widened domain overflow retaining its private refusal, and valid LDT selector TI1/index0 rather than treating every index0 as null. NMI entry plus invalid IDT geometry with allowance1 leaves a secondary pending #GP(0), NMI blocking retained and no partial frame; it does not become immediate #DF.

## implementation and verification boundaries

Keep semantic source classification and its tests with x86 decode/access/protection owners; generated failure publication with lowering; representation with embedding; bounded coordination/artifact ownership with host. Follow `agents/architecture.md`, the existing Rust/TypeScript style and shared scenario registration. A representative source contract carries architectural fault data separately from the private diagnostic, for example `#SS(0)` plus its selected SS access; do not prescribe a file tree, a new framework or duplicated layout offsets.

Implementation checkpoints are: inventory/provenance and decode frontiers; checked access consumers and RF/publication phases; source-aware entry escalation; guest repair/IRET loops; independent cross-runtime conformance and measured fast-path preservation. Each checkpoint must include its failing literal packet before the behavior is changed. Do not widen unknown opcode classification, introduce control state or change private partial-progress rules to simplify the implementation.

Run `cargo test --locked`, `npm run typecheck`, `npm run lint`, `npm run build`, `npm test` and `npm run test:browser`; `npm run check` is the complete formatting/lint/native+wasm Clippy/Rust/build/Node/Chrome gate. Spec-only verification is `npx prettier --check specs/index.md specs/architectural-access-and-legality-faults/spec.md`, local-link validation and `git diff --check`; no implementation claim follows from those checks.

Compare identical checked inherited kernels against source `fee1edc` in default report and matched delivery-enabled no-event modes. All142 existing workload names are now baseline-capable, including the16 external cases; the matched mode excludes the sole TF-detection row. Include inactive ordinary code, existing TF/RF/shadow and numeric paths, short resumes, masked IRQ/blocked NMI and already typed exceptions. Characterize new delivered sources, repaired guest retry, REP progress, entry escalation and private refusal separately; old private reporting is not an equivalent delivery baseline. Record translation/compile/instantiation, first/early/later completion, run-call/entry counts, artifact/core/cache bytes and control timings. Use balanced/reversed samples and same-build controls for material differences; preserve short/zero-clock observations and avoid p99/application-throughput claims. No new successful-path per-instruction observer or host callback is allowed. Falsify wrong-vector SS provenance, Invalid→#UD blanket conversion, EXT hard-zero corruption, backing→#PF confusion, RF phase changes, access reorder, frame replay and stale source publication with targeted mutations through public Cpu/generated Wasm; engine/build failures and timeouts alone do not establish the intended semantic kill.
