# processor identity and virtual time: selection and falsification

Prepared against clean implementation `e785914aa60d7bc48359561107508bef7e82c3c2`, after the completed [call-gate delivery](../call-gates-and-privilege-stacks/verification.md). This record covers current-source inspection, architectural references, specification arithmetic and adversarial specification review. It is not executable CPUID/TSC conformance, a mutation-kill report or a performance result. README and implementation files are outside this task.

## selection against current implementation

Three independent agents compared the actual implementation with the earlier thirteen-area research. That research supplies dependency questions rather than a fixed number of remaining specs. One lane initially ranked the remaining x87 special functions first. Its recommendation changed after challenging the numerical oracle and after pinning a concrete identity/time contract; this was not an initial unanimous vote.

| candidate                                                    | current evidence                                                                                                                                                                                                                                                           | decision                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Processor identity and virtual time                          | CPUID/RDTSC have no selected execution path; F9 currently falls into the `0F 01 /7` consumer. Existing instruction retirement, common generated publication, physical/fixed CR4, MSR admission, host capture/reset and fault/event owners supply the necessary boundaries. | Selected, with literal private CPUID disclosure, deterministic retirement time, selected MSRs and TSD delivered together. An all-clear CPUID stub or host-clock passthrough would not qualify.                                                             |
| Remaining x87 special functions                              | The raw80 owner, stack/status and dispatch representation exist. Eight selected D9 transcendental encodings are absent: F0/F1/F2/F3/F9/FB/FE/FF.                                                                                                                           | Valuable next numeric cohort, but argument reduction, approximation/rounding/status and an independent accuracy oracle need a model decision. Free dispatch slots do not resolve these issues. This cohort alone would not certify every x87 feature/form. |
| Hardware task switching                                      | Task descriptors/TR and TSS consumers exist, but far task paths and NT-IRET still refuse.                                                                                                                                                                                  | A separate phased task-image/context/CR3 contract is needed. Intel old/new-task failure boundaries cannot be implemented by copying call-gate atomic preparation/rollback.                                                                                 |
| Extended state / AVX                                         | Legacy/FX state images and SIMD state exist.                                                                                                                                                                                                                               | No XCR0/OSXSAVE component authority or upper-vector state contract. Feature enumeration, controls, masks, images and execution must be designed together; existing FXSAVE is insufficient.                                                                 |
| Retained TLB, parallel atomics and broader platform controls | Private page walks/invalidation dependencies, LOCK operations, events and I/O already have owners.                                                                                                                                                                         | Retained translations, shared ordinary accesses, multi-vCPU ordering, CR8/APIC/PMU and devices need their own authority and coverage. They are not implied by this timebase.                                                                               |

The selected path improves the system vertical while exercising context/registers, decode, retirement, paging controls, faults/events/debug and host ownership. It is large enough to require integration work without making an unsupported complete-CPU claim.

## thirteen-area reconciliation

The [scope map](../index.md#scope) remains a map of selected contracts, not thirteen finished verticals. The following is a prioritization map against this checkout, not a complete ISA census:

| architectural area              | current owner/evidence and effect of this spec                                                                             | remaining boundary relevant to selection                                                                          |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Execution context and registers | Imported modes, raw scalar/numeric banks and physical reset/transitions exist; add an explicit separate time bank.         | A positive family claim still needs a wider state/control audit.                                                  |
| Fetch/decode/legality           | Mode/prefix/length/access faults exist; select CPUID/RDTSC/exact F9 and preserve adjacent frontiers.                       | Unselected ISA/feature forms remain separate.                                                                     |
| Scalar integer and flags        | Existing arithmetic, bits, multiply/divide and system FLAGS supply ordinary retirement controls.                           | This spec makes no whole-family completion claim.                                                                 |
| Addressing and memory           | Private backing, aliases, checked accesses and code invalidation exist. Clock instructions have no operand-data footprint. | Shared/device access authority is separate.                                                                       |
| Control flow and stack          | Near/far calls/returns, events, fast-system and now call gates are implemented.                                            | Task transfer semantics remain missing.                                                                           |
| Repeated/multi-access execution | Memory and I/O repetition retain partial progress independently of retirement.                                             | Time must count final instruction retirement, not elements; no new transaction mechanism is needed.               |
| Segmentation/protection         | GDT/LDT, loaded caches, TR/TSS fields and gates exist.                                                                     | Outgoing/incoming hardware-task images and partial failures remain separate.                                      |
| Paging/permissions/invalidation | PG0, legacy non-PAE/PAE and IA32e plus control/import paths exist.                                                         | TSD is runtime permission, not translation identity. Retained TLB/advanced translation work is separate.          |
| Exceptions/interrupts/delivery  | Fault/trap delivery, IRQ/NMI, HLT, debug and returns exist.                                                                | TSD faults consume these owners; frame construction must not tick. Broader task/debug facilities remain separate. |
| x87/MMX                         | Raw80, core arithmetic, remainder/exponent/BCD, MMX aliases/images and numeric controls exist.                             | Transcendental accuracy is unresolved. No complete MMX-family audit was established during selection.             |
| SIMD/extended state             | Selected SSE/SSE2 integer/numeric forms, MXCSR and FX images exist.                                                        | Full-family certification and XCR0/component/upper-vector state are not inferred.                                 |
| Atomics/memory ordering         | Private LOCK/RMW, fences and hints exist.                                                                                  | No shared-vCPU observer/order promise is added by CPUID serialization or RDTSCP.                                  |
| System/privileged operations    | CR/debug/MSR subsets, transfers, reset, I/O and events exist; add identity/time/TSD coherently.                            | Broader MSRs, PMU, CR8/APIC and platform clocks remain separate.                                                  |

There is no justified numeric estimate of all future specs from this map: family completion, numerical fidelity, task semantics and shared/platform scope can split differently. The actionable next increment is the selected contract, with x87 special functions and task execution remaining strong follow-on candidates.

## resolved counterexamples and decisions

| attempted shortcut / falsifier                                                            | resolution in the specification                                                                                                                                                                                                               |
| ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Advertise a familiar Intel model from broad opcode coverage                               | Fixed vendor `Ring64Engine`, no signature/brand/model promise; only selected TSC/RDTSCP bits are positive. All other leaf words are literal zeros.                                                                                            |
| Feature bits clear means all such instructions must now #UD                               | This is explicitly a private positive-disclosure profile. Existing LFENCE executes while SSE2 is unclaimed, unlike Intel's feature-absence rule. The departure is exposed; inherited admission is not silently replaced by a new global gate. |
| Clear RDTSCP bit27 while executing RDTSCP                                                 | Rejected: the positive RDTSCP/AUX contract and its bit ship together.                                                                                                                                                                         |
| Use normal legacy32 writes for fixed outputs                                              | CPUID and selected timestamp/MSR reads clear the raw upper32 even outside long64. Dirty-upper-bank literals are mandatory.                                                                                                                    |
| Read time from host Date/performance or tick only at a timestamp read                     | Both lose deterministic ordinary/no-clock progress. One bank counts every retired instruction, with literal partition/wrap cases.                                                                                                             |
| Credit canonical remaining when clearing faults                                           | I/O invokes `core_clear_fault` inside generated execution with stale canonical remaining. Use live local retirement and one common normal epilogue, never diagnostic/clear-fault settlement.                                                  |
| WRMSR writes W then ordinary own tick produces W+1                                        | Pin the explicit private write-at-retirement policy: own completion installs exactly W. For the candidate invocation ledger, rebase to `W-(d+1)`; wrap and nonzero-prefix tests distinguish the offset.                                       |
| Count REP elements, event frame construction or waiting HLT as instructions               | Only completed guest retirement ticks. Partial progress and automatic delivery have their own work counters; actual handler instructions tick normally.                                                                                       |
| Admit selected MSRs on linear by moving generic decode                                    | Preserve linear's pre-begin Unsupported frontier; only the existing fixed-paged/physical MSR planes gain the selected indices. Direct reads and host time import still work in linear.                                                        |
| Treat TSC as a syscall pointer or TSD as translation geometry                             | TSC is arbitrary u64, AUX is u32, CR4 remains the sole TSD bank. TSD changes do not flush/rekey artifacts or reload PAE PDPTEs.                                                                                                               |
| Both selected MSR privilege and value faults use phase `target`                           | Two independent reviewers found the existing global CPL guard uses `privilege`, while semantic value failure uses `target`. The spec and acceptance packets preserve that distinction.                                                        |
| Assume repeated F2/F3 are rejected by the prefix parser                                   | Current parser collapses them to its last repeat value. Explicitly inherit and ignore that value for these three operand-free instructions; pin repeated/mixed repeat literals separately from LOCK combinations.                             |
| Rejected setter capture restores all state even after an accessor runs/reset/disposes CPU | Impossible rollback claim removed. Strict capture generation rejects the setter's publication; accessor effects persist. TSC100 plus one accessor NOP leaves101, reset leaves0, disposal remains disposed.                                    |
| Every bank setter may accept a run completed during capture                               | Use the existing strict capture path, not the `allowCompletedRun` exception. A stale time import could otherwise erase real retired progress.                                                                                                 |
| New clock forms have a predecessor throughput baseline                                    | The predecessor refuses them. Characterize new forms; compare inherited controls with frozen inputs/artifacts, reverse/A-A controls and raw timer limits. Common-exit overhead and generated byte growth must be measured.                    |

## source and claim boundary

The accounting candidate is grounded in the actual five-argument [generated execution call](../../host/core.ts), [live remaining initialization/publication](../../src/dbt/wasm/state.rs) and sole normal [unit epilogue](../../src/dbt/wasm/mod.rs). [I/O preparation](../../src/embedding/exports/io.rs) supplies the mid-unit clear-fault counterexample. [Control validation/translation comparison](../../src/x86/paging/controls.rs), [privileged bridge](../../src/embedding/exports/paging.rs), [prefix parser](../../src/x86/decode/prefix.rs) and [CPU capture/lifecycle](../../host/cpu.ts) were inspected rather than inferred from older specs. Those observations establish feasibility and required touch points, not generated-runtime correctness.

Intel SDM093 supplies CPUID fixed-register behavior, RDTSC/RDTSCP privilege/ordering, WRMSR source/reserved fields, and TSC/AUX definitions. Cross-reading Vol3B §20.17 and Vol4 distinguishes full64 counter writes from historical low32-only models and identifies AUX's reserved high32. The immutable disclosure table, all-zero unknown queries, retirement timebase, halted-time policy and write-at-retirement rule are Ring64 choices, not native timing guarantees. [Primary links](spec.md#primary-sources) point to the official collection.

Final written-contract review used three independent lanes: architectural profile/decode/priority; retirement/MSR/control/lifecycle; and oracle/mutation/performance/claim coverage. Each rechecked the corrected contract and reported no remaining blocker. Besides the resolved phase/prefix/capture contradictions, review added original-budget width tests, explicit live helper arguments/shared rebasing and long64-only REX retirement controls. This is a specification-readiness verdict, not an implementation approval or runtime result.

It checks vendor/feature words, u64 halves, the 102/104/final105 example, wrap, write-at-retirement, no-retirement events and original budgets above 32/63-bit boundaries.
