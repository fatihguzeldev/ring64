# port I/O and string I/O

Status: implementation-ready specification; implementation not started. Baseline: `4df41a0814beaceb0681dc013f5eac094cdc6660`. Order: 5 of the next five specs.

## objective and supported profile

Execute scalar IN/OUT and bare/REP INS/OUTS against an optional synchronous embedding provider. A complete path includes permission admission, one external transaction, architectural publication, bounded repeated progress, guest fault delivery/repair and continuation without replaying completed work.

The option is available to all three memory models: existing `linear`, existing `ia32e-paged`, and `physical` from [legacy paging](../legacy-paging-and-permissions/spec.md) and [reset/transitions](../reset-and-mode-transitions/spec.md). Cover every admitted execution mode, including real/unreal contexts, protected16/32, virtual8086, compatibility and Long64. Permissions derive PE/VM/CPL from execution context and IOPL from live FLAGS; no paging-control bank is required on linear CPUs. Numeric enable controls do not gate I/O.

No MMIO, devices, DMA, APIC/PIC, asynchronous callbacks, active-run interrupt intake, shared vCPUs, I/O breakpoints, virtualization exits, transaction journal or bus timing. CR0.AM remains zero in admitted physical profiles; general alignment checking is not added. Unaligned ports still produce one full-width callback. Ordinary operand access rules remain inherited. Finite guest allowances do not preempt a blocking synchronous provider or bound callback latency.

## embedding contract and failure boundary

The optional CPU-construction property is:

```ts
type IoWidth = 8 | 16 | 32;
interface IoProvider {
  read(port: number, width: IoWidth): number;
  write(port: number, width: IoWidth, value: number): void;
}
```

Absent `io` means no provider; present `undefined` rejects. Require a non-null, non-array object. Capture the option, `read` and `write` exactly once before construction compilation awaits; validate both methods as callable. Pass an internal owned binding through construction instead of recapturing public getters in Core. Keep the original object as `this`. Method replacement cannot change the binding; mutable queue/device state through the receiver is allowed. Reentrant getters follow existing input-capture/lifecycle checks. Construction failures drop references without invoking provider effects or hooks.

Ports are unsigned16, widths are literal bit widths, and values are unsigned integers fitting that width. Validate read results in JavaScript **before Wasm i32 coercion**: primitive number, finite, integral and within `[0, 2^width-1]`. Dword `89abcdef` means positive `2309737967`, without rejection or unintended sign extension. Normalize signed i32 transport to unsigned before a write callback, then apply the selected width. Writes must return exactly `undefined`.

Objects, Promises, thenables and malformed primitives are invalid results. Do not read `.then`, coerce objects, inspect prototypes or await results. One accepted element makes one full-width callback, never several byte calls. The provider is not a RAM backing and receives no guest pointer or mutable Core view.

The same CPU remains running during callbacks. Its run/state/context/memory/inspection/interrupt/reset/dispose methods retain running rejection; provider replacement is not an API. A caught rejection does not poison the outer transaction: a provider may catch a synchronous state-access error, or handle the Promise rejection from nested `run()`, and return a valid value. An uncaught exception, invalid result or bridge invariant failure rejects the outer run through its existing terminal `failed` lifecycle. There is no guest fault, resumable `RunResult`, usable post-failure checkpoint or automatic retry. External effects may already have occurred. Later run/state/reset rejects; `dispose` releases host references while preserving the existing rule that failed cleanup does **not** reenter the unwound native Core. Another CPU is independent.

Recovery requires a new CPU, a checkpoint captured before failure, and embedder reconciliation of external effects. CPU state serializes no provider, queue, device snapshot or deduplication ID. Continuing committed progress with matching external state does not replay it. Restoring an older checkpoint can repeat I/O; no cross-checkpoint exactly-once guarantee is claimed. Reset preserves the captured binding and current external state, invokes no provider reset/dispose hooks, and rejects during callbacks.

## instruction forms and decode frontier

| operation | byte          | word/dword    | port                        |
| --------- | ------------- | ------------- | --------------------------- |
| IN        | `E4 ib`, `EC` | `E5 ib`, `ED` | immediate8, DX respectively |
| OUT       | `E6 ib`, `EE` | `E7 ib`, `EF` | immediate8, DX respectively |
| INS       | `6C`          | `6D`          | DX                          |
| OUTS      | `6E`          | `6F`          | DX                          |

Immediate ports are zero-extended8; DX always means RDX's low16. There is no ModRM. Wide forms use CS.D and `66` outside Long64, including unreal CS.D=1. Long64 defaults to dword, `66` selects word, and REX.W is ignored **before** selection: `48 ED` is dword; `66 48 ED` is word. Byte forms ignore `66`. REX extension bits never select a different implicit accumulator, port, index or count register; REX is a prefix only in Long64. No 64-bit I/O form exists.

AL/AX inputs preserve all other raw RAX bits. EAX input clears upper32 in Long64 and preserves raw upper32 in non-long modes, following inherited register views. OUT captures only the selected accumulator bits. Arithmetic flags remain unchanged; ordinary RF clearing, TF/debug and event boundaries still apply.

F3 admits REP INS/OUTS. F2 strings and F2/F3 scalar I/O remain engine `unsupported`; inherited last-repeat-prefix selection and conflicting-prefix frontiers stay unchanged. A sole LOCK selects architectural #UD, with required-byte fetching for an otherwise admitted form first. `F0 E4` ending at the final executable byte faults fetching its missing immediate; complete `F0 E4 80` selects #UD without operand/provider work. Unsupported repeat combinations stop at their inherited recognition frontier without unrelated tails. Enforce the 15-byte ceiling before byte16. Segment/address prefixes do not change scalar port selection.

INS writes ES:(E)DI/RDI and ignores segment overrides. OUTS reads DS:(E)SI/RSI with the selected override; FS/GS bases apply in Long64. Address size selects indices and REP count independently of operand width and SS.B. DF adds/subtracts the whole element width, wrapping the resulting index at its selected width. Individual element bytes use a checked full span, without wrapping at an index boundary. INS changes only DI; OUTS only SI; bare forms never change count.

## live permission algorithm

Apply this to scalar execution and every attempted string element, using live CPL/VM/IOPL after preceding guest FLAGS/control/return operations. Do not specialize on stale canonical FLAGS or read TSS memory during discovery.

1. Real mode bypasses the bitmap. Protected/compatibility/Long64 bypass when CPL<=IOPL. Virtual8086 requires the bitmap even with IOPL3. A bypass performs **zero TSS reads or TR validation**.
2. Otherwise require a non-null GDT loaded TR cache, present system busy32/64 TSS (type11). Invalid, malformed or busy16/type3 caches select #GP(0), not event-entry #TS/#NP. Do not reload GDT. Require cached limit>=`67` before reading the live u16 I/O-map base at TSS offset`66`.
3. The u16 map base must be strictly less than the cached inclusive TSS limit. There is no invented minimum`68`, full-map requirement or blanket maximum`dfff`: short maps are allowed. Compute `offset=mapBase+(port>>3)` with widened arithmetic; require `offset+1<=limit` before permission-memory access. Offsets never wrap to16 bits.
4. Read exactly two bytes at that offset, even for byte I/O, and complete the word access before testing bits. Test `((1<<(width/8))-1)<<(port&7)` in the little-endian word. Any selected one bit selects #GP(0); unselected bits are irrelevant. Read both the map-base field and permission word again per attempted element. There is no positive permission cache across REP. Neither nominal u16 field may be widened to an unrelated8-byte read.
5. After permission succeeds, a port span extending beyond`ffff` selects engine `unsupported` before provider/operand effects, never wraps to port0. Intel leaves beyond-space behavior implementation-specific; this is the bounded profile. Bitmap denial may precede this frontier. Check provider presence at this reached admission boundary; absence selects `unsupported` before operand geometry/access. Both private refusals have no external effect.

The full-map terminal all-ones byte is a software format requirement, not a request to scan the map or read its terminal byte on unrelated accesses. For base`80`, limit`2080`, last permission byte at`207f`=`00` and terminal`2080`=`ff`, port`ffff` byte I/O passes mask`0080`; word I/O fails mask`0180`. Dword at`fffd` fails mask`01e0`. Limit`207f` instead refuses even that byte request before permission reading because its mandatory second byte is outside the limit. Clearing the terminal may pass the mask, but beyond-space requests still hit the private frontier.

TSS reads are supervisor implicit accesses through the current memory-family owner, with existing `table: tss`, `systemPhase: tss-read`, loaded-TR selector provenance and width2 diagnostics. CPL3 does not make these user page accesses. Preserve inherited #PF/CR2, private physical/page-table/final-access diagnostics and partial paging A/D effects. A missing map-field page at linear`10066` produces supervisor nonpresent read #PF error`00`, not`04`.

Bounds, type, denying bits and a noncanonical IA32e TSS field/word span select existing `protection-fault`, vector13/error0, phase`privilege`, without fabricated faulting-selector data. This explicitly chooses #GP(0) for unusual imported cache addresses; do not reuse an event system-read helper that emits #TS(selector). Widened u64 overflow retains private address-range refusal. Legacy formed starts retain the memory owner's32-bit projection and nonwrapping field span. No new reason/vector registry entry or generic SIMD fault cause is needed. Implicit TSS reads remain outside operand-data-watchpoint observation.

## external effect, operand and progress order

Entry budget0/stop prevents instruction work. Execute breakpoints precede fetching/count processing. After decode, zero-count REP completes once without permission/provider/operand checks or index/count bank writes, even with repeatBudget0. Positive count with repeatBudget0 returns `repeat-budget` before instruction-begin RF clearing or TSS/provider access. Otherwise begin normally, including RF clearing, then execute:

| form | ordered work after begin                                                                                                                                                                  |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| IN   | permission/private admission; one provider read; publish selected accumulator; retire                                                                                                     |
| OUT  | permission/private admission; capture selected accumulator; one provider write; retire                                                                                                    |
| OUTS | permission/private admission; full source segment/canonical/memory read; one provider write; publish index/count progress                                                                 |
| INS  | permission/private admission; destination segment/canonical admission; one provider read; destination paging/private-memory preparation and full-span write; publish index/count progress |

INS selects Intel's permitted consumed-read-before-faulting-write behavior. Destination #PF/private refusal may consume input without storing the failed element. Its DI/count and completed-repeat accounting remain unchanged. Repair/retry consume a **new** input; retain no synthetic architectural input latch. Segment/canonical rejection is earlier and consumes nothing. OUTS emits nothing on a failed source read. Both use full-span checked element publication without half a failed write. Permission/operand walks may still publish inherited A/D effects.

Discharge compilation, artifact admission and private execution-capacity work before callbacks. After a callback, do not await compilation, yield a private resource quota or restart an operand walk because a dependency changed before publishing the element or its actual fault. Use synchronous walks/prepared publication; source-change discovery may mark owners stale but cannot replay transactions. Fatal internal/allocation failure poisons the CPU rather than manufacturing a resumable uncertain transaction.

A successful REP element publishes its effect, relevant index, decremented count and one repeat iteration/allowance consumption together. Bare INS/OUTS perform one element, retire once, preserve count and consume **zero** repeat iterations/allowance, including with repeatBudget0. Failed INS consumption is an external attempt, not a completed repeat iteration. Nonzero u64 counts remain bounded by supplied completed-work allowance. Fault-delivery and instruction budgets bound handler/retry loops separately.

REP retires once when complete; partial progress leaves RIP on the instruction. For unfinished code-writing INS, commit bookkeeping and refetch/redecode at that RIP before another element, including dormant writable aliases and executable PTE edits. Preserve inherited suspension priority: exhausted repeat allowance returns `repeat-budget` before source-invalidation redispatch; the next run refetches the changed form. With remaining allowance, invalidate/redispatch before continuing. New bytes may be a bare string or unrelated instruction. Final/bare instructions retire before invalidation dispatch; exhausted instruction budget/stop precedes successor fetch. There is no latched REP form. A later quota may refuse the **next** form after the preceding element is fully published.

Use inherited element-boundary TF, debug, inhibition and eligible queued IRQ/NMI arbitration. OUTS contributes its actual operand read; INS contributes a committed destination write, not a late failed write or provider activity. TSS traffic produces no operand watchpoint. Callbacks cannot admit active-run IRQ/NMI requests. Pending/accepted events and IRET preserve prior progress; completed transactions do not replay on ordinary continuation or handler return.

## integration and ownership

Current [decoder](../../src/x86/decode/opcode.rs), [instruction model](../../src/x86/instruction.rs) and [string emitter](../../src/dbt/wasm/strings.rs) cover memory strings only. Update every new-form consumer: decode, validation, width/address views, emitter dispatch, repeat locals/accounting, instruction-begin/RF work gate, index/count branches, store/source-change status, debug/event publication and probe/discovery classification. INS is a store for source ownership; neither form falls through accumulator-writing memory-string code. Preserve the five-argument generated entry ABI and authoritative progress/state layouts.

Rust owns permission/register/operand/progress semantics; TypeScript owns capture, synchronous adaptation and terminal lifecycle. The selected bridge uses two fixed Core-Wasm host read/write imports and per-CPU immutable provider presence. Core currently instantiates import-free; account for that fixed import cost. Generated non-I/O units acquire no I/O-specific import, body helper or per-instruction provider poll. I/O lowering reaches the architectural helper and one full-width effect. Release Rust bridge/state borrows before user JavaScript; do not rely on unwinding RefCell borrows after imported exceptions.

Arm the host adapter only during actual synchronous native execution and a reached I/O effect phase. Lifecycle `running` alone is insufficient: run also awaits compilation and instantiates artifacts. Construction, discovery, Core probe, compilation, generated start/instantiation and administrative calls cannot invoke user methods. Premature imports reject before touching providers. Clear per-CPU effect/execution scopes in `finally`, including exceptions; another CPU has independent scopes. The cold probe never executes control/I/O instructions to outrun translation quotas. A cold quota may refuse an uncompiled I/O instruction before permission execution; reached permission failures still precede operand/provider effects.
