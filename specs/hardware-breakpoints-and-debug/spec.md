# hardware breakpoints and debug

## purpose and selection

Close guest breakpoint installation → execution/data/general-detect #DB → handler inspection/repair → IRET → continued execution in the existing imported execution profiles. Cover instruction breakpoints and operand-data watchpoints across the currently implemented instruction families, including REP and stack-load inhibition. This is a complete debug execution vertical within the memory-observation profile below; it does not claim complete x86 debug coverage.

Implementation through `319bda2` supplies selected #UD/#GP/#SS sources, checked operands, TF/RF boundaries, SS/STI inhibition, processor/external delivery, pending checkpoints and handler returns. Hardware debug now has concrete consumers for each. Current `DebugException` is only a single-step trap, pending vector1 carries no fault/trap source, and the boundary profile observes only TF/RF/shadow. A DR register bank alone would close none of the new behavior.

Paging is the strongest alternative and remains next in foundation value, including without an OS-boot goal. Its smallest useful vertical needs physical backing separate from current linear mappings, coherent CR0/CR3/CR4/EFER authority, page walks/A/D effects, #PF/CR2 and root/invalidation/code-dependency lifetime together. Fast system transfers likewise need their MSR and enable-state authority; remaining x87 special functions are a separate numeric expansion. Do not insert standalone control-register or CPUID storage as a substitute for either vertical.

The [architectural access](../architectural-access-and-legality-faults/spec.md), [instruction boundary](../system-flags-and-instruction-boundaries/spec.md), [event delivery](../event-delivery-and-returns/spec.md), [external interrupt](../external-interrupts-and-halt/spec.md), [software event/return](../software-events-and-iret/spec.md) and [private memory/code validity](../memory-map-and-code-validity/spec.md) contracts remain the foundation. New #DB sources use the existing opt-in delivery options and shared attempt allowance.

## register and feature profile

Implement DR0–DR3, DR6 and DR7 as CPU-owned architectural state. Select a fixed CR4.DE=1 profile; no writable CR4 is introduced here. DR4/DR5 accesses select #UD. DR7 R/W=10 therefore selects an I/O comparator, which has no producer until port I/O is implemented; it must not match ordinary memory. Preserve local/global enable fields and treat either as enabling a slot. Task-switch clearing of local enables, BT generation, I/O producers, debug MSRs, branch tracing/BTF, RTM, bus-lock detection, ICEBP reinterpretation and virtualization are outside this increment. Existing INT1 software-entry semantics remain intact.

Fresh construction uses four zero addresses, DR6=`0xffff0ff0` and DR7=`0x400`. DR0–DR3 hold raw unsigned64 values, including noncanonical ones; writing such a value alone is not #GP. Comparisons use valid generated linear addresses. Non-long guest transfers use 32 bits; writes zero-extend into DRn, while GPR writes retain the existing mode's register-view policy. Long64 transfers use64 bits. Select modern 8-byte data-breakpoint support in every imported mode, alongside lengths1/2/4.

Pin the following deterministic register profile. Host bank imports accept unsigned32 DR6/DR7 and normalize them like guest low32 writes. Guest long64 writes of nonzero upper32 to DR6/DR7 select #GP(0), without publishing the write. Unsupported/reserved low fields are not an excuse to invent #GP:

- DR6 readback is `(low32 & 0xe00f) | 0xffff0ff0`: B0–B3/BD/BS/BT are software-writable; unsupported BLD/RTM remain1, bit12 remains0 and upper32 reads0.
- DR7 readback is `(low32 & 0xffff23ff) | 0x400`: retain enables, LE/GE, GD and comparator fields; LE/GE have no matching effect. Unsupported RTM and reserved low fields read0 except fixed bit10.
- On a selected processor #DB, B0–B3 become exactly the slots enabled when their participating accesses matched, including captured SS-deferred hits; disabled-at-match slots are not reported. Do not filter historical hits using the current DR7. BD/BS/BT remain latched except software writes, with BD/BS ORed for their current causes; no source generates BT here. This pins behavior where hardware permits variation. A DR6 read alone is not a current-cause record.
- An execute slot with LEN!=00 or an unaligned data range is retained in register readback but does not match in this profile. Invalid/noncanonical/out-of-domain comparator spans likewise do not match. These are explicit bounded choices, not new architectural faults or claims about undefined hardware configurations.

Both MOV DR directions (`0F 21 /r`, `0F 23 /r`) are required. ModR/M.mod is ignored: these encodings name a GPR even when the bits resemble memory addressing, and consume no SIB/displacement. Ignore66 and REX.W; REX.B extends the GPR in long64, while effective REX.R and LOCK select #UD. Preserve existing unsupported duplicate/mixed-prefix frontiers and required-byte priority. Real mode permits the transfer; other admitted modes require CPL0, with virtual8086 selecting #GP(0). Pin legality/#UD before privilege/#GP before GD for this private profile. MOV DR arithmetic flags are architecturally undefined; choose preservation of their concrete incoming values, while keeping normal RF/boundary effects.

## public state and captured sources

Add idle `readDebugState()` and `setDebugState(state)` beside the existing numeric projections. Do not serialize six debug registers into every ordinary run snapshot:

```ts
interface DebugState {
  addresses: bigint[]; // exactly four unsigned64 entries: DR0 through DR3
  dr6: bigint; // unsigned32 input, normalized readback
  dr7: bigint; // unsigned32 input, normalized readback
}
```

The setter replaces the complete captured bank atomically. Reject wrong lengths/types/ranges, missing or explicit undefined fields and busy/failed/disposed calls using the existing lifecycle conventions; host errors are not guest exceptions. Capture caller-owned values once, then validate against the live CPU generation after getters, preserving successful nested operations on an outer rejection. Readbacks are detached. `setState` and `setContext` preserve the bank; host/guest bank changes affect future comparisons, not already captured causes. Memory/numeric repairs preserve it. Reconfiguration invalidates or revalidates existing artifact assumptions through their owner and neither synthesizes nor consumes an event.

Extend the scalar checkpoint additively with optional `debugContinuation: { breakpoints: number; originPc: bigint }`. It exists only for nonzero SS-deferred data hits: a four-bit mask, the oldest contributing instruction's logical PC, the current ready boundary and retained SS inhibition. Omission in `setState` clears it; active readbacks include it, inactive readbacks omit it. Validate the entire scalar/event/interrupt/continuation image atomically, including unsigned64 origin PC, mask1..15, ready event and `interruptibility.ss=true`. A supplied continuation binds to the incoming scalar RIP; `originPc` is historical diagnostic information, so no byte decoding or exact origin/successor-distance validation is performed. Explicit undefined/null rejects rather than selecting omission. Do not validate historical hits against current DR7 enables/addresses or current DR6. Reject malformed or inconsistent imports without partial publication. A bank setter preserves historical hits; a context replacement clears the continuation along with its existing shadow/event cancellation. A complete checkpoint restores context, then debug/numeric banks, then scalar state and memory under the predecessor's lifetime rules.

Ordinary current-instruction or failed-REP-element candidates are transient and discarded at private exits; they do not require a public continuation. Only already committed SS-inhibited work is latched. In particular, no SS-false unfinished-instruction record may accidentally follow a newly accepted NMI into its handler.

Extend `DebugException` into producer-owned variants: retain the exact existing single-step trap fields for TF-only reports; new instruction sources identify fault/trap class, execute/data/general-detect/combined cause, current slot mask and whether BS participates. Keep instruction PC, actual resume PC, completion and saved FLAGS explicit. Combined TF/data causes produce one #DB, with both cause sets, rather than competing deliveries. Sticky DR6 bits are not a substitute for that current-source record.

Use an optional `ExceptionEvent.debug` discriminant for the new selected sources; ordinary TF-only snapshots keep their old shape:

```ts
type DebugSource =
  | { class: 'fault'; cause: 'execution-breakpoint'; breakpoints: number }
  | { class: 'fault'; cause: 'general-detect' }
  | {
      class: 'trap';
      cause: 'data-breakpoint';
      breakpoints: number;
      singleStep: boolean;
      instructionCompleted: boolean;
      deferredOriginPc?: bigint;
    };
```

Slot masks are integer1..15. General-detect carries BD, not a slot mask; trap `singleStep` carries BS and may combine with the nonzero data mask. Optional deferred origin is an unsigned64 diagnostic, not a second return PC. New report variants consume this same architectural source contract rather than duplicating classification.

Pending vector1 must capture this source information, including class and current slot/BS/BD causes, through raw state, detached snapshots and imports. Old vector1 snapshots without new source metadata retain their inherited single-step-trap interpretation. `debug` is accepted only on vector1 with no error code. Validate fault source/return PC equality, nonzero slot masks where required and primitive booleans; reject incompatible fields across variants. New execute checkpoints require SS=false and live/saved RF0. GD requires live RF0/saved RF1 and may retain the incoming shadow. For completed data traps the saved image equals architectural live FLAGS; unfinished data/TF traps require saved RF1, live RF0 and `returnPc == instructionPc`. Validate captured structure without decoding current bytes or reconstructing instruction history, since code may already have been repaired. A selected data trap cannot retain SS inhibition except the inherited delivery-enabled, combined-TF unfinished-REP case (`singleStep=true`, `instructionCompleted=false`); that case consumes the continuation but retains SS until handler entry. This describes the captured selection path, not the current delivery option: the frozen record must import while delivery is disabled, survive an omitted-option `pending-exception` result, and resume when delivery is enabled later. Report-mode trap selection clears both shadows, while delivery-mode selection retains predecessor inhibition until its established completion/entry boundary. Preserve old metadata-free TF validation. Equal source and return PCs do not imply a fault, since unfinished REP traps and completed self-transfers can have equal PCs. Keep frozen source identity independent of later DR6/DR7 repair. Do not infer class from vector1, DR6, a diagnostic string or instruction bytes in TypeScript.

## detection, publication and ordering

The x86 debug owner decides comparison, cause aggregation, DR6 effects and saved-image policy. Decode owns MOV DR legality; instruction/access owners identify participating memory operations and their commit point. Embedding transports those decisions. TypeScript coordinates bounded execution and delivery without reimplementing x86 comparisons. Use bounded masks and existing operation boundaries, not an access log, general observer API or another memory/cache authority.

| source             | selected boundary                                                                              | retirement and saved image                                                                |
| ------------------ | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| execute breakpoint | actual first byte/prefix of the reached instruction, before fetch/decode and instruction begin | fault; retire0; source/resume PC equal; preserve live and saved RF rather than forcing1   |
| GD                 | admitted MOV DR before its register transfer                                                   | fault; retire0; BD set; normal begin clears live RF; saved RF1                            |
| data breakpoint    | successful current instruction or committed REP element                                        | trap; committed results remain; continuation/REP PC and saved RF follow actual completion |
| TF                 | inherited sampled-TF completion boundary                                                       | trap; BS set, preserving existing TF-only behavior and REP flags                          |

Publish DR6 current-source effects when the debug exception is selected, including report mode and entry-allowance0. Do not publish a tentative operand match early. For this private entry profile, clear GD atomically on successful processor #DB handler admission for every cause, including TF/execute/data; report, allowance0 and failed private entry admission retain GD. This is separate from source-status publication. Existing INT1 enters its software handler and clears GD on successful vector1 entry, without fabricating BD/BS or hardware slot hits. Other vector1 IRQ injection retains external source kind and does not become a processor #DB.

At a fresh admitted instruction boundary preserve completed/retained #DB trap → eligible NMI → IRQ → execute #DB → required fetch/decode → execution ordering. Initial instruction-budget0/stop prevents new work. A positive instruction allowance permits an execute fault before remaining source/artifact/translation quota or REP element allowance can hide it; zero count does not remove an instruction breakpoint. A suppressed execute check must not acquire required bytes merely to compare. Discovery of future instructions is pure and cannot publish DR6 or pending sources.

An execute comparator uses CS-derived linear first-byte identity, not logical RIP alone, a backing offset, or every byte fetched for a multi-byte instruction. Preserve segment-base/address-domain rules without using a fetch that prematurely applies a lower-priority CS-limit or backing refusal. An invalid generated linear point cannot match solely because DRn contains the same raw invalid value. Cold probe paths, cached entry, retained middle entry and native intra-unit control flow must agree. A generated-only begin check misses a cold source; mutating detection in the current `prepareEntry`/clear-fault call would run before the host's initial gates and is also wrong.

RF suppresses execution breakpoints only; it does not suppress data matches or GD. Execute #DB leaves RF unchanged. GD and other fault sources use their selected RF1 saved images. Normal begin clears live RF after the established pre-begin checks. Pending waiting-x87 and CS-limit behavior remains ordered, with execute #DB taking its documented higher priority at a valid point. Handler repair of the saved RF image followed by IRETD/IRETQ must let the faulting instruction run once without silently disabling its comparator.

Synchronous instruction faults beat tentative current data traps and TF completion; failed scalar/RMW/numeric destinations do not become successful watchpoint accesses. Successful data traps publish the full instruction's GPR/FLAGS/numeric/context/memory effects before reporting/staging, including code-alias invalidation. A trap from a context-changing transfer uses the actual destination context/return boundary. Do not replay a completed transfer, store or frame after private handler refusal or handler compilation failure.

## operand-data observation and private frontiers

Compare the actual translated linear bytes and access kind of admitted instruction operands against enabled data slots. Overlap of any participating byte is sufficient; OR all matching slots into one current mask. Preserve logical addressing, FS/GS and effective segment rules before matching. Equal backing bytes exposed at different linear addresses do not share a breakpoint; segment aliases producing the same linear address do.

Inventory every existing guest-access consumer during implementation, with literal tests or an explicit profile exclusion beside its owner. This scope includes:

- scalar loads/stores, conditional reads, memory ALU/bit operations and pair/LOCK/RMW operations; false CMOV still reads; successful failed-compare CMPXCHG identity writebacks and zero-count memory-shift writebacks still count as writes, and bit-string register indices use the adjusted operand address;
- explicit control-pointer operands, PUSH/POP, near/far CALL/RET, LEAVE and IRET stack operands, including a POP SS read and POP-to-memory's post-pop destination address; descriptor metadata used by those operations is distinct;
- string source/destination/comparison accesses, with a per-element combined mask and no data access at zero count or private zero element allowance;
- SIMD/MMX/x87 memory operands, non-temporal stores and the defined selected fields of legacy/FX state images; scratch Wasm V128 reads are not another guest access;
- MASKMOV selected byte writes only, retaining its full nominal geometry and permission admission even at zero mask. Choose normal execute-breakpoint handling and no data hit for a successful all-zero mask, acknowledging the instruction reference permits breakpoint variation;
- explicit descriptor-instruction operands such as SGDT/SIDT destinations and MOV/LTR/LAR memory selector operands; their subsequent system-table traffic is separate.

This increment explicitly excludes data-breakpoint sampling of GDT/LDT/IDT/IVT/TSS metadata reads, accessed/busy-bit updates and software/automatic event-entry frame writes. It also excludes host inspection/repair, translation/code-validation fetches, PREFETCH/LEA and cache-maintenance-only CLFLUSH from the data footprint. All inherited checks, faults, writes and alias invalidation for these operations still occur. These exclusions define a bounded Ring64 observation profile, not an assertion that real hardware never observes implicit system accesses. IRET and ordinary control-stack operands are included despite being implicit. System-access/debug-entry behavior remains visible remaining scope alongside task/I/O/trace debug.

Missing backing, private permissions, widened domain/refusal, resource limits and engine failures remain private. Neither a private admission probe nor a failed operand produces Bn/#DB. Accumulate successful subaccess candidates until the instruction/element commits; on private failure discard that uncompleted candidate and preserve the owner's existing effects/restart policy. Do not impose a new transaction over multi-access instructions. Successful prior REP elements and earlier SS-deferred hits remain committed history, independently of a failing current element. Add no speculative memory reads or writes to obtain a preferred debug result.

## REP and SS-deferred debug

Without incoming SS inhibition, stop after the first committed REP element that matches, merging its source/destination slots and sampled TF into one trap. If the instruction remains unfinished, retire0 and resume at the REP PC with remaining count/indices, completed memory effects and the inherited RF1/comparison-trap flags. If that element finishes REP, retire1 and resume at the successor. Private repeat allowance, TF and debug allowances remain independent; a selected trap beats post-work budget/stop gates. Failed elements consume no repeat work and publish no current data cause.

Keep the inherited full-instruction SS interval across data-only unfinished REP/private yields. MOV/POP SS operand hits and matching committed elements under that interval accumulate in `debugContinuation`, without publishing DR6/Bn or a selected data-only event yet. Preserve the predecessor's eligible TF trap after a committed unfinished REP element even with incoming SS. At that TF boundary consume/merge any deferred and current data mask into the same partial trap: retire0, use that element's comparison flags and RF1 saved image, remove `debugContinuation`, and apply the predecessor's report-versus-delivery shadow policy. Data-only private suspension must not suppress that TF boundary or invent an extra trap. LSS retains its inherited distinct inhibition behavior; it must not acquire MOV/POP SS suppression accidentally. Execute breakpoints at the inhibited successor are suppressed; STI inhibits IRQ but not execute/data/TF debug.

At successful successor completion, or the eligible partial-TF boundary above, consume the deferred mask exactly once, merge current data/TF causes and select the trap at its actual continuation. Do not reconstruct it from current memory, bank enables or DR6. Source diagnostics retain the oldest contributing origin PC separately from the successor's reporting boundary; the handler frame uses the current context and resume PC. An instruction that changes DR7 before this completion does not cancel historical matches.

A recognized architectural successor fault discards the unselected SS-deferred cause before reporting/staging that fault, in both report and delivery modes. This is the selected private report/admission boundary for the new continuation; private backing/fetch/resource/unsupported frontiers retain it for repair. A successful INT n/INT3/taken INTO successor preserves the deferred cause through its software-entry transaction and selects #DB after the software handler transition, before that instruction's post-completion gates; captured CS/CPL/FLAGS must be those of the new boundary. A failed software entry follows its actual architectural-fault versus private-refusal classification. Successful INT1 entry instead cancels the old deferred cause without publishing its Bn/BS. A private refusal while entering INT1 retains the continuation for repair, just like another private software-entry refusal; an architectural entry failure discards it before reporting/staging that fault. Selected causes, deferred causes and external queues must never be treated as interchangeable pending state.

## artifact ownership and bounded delivery

Extend the existing boundary-activity/artifact authority for active execute/data comparators and an SS-deferred continuation. GD alone does not require observing unrelated instructions. A successful guest MOV DR control write must end/revalidate the current unit before the next affected instruction, including a middle-entry successor; host bank changes do the same through idle admission. Already selected sources are not canceled by such changes.

Do not bake mutable DR addresses/enables into reusable artifacts without owner invalidation. Use the existing translation/cache owner and finite activity assumptions, including pending asynchronous compilation checks. Debug-disabled ordinary modules must preserve their successful-path generated bytes, helper imports/call counts, five-argument invocation and absence of per-instruction polling. Binding an active path through existing checked operand helpers or specialization is an implementation choice; no all-access host callback, new observer API, competing translation cache or unbounded per-bank cache is justified. TF-only DR6.BS publication is an intentional new architectural effect, not a reason to instrument otherwise inactive code.

Layout changes for the bank/source/continuation use the authoritative descriptor and atomic validation; append required transport fields while preserving existing generated offsets and numeric field meanings. Do not hand-copy offsets or silently truncate fields across Rust/TypeScript. The existing `eventDelivery`/`exceptionDelivery` options, pending omission behavior, IRQ/NMI arbitration, HLT activity refresh and shared automatic attempt budget remain. New fault-class #DB is benign for secondary contributory entry failure, like existing trap #DB; vector alone does not identify its class or an external IRQ1. Failed private entry preserves a selected debug event and its source effects. Secondary escalation uses the original accepted boundary, without replay or a fabricated guest instruction. Replacement by #GP/#SS/#DF drops the old `debug` discriminant; never copy vector1-only metadata through a generic `..self` escalation. A deferred-data trap after HLT clears halted activity through the same source-publication owner as TF before post-work gates or queued-event arbitration; an execute fault before HLT never writes halted activity.

## implementation and verification boundaries

Keep architectural debug state, comparisons and source policies with x86 owners; instruction-specific footprint/publication with its instruction/access owner; wire layout with embedding; bounded dispatch and artifact lifecycle with host. Follow `agents/architecture.md` and existing Rust/TypeScript style without prescribing a new file tree or general tracing framework. Implementation checkpoints are register/decode and source contracts; actual execute admission; operand matching/publication across every consumer; REP/SS/checkpoint lifetimes; guest handler repair; independent correctness/boundary/performance falsification. Each behavior starts with a failing literal packet before the implementation changes.

Spec-only checks are `npx prettier --check specs/index.md specs/hardware-breakpoints-and-debug/spec.md`, local-link validation and `git diff --check`. Implementation verification runs `cargo test --locked`, `npm run typecheck`, `npm run lint`, `npm run build`, `npm test` and `npm run test:browser`; `npm run check` is the complete format/lint/native+wasm Clippy/Rust/build/Node/Chrome gate. No implementation claim follows from spec validation.

Compare source `319bda2` on all152 inherited workload names, including the10 access-fault kernels, in report and matched delivery modes on Node and Chrome. The matched mode has151 rows because it excludes the sole TF-detection row. Keep default debug-disabled observations identical; characterize the intentional TF DR6 effect via the new projection separately, without dropping legacy scalar/flags/frame checks. Prove inactive generated bytes, imports/helper counts, invocation and owner/resource equality; measure any added host snapshot/admission cost in one-instruction resumes, not only large kernels. Existing private failure paths and the predecessor's short Chrome cohort differences remain visible controls.

Characterize active execute/data misses and hits, multiple slots, GD, guest status/control edits, RF suppression, REP progress, deferred SS/software transition, handler repair, private refusal and alias/context churn separately; the old build has no equivalent active-debug execution. Record creation/translation/compile/instantiation, first/early/later completion, calls/entries/dispatches, generated/core/cache/transport bytes and control timings. Use balanced/reversed and same-build controls for material differences, retain zero/sub-tick samples and unsupported rows explicitly, and make no p99/application-throughput claim. Mutate execute-before-probe ordering, RF source policy, slot overlap/direction, identity writebacks, DR6 current/sticky separation, combined causes, SS deferred loss/double delivery, private-access false hits, excluded system traffic and stale activity/owner admission; count actual semantic assertion kills, not engine errors/timeouts.
