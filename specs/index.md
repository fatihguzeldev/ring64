- [string and repeated execution](string-and-repeated-execution/spec.md): memory strings, DF, bounded repetition, partial progress and restart after faults or code changes.

- [simd integer and data](simd-integer-and-data/spec.md): raw XMM state, legacy packed integers, bit-preserving moves and checked wide memory.

- [x87 state and execution](x87-state-and-execution/spec.md): raw80 register stack, tags, precision/rounding controls, core numeric execution and deferred x87 exceptions.
- [mmx and numeric state images](mmx-and-numeric-state-images/spec.md): MMX aliases and packed execution, MMX/SIMD conversions, legacy x87 environments and full-state images, FXSAVE and FXRSTOR.
- [masked and streaming memory](masked-and-streaming-memory/spec.md): legacy masked/non-temporal stores, fences, prefetch and pause hints, CLFLUSH access checks and backing-aware code invalidation.
- [descriptor tables and segment loads](descriptor-tables-and-segment-loads/spec.md): imported protection state, guest GDT/LDT operations, segment reloads, selector queries and checked descriptor side effects.
- [far control and code segments](far-control-and-code-segments/spec.md): code-descriptor CALL/JMP/RETF, outer returns, CS/CPL/submode changes and checked far frames.
- [system flags and instruction boundaries](system-flags-and-instruction-boundaries/spec.md): FLAGS stack transfers, CLI/STI, system-flag preservation, TF traps, stack-load suppression and resumable instruction boundaries.

- [event delivery and returns](event-delivery-and-returns/spec.md): opt-in processor-exception delivery, saved fault/trap boundaries, error-code frames, bounded pending delivery and selected double-fault/shutdown behavior.
- [external interrupts and halt](external-interrupts-and-halt/spec.md): bounded idle IRQ/NMI intake, source-aware boundary arbitration, HLT/wakeup, NMI blocking and early IRET unblock, with resumable guest delivery.

- [hardware breakpoints and debug](hardware-breakpoints-and-debug/spec.md): DR state and MOV DR, execute/GD faults, operand-data watchpoints, combined TF causes, SS-deferred checkpoints and guest handler recovery in a bounded instruction-access profile.
- [long-mode paging and permissions](long-mode-paging-and-permissions/spec.md): opt-in four-level IA32e physical memory, page permissions/A-D, coherent control consumers, #PF/CR2, handler repair and executable translation dependencies.
- [fast system transfers](fast-system-transfers/spec.md): Intel IA32e SYSCALL/SYSRET and SYSENTER/SYSEXIT, selected MSR/FS-GS authority, SWAPGS and complete paged user/kernel round trips; [verification](fast-system-transfers/verification.md).

## next five specifications

Selected against implementation baseline `4df41a0`, in the implementation order below. Each contract has received a separate source audit and independent semantic, ownership/boundary and performance/falsification review. They specify public inputs, publication/fault order, consumer changes, literal acceptance packets and future measurement gates. All five remain unimplemented; acceptance cases and mutation/performance gates are requirements, not passed verification results.

| order | spec                                                                      | complete execution path                                                                                           | dependency                                                                   |
| ----- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 1     | [x87 remainder, exponent and BCD](x87-remainder-exponent-and-bcd/spec.md) | exact raw80 remainder/scaling/extraction and packed-decimal load/store, with stack/status and deferred exceptions | existing x87 and numeric images                                              |
| 2     | [numeric execution controls](numeric-execution-controls/spec.md)          | numeric disable/task-switch controls, #NM delivery, handler repair and instruction retry                          | current physical IA32e profile; extends existing numeric consumers           |
| 3     | [legacy paging and permissions](legacy-paging-and-permissions/spec.md)    | imported non-PAE/PAE execution, captured PDPTEs, #PF handler repair and coherent executable ownership             | numeric control authority from 2; existing memory/event owners               |
| 4     | [reset and mode transitions](reset-and-mode-transitions/spec.md)          | physical-unpaged execution and reset, then guest-directed real/protected/paged/IA32e transitions and return       | 2 and 3                                                                      |
| 5     | [port I/O and string I/O](port-io-and-string-io/spec.md)                  | permission-checked external port effects and resumable scalar/repeated I/O                                        | existing REP, privilege and TSS owners; additional physical profiles use 2–4 |

The first spec closes a bounded numeric cohort; transcendental accuracy remains separate. Imported legacy paging deliberately precedes reset: its tests need a complete PG1 bank, not a guest boot sequence. Spec3 introduces one physical plane with derived legacy families and captured PAE state; spec4 extends that same plane to PG0 and guest family transitions, explicitly superseding spec3's physical fast-system frontier. Port I/O can also be developed against existing imported contexts and applies to all three memory models. This order does not mean five remaining specs finish the thirteen architectural areas.

CPUID/clock providers, x87 transcendentals, call gates/task switching, extended-state/AVX, retained TLB facilities and shared-vCPU atomics remain later work. No new device platform or OS-boot target is implied.

## dependencies

scalar and stack operations use register views and operand widths. execution contexts supply mode, size and feature rules to decoding and code reuse. strings also need df and resumable progress. descriptor operations need context, checked memory access and architectural fault outcomes.

memory backing supports ram, special accesses, aliases and code mutation independently of guest paging. page walks use that backing. paging contracts include the control writes and invalidations that affect translation. reset and mode transitions combine these controls with descriptor and execution-context behavior.

fault detection, single-step boundaries and state recovery can be tested before full event delivery. handler entry and return then combine fault records with descriptor, privilege and memory rules. irq/nmi service and halt/wakeup use that delivery path and the instruction-boundary state.

FLAGS stack transfers and CLI/STI use mode, CPL, IOPL and checked stack accesses. TF single stepping needs a precise completion boundary, including branch destinations and partial REP progress. MOV/POP SS suppression and STI delay survive private suspension; LSS has different event rules. detected traps and interruptibility snapshots do not perform IDT entry or handler return. software INT instructions and IRET use explicit IVT/IDT gates and saved frames; privilege stacks and IST consume a loaded TR and live TSS fields. automatic fault delivery, nested delivery and external events add their own service rules.

numeric execution needs register state, checked byte-range accesses and numeric fault outcomes. SIMD floating-point execution adds MXCSR rounding, status and exception masks to the XMM state contract; numeric faults can publish status while suppressing destination changes. feature-enable writes and state images must agree with the instruction families they control. core x87 execution establishes raw80 state, stack effects and deferred exceptions. mmx shares the x87 physical state. legacy and FX images add guest save/restore across x87, MMX, XMM and MXCSR, including handover of live generated values. `x87-remainder-exponent-and-bcd` adds exact remainder/exponent operations and packed-decimal conversions; the later `x87-special-functions` topic retains transcendental accuracy; XSAVE-style component images need their own enable, mask and format rules.

imported contexts allow isolated tests of paging, descriptors and numeric instructions. integration tests execute guest control writes, mode transitions and save/restore, then check their effects on subsequent instructions.

a gdt edit leaves loaded segment state intact until an architectural operation changes it. generated code must still recheck or invalidate assumptions affected by context, mapping or code changes. this applies to cached middle entries and pending compilations.

descriptor table and segment operations use imported CPL, visible selectors and a complete loaded-cache snapshot. LSS supplies the atomic SS/GPR path; MOV/POP SS inhibition, CS transfers, privilege changes and event delivery have separate contracts. installing an IDTR does not itself implement IDT dispatch. query instructions share descriptor interpretation without sharing a load's fault or accessed-bit behavior.

ordinary-code far CALL/JMP and RETF load CS through descriptor protection. CS.D/L selects the next code context within its active execution family. outer RETF restores SS:SP from the current frame and updates CPL; call gates, task switching and event returns add their own state and frame rules.

instruction breakpoints and operand-data watchpoints add DR state, execute/GD fault provenance, TF/data cause aggregation and SS-deferred debug checkpoints. their bounded observation profile includes control-stack operands, strings and selected numeric fields, while implicit descriptor/TSS/event-entry traffic, task debug, I/O and tracing remain separate coverage. debug activity participates in existing artifact admission without a separate cache or inactive per-instruction observer.

four-level IA32e paging adds an explicit physical-backed execution model alongside the existing private-linear model. its controls, permissions, A/D effects, #PF/CR2, implicit system accesses and executable translation dependencies form one contract. speculative discovery remains observational; reached instruction and prepared operand/frame access publish their own effects. legacy paging, reset/mode transitions and advanced translation facilities remain separate.

fast system transfers use that paged IA32e profile, loaded CS/SS/CPL context and existing fault/debug boundaries. EFER.SCE controls SYSCALL/SYSRET; selected entry MSRs, synthetic segment caches and one live FS/GS-base authority support guest-managed stack handover with SWAPGS. compatibility entry uses SYSENTER under the selected Intel rules. transfer completion and a later target-fetch fault are separate boundaries. identity reporting, reset and legacy paging remain separate coverage.

rep, enter, state images, event frames and vector operations have instruction-specific partial-progress rules. instruction retirement, completed suboperations and yield/poll work are separate quantities. resumption must preserve completed effects without replaying them.

shared-memory execution puts ordinary accesses, atomic operations, numeric-wide accesses, page-table updates, devices and executable bytes under the same synchronization rules. a lock used only by lock-prefixed instructions cannot protect accesses that bypass it.

cpu feature reporting, physical/device/clock providers, browser capability fallbacks and the observer model for shared memory need explicit contracts.

## verification

verify instruction forms across their supported widths, modes and feature/control states. undefined outputs and preserved state need separate comparison rules. valid unimplemented instructions, architectural invalid encodings, disabled features and engine failures have different outcomes.

check decoding and generated execution against independent expectations through the public host path. compare register state, memory, defined/preserved flags, fault metadata and ordered external effects. include repaired faults, interrupted progress, save/restore and resumed execution with changed inputs, including entry into retained code without running its predecessors.

performance comparisons use identical guest bytes, inputs and observations with checked outputs. newly executable forms need separate characterization. record translation, browser compilation/instantiation, first completion, early/later reuse, short resumes, code/cache memory, native entries, dispatch and event latency.

measure memory lowering, flags representation, region geometry, state transfer, indirect/return routing, cold execution and cache policy on mixed workloads. compare their compilation cost and resource use alongside execution time.
