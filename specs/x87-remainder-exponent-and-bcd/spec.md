# x87 remainder, exponent and BCD

Status: implementation-ready specification; implementation not started. Source audit baseline: `4df41a0814beaceb0681dc013f5eac094cdc6660`. First of the next five specs.

## objective and admitted profile

Add the complete execution path for FPREM, FPREM1, FSCALE, FXTRACT, FBLD and FBSTP: decoding, exact raw80 arithmetic or decimal conversion, physical stack/status effects, operand admission, deferred exceptions, resumed guest consumers and generated-source validity. The existing x87 projection and event/memory contracts remain authoritative. A helper returning a plausible binary64 value does not satisfy this spec.

The cohort runs in all fourteen inherited mode/code-size/stack-size profiles and in the current physical IA32e profile. It uses their enabled numeric controls; [numeric execution controls](../numeric-execution-controls/spec.md) subsequently supplies disabled-state consumers without changing these arithmetic rules. Transcendentals, FISTTP, XSAVE, new vector state, shared RAM and reset are separate work. This is a bounded part of the later `x87-special-functions` topic.

At this baseline the operation word allocates five kind bits and already has 31 kinds. Adding six kinds requires deliberate repacking or another checked representation. Thirty bits suffice for six kind bits, four format bits and the current index/destination/pop/condition/11-bit encoding fields; the exact private layout is an implementation choice. Update encoder, decoder, reserved-bit rejection, well-formed combinations, generated calls and test adapters together. Exhaustively round-trip every admitted old/new combination; reject malformed combinations and unused high bits. No persisted cross-build operation-word compatibility is promised. Preserve public raw80 snapshots, existing transport offsets and the generated five-argument entry ABI.

BCD needs a distinct semantic format/direction, even though its span equals m80real. It cannot use the raw-float `widen`/store path. FPREM/FPREM1/FSCALE consume logical ST(0) and ST(1), not whichever generic index happens to default to zero; FXTRACT consumes old ST(0) plus the destination stack slot. Access width, store classification, environment updates and debug publication must follow those roles.

| `d9 f5`                     | FPREM1    | nearest-even quotient remainder, no pop         |
| `d9 fd`                     | FSCALE    | scale ST(0) using ST(1), no pop                 |

All six wait. `9b` remains a separate WAIT instruction with its own PC, retirement and stop boundary. `66` never changes the BCD width or register operation. `67`, segment overrides, SIB/displacements and REX.B/X select inherited memory addressing; REX.W/R do not create another numeric width/opcode extension. Register forms ignore otherwise irrelevant address prefixes. Retain the predecessor's ignored F2/F3 behavior on this selected x87 cohort. LOCK on a recognized selected form is architectural #UD; repeated/conflicting prefix groups retain the existing private frontier. Do not expand this work into a general prefix cleanup.

Decode only bytes needed to recognize the selected form and its actual address. No fictitious trailing immediate, m128 span or next-instruction fetch is allowed. Check register-only `df` encodings against their existing meanings rather than treating every `/4` or `/6` as BCD. A matching execute breakpoint at a cold/unmapped source selects #DB without source-byte reads; entry budget0/stop still prevents work. Cover exact last-byte fetch, cross-page ModR/M/displacement, maximum instruction length, each supported address size and nonzero segment bases. A valid unselected instruction remains coverage-unsupported, not a fabricated #UD.

## exact remainder and partial progress

For finite ordinary inputs let `a=ST(0)`, `b=ST(1)`. On a completed reduction FPREM uses `Q=trunc(a/b)`; FPREM1 uses nearest integer with ties to even, independent of CW.RC. The result is the exact `a-b*Q`; a zero retains the dividend sign. ST(1), TOP and all unrelated physical payloads remain unchanged. Publish C2=0 and the quotient low bits Q2/Q1/Q0 in C0/C3/C1, using the low three bits of the quotient magnitude; its sign is used in the remainder arithmetic, not as a two's-complement flag encoding. Neither PC nor RC rounds the remainder; neither instruction newly raises PE, including an exact tiny remainder whose unmasked underflow response posts UE.

Compute the exponent difference D from the normalized values, including subnormals, not only raw exponent fields. If D<64 take the completed path. A negative D is not a shared return-a shortcut: FPREM1 can round a ratio between 0.5 and1 to quotient1 (for example1.5/2 gives remainder-0.5), whereas FPREM truncates it to0. Otherwise perform exactly one partial reduction, with the selected deterministic `N=32+(D mod 32)` (within Intel's permitted 32–63 range): `QQ=trunc((a/b)/2^(D-N))`; `r=a-b*QQ*2^(D-N)`. Both instructions truncate this scaled quotient. Publish the exact partial result and C2=1; select zero for undefined C0/C1/C3 on this path, but exclude them from architectural conformance masks. Do not loop to completion inside one instruction or charge hidden iterations as retired instructions.

This choice replaces the earlier fixed-N63 proposal: D-N is now a multiple of 32, so partial quotient contributions do not corrupt the low three quotient bits observed by the final reduction. Each guest iteration still consumes one instruction and may be interrupted or checkpointed. Preserve C2=1 even for a partial step yielding exact zero; the next reached operation completes it. A finite nonzero divisor converges with bounded integer work per step. Do not allocate or iterate according to the numeric magnitude of a floating-point exponent operand.

For special operands use the x87 class/exception rules, before finite reduction: zero divisor or infinite dividend selects invalid; finite dividend with infinite divisor is unchanged; zero dividend and nonzero finite divisor preserves signed zero. SNaN/unsupported operands select invalid, QNaNs use inherited quiet propagation, and reported denormal inputs obey DM and pre-operation suppression. A masked invalid FPREM/FPREM1 produces the raw80 indefinite and clears C2; it is not an unfinished reduction. Stack-empty response sets IE/SF and C1=0. Unmasked pre-operation conditions preserve numeric destinations and TOP while posting status/pending. Use the existing x87 priority/NaN-selection contract; undefined condition bits never become portable oracle requirements.

## scale, extract and numeric exceptions

All six new forms ignore PC, including PC24/53 and the inherited reserved-PC policy. FSCALE alone applies RC when its full 64-bit-significand result needs boundary rounding; FBSTP applies RC to integer conversion. Do not reuse generic PC-sensitive arithmetic simply because it already produces raw80.

FSCALE truncates the mathematical value of ST(1) toward zero without reporting the precision or integer-overflow effects of an intermediate host-integer conversion. Preserve ST(1) and TOP. Finite in-range scaling adjusts the exponent exactly; normalize a denormal source when appropriate. Classify huge finite scales and infinities before any bounded-integer cast or shift. Finite nonzero scaled by +infinity becomes signed infinity, and by -infinity signed zero; zero with +infinity or infinity with -infinity selects invalid. Other signed zero/infinity and NaN responses follow Intel's FSCALE table. No MXCSR/DAZ/FTZ behavior applies.

Apply inherited masked overflow/underflow rounding and unmasked register-result exponent adjustment by 24,576. FSCALE adds the manual's massive cases: if the adjusted exponent still overflows, store signed infinity; if it still underflows, store signed zero. Do not wrap a second out-of-range exponent through an unsigned pack. Check OE/UE/PE and C1 separately; old sticky flags do not manufacture a new abort.

FXTRACT normalizes a finite nonzero source into a signed significand whose magnitude is in [1,2) and its unbiased exponent represented exactly as raw80. The new ST(0) is the significand, ST(1) the exponent; old TOP decrements modulo8 only when the permitted push occurs. For ±zero with ZM set, push the same signed zero and place -infinity in ST(1), posting ZE. With ZM clear, preserve payloads/TOP and post ZE/pending. For signed infinity produce signed infinity at new ST(0) and +infinity at ST(1); QNaN/quieted invalid responses populate both results under the instruction's rules. A full destination slot is a stack overflow, distinct from an empty source underflow. Unmasked invalid/denormal/stack/zero-divide preconditions suppress destination and push changes; for a masked empty-source or occupied-push-slot stack fault, replace both result slots with indefinite, tag them special and decrement TOP once. Source underflow takes priority over push overflow, setting C1=0 rather than1 when both exist. Unmasked stack faults preserve payloads/tags/TOP and distinguish underflow/overflow with C1. The exact stack response must be tested, not inferred from a generic unchecked push helper.

## decimal format, memory and completion

FBLD/FBSTP use ten little-endian bytes. FBSTP reports invalid/stack/precision conditions, not a generic denormal-input DE; do not inherit that arithmetic admission check. Bytes0–8 contain eighteen digits, low nibble first; byte9.bit7 is sign. FBLD ignores byte9.bits6:0 and preserves negative zero. Valid eighteen-digit magnitudes are converted exactly without PC/RC rounding. Digit nibbles A–F have an architecturally undefined loaded result: do not invent a digit-validation #IA, and mask the undefined payload/tag result rather than copying a backend answer into the oracle. The waiting/access/retirement and no-unrelated-state rules remain checked.

FBSTP rounds the complete raw80 source to an integer under RC, then checks the eighteen-digit magnitude bound. Write valid digits and sign; select zero for unused output sign-byte bits. Masked invalid/empty conversion writes packed-BCD indefinite `ffffc000000000000000` as a ten-byte image (little endian `00 00 00 00 00 00 00 c0 ff ff`) and performs the permitted pop. This is a BCD image, not the raw80 indefinite payload. Unmasked invalid conversion posts IE/pending, writes nothing and does not pop. A valid conversion with unmasked precision still commits rounded bytes and pop, then posts PE/pending. C1 follows rounded-up/stack response; C0/C2/C3 are undefined.

For either BCD operation use this order: entry budget/stop gates; execute breakpoint before source-byte fetch; required instruction fetch/decode/legality; existing waiting check; complete segmented/paged/private admission of ten bytes; numeric/stack evaluation into candidate state; permitted prepared payload write; candidate numeric/environment publication and ordinary completion. Existing pending #MF wins over an operand failure. Operand failure precedes newly detected empty/full stack, invalid conversion or rounding status, and leaves all incoming x87 payloads/tags/status/FIP/FDP/FOP unchanged. Later numeric-disable checks are inserted at the owner-defined point in spec2. No universal instruction rollback is introduced.

Loads require read access; stores require write access without reading destination data. Preflight the entire ten-byte span and retain prepared destinations through aliasing PTE changes; no separate guest m64+m16 accesses or partial payload stores. Keep private backing refusal distinct from #PF/CR2. If the actual-store D phase refuses after numeric evaluation, suppress candidate numeric/environment publication and payload/pop; prior permitted A effects remain. Test A and D phases independently. FBLD/FXTRACT masked pushes, FBSTP permitted pops and sticky-status updates form one instruction-specific publication; no intermediate stack escapes. Newly posted x87 conditions retire the producer once; a later WAIT reports the pending source, which survives diagnostic clearing until repaired.

All six update FIP at the prefix-start PC after operand admission; memory forms update FDP under the inherited mode-specific logical/linear-pointer rules. FOP updates when the producer posts an unmasked condition, using the admitted opcode/ModR/M image. Register forms preserve undefined FDP. A pending detector does not replace producer metadata.

Debug observes actual admitted FBLD reads and committed FBSTP bytes, including a committed precision-result store, not a suppressed invalid store. Pre-operation memory failures discard uncommitted operand candidates. Numeric helpers own canonical x87 state; these six do not write GPR/FLAGS/XMM/MXCSR. Preserve unrelated generated locals and reload only projections actually written; a blanket spill/reload of every bank is unnecessary and can clobber results.

## source currentness and independent packets

A payload store through any executable alias invalidates active and dormant owners even when bytes are unchanged. Also account for paging A/D writes caused by operand admission: a FBLD read or a FBSTP whose data store is suppressed can still change generated source or a source PTE. Finish and retire the reached instruction under its admitted bytes, then refetch changed successor code. Do not key the currentness exit only on `effect.store`, and do not replay a committed pop/store or the producer's pending status. Pending browser compilation, retained middle entries and later reactivation use current context/source facts.

## verification, falsifiers and performance

Use exact integer/rational reference calculations and separately authored raw80/BCD/status fixtures, with source lineage recorded. Production `number`/`eval`, JS Number arithmetic, QEMU/SoftFloat agreement or Rosetta alone is not the oracle. Source review found the inspected QEMU v10.1.0 FPREM1 helper does not provide a usable quotient-flag oracle; its numeric helper is corroboration only. A separate temporary Rosetta x86 probe corroborated masked stack/quotient cases, but failed unmasked-exception behavior, so exclude its unmasked results. Record that adapter identity and limitation rather than calling it native-x86 proof. Hardware captures identify CPU/control state and mask implementation-dependent partial-step choices. Validate every defined raw/status/stack result and a subsequent guest consumer, not just final floating output.

Required semantic mutations include swapped quotient rounding, nearest rounding on the partial path, wrong normalized exponent/C2, quotient-bit permutation, PC-sensitive scale, bounded-host conversion of huge ST1, missing massive-range adjustment, swapped FXTRACT results or unchecked full stack, BCD-as-raw80 interpretation, sign/width loss, invalid-pop versus precision-pop confusion, operation-word collision, wrong waiting/access priority, unconditional helper spill, and source-currentness checking only payload stores. A killed mutation needs an unchanged semantic assertion at the intended owner/public consumer; compilation failure, empty filter, generic refusal or crash is not a kill. Restore exact source/build hashes and rerun clean controls.

Implement in logical slices with independently reviewable gates: (1) operation representation/decode/classification with round-trip tests; (2) exact remainder/partial profile; (3) scale/extract class and stack responses; (4) BCD admission/publication; (5) actual-Wasm fault/debug/currentness/resume integration. Each slice preserves the full final cohort; no unrelated arithmetic or prefix refactor is required. Native tests stay with existing numeric/decode owners; shared public Cpu packets run on Node and Chrome, including actual retained middle-entry execution.

```sh
cargo test --locked
npm run build
npm test
npm run test:browser
npm run check
```

Freeze the immediate predecessor's source/core/host and environment before implementation; source-review baseline and runtime measurement baseline are distinct. Compare inherited x87/MMX/SSE and scalar workloads with identical bytes/inputs/observations, balanced forward/reverse ordering and A/A controls for material residuals. Check unchanged default generated imports, body/helper work, native entries, cache/transport sizes and live-state behavior; widening a private operation constant can change inherited x87 immediates/LEB sizes; identify and measure those permitted changes without demanding impossible byte identity. It is not a license for more hot-path calls.

Characterize each new form, ten-byte splits, normal/exceptional scale, full-stack extract, cold/first/warm completion and short resumes separately. For remainder loops record individual partial steps, convergence instructions and actual helper work; report per retired instruction and per completed reduction, never fewer hidden steps as a speedup. Record translation/browser compile/instantiation costs, source-writer/alias work and generated/cache memory. The new cohort has no executable old baseline; its timing is characterization. Put implementation evidence in this directory's `verification.md`; README is outside scope.
